# Этап 4. Дверь на клавишу E

> Первый настоящий блюпринт-актор: дверь с петлёй, зоной срабатывания и плавным открытием. Учимся компонентам, событиям коллизии, Cast, вводу в акторе, Timeline и Flip Flop.

[← Материалы дома](03-materialy-doma.md) · [О курсе](00-dom-o-kurse.md) · дальше → [Свет в доме](05-svet-v-dome.md)

---

**К концу этапа:** подходишь к двери, жмёшь `E` — она плавно открывается внутрь; ещё раз `E` — закрывается. Дверь — отдельный блюпринт `BP_Door`: поставь сколько угодно копий, у каждой своя логика.

> ✅ **Проверено в редакторе — компоненты и геометрия.** `BP_Door` с Hinge, DoorMesh и Trigger собран по таблицам: закрытая дверь точно закрывает проём 120 × 220, при +90° уходит внутрь дома и не мешает пройти, зона ловит игрока с обеих сторон. **Логику графа** (события, Cast, Timeline, Flip Flop) скриптом собрать нельзя — её проверишь сам на шаге 7: если что-то не так, смотри «Если не получилось» и «Как отлаживать блюпринт».

## Чему научишься

- создавать **Blueprint-класс** на основе Actor — [Блюпринты](../ref/04-blueprinty.md);
- собирать **дерево компонентов**: петля → дверь, зона срабатывания;
- ловить **события коллизии** (Begin / End Overlap);
- **Cast** — «а это точно игрок?»;
- принимать **ввод в акторе** (Enable Input) — [Enhanced Input](../proekt/07-personazh.md#шаг-5-управление-enhanced-input);
- плавную анимацию через **Timeline** и переключатель **Flip Flop**.

## Что понадобится

- [этап 3](03-materialy-doma.md): дом с материалами и дверным проёмом 120 × 220;
- пройденный [квест «Спринт на Ctrl»](../proekt/07-personazh.md#квест-2-спринт-на-ctrl) — там первые шаги в Event Graph.

---

## Шаг 1. Действие «Взаимодействовать» на E

1. Каталог → `Content/Input/Actions` → правый клик → **Ввод → Действие ввода** → `IA_Interact`.
2. Открой `Content/Input/IMC_Default` → **Mappings → +** → `IA_Interact` → клавиша **E**. Сохрани оба.

<details>
<summary>🔎 Подробнее: почему одно действие на все предметы</summary>

Действие означает **«игрок хочет взаимодействовать»**, а не «открыть дверь». Тогда одна клавиша `E` будет открывать двери, включать свет, подбирать предметы — каждый предмет сам решает, что делать с этим желанием.

Переназначить клавишу (например, на `F`) — одна правка в `IMC_Default`, а не в каждой двери. Это главная идея Enhanced Input: **отделить «что» от «какой клавишей»**.

</details>

## Шаг 2. Создать блюпринт

1. Каталог → создай папку `House/Blueprints`.
2. Правый клик → **Класс Blueprint** → в окне выбора родителя — **Actor** → имя `BP_Door` → двойной клик.

<details>
<summary>🔎 Подробнее: почему Actor, а не Pawn или Character</summary>

| Родитель | Что умеет | Для чего |
|---|---|---|
| **Actor** | стоять в мире, иметь компоненты и логику | двери, лампы, сундуки, ловушки |
| Pawn | + им можно управлять | машины, камеры, простые существа |
| Character | + капсула и ходьба | люди и звери |

Дверью никто не управляет — ей хватит **Actor**. Лишние возможности — лишняя нагрузка и путаница.

</details>

## Шаг 3. Компоненты

Открылся редактор блюпринта. Слева вверху — панель **Компоненты**, там уже есть `DefaultSceneRoot`.

1. **+ Добавить** → **Scene** → имя `Hinge` (петля).
2. Выдели `Hinge` → **+ Добавить** → **Static Mesh** → имя `DoorMesh` (появится **внутри** Hinge). В Сведениях:
   - **Static Mesh** → `Cube`;
   - **Расположение** `0, 60, 110`, **Масштаб** `0.05, 1.2, 2.2`;
   - **Материал** — любой деревянный с обычными UV (см. ниже).
3. Выдели `DefaultSceneRoot` → **+ Добавить** → **Box Collision** → имя `Trigger`:
   - **Расположение** `0, 60, 110`, **Box Extent** `150, 150, 110`.
4. **Компилировать** → **Сохранить**.

```console
DefaultSceneRoot
 ├── Hinge          ← петля: будем поворачивать её
 │    └── DoorMesh  ← полотно двери, смещено от петли на 60 см
 └── Trigger        ← невидимая зона: «игрок рядом»
```

> ⚠ **Материал двери.** `MI_House_Floor` с World Aligned на двери «поплывёт» при открытии — текстура привязана к миру, а дверь в нём двигается. Для двери сделай простой `M_Door`: Texture Sample `T_Floor_D` → Base Color, без WorldAligned (как в [главе 2](../proekt/02-teksturi-i-import.md#шаг-3-материал)).

<details>
<summary>🔎 Подробнее: зачем петля, если можно вращать саму дверь</summary>

Объект вращается **вокруг своей точки опоры**. У куба она в центре: повернёшь дверь — она закрутится вокруг середины, как вертушка в метро.

Хитрость: пустой компонент `Hinge` стоит там, где у настоящей двери петли, а полотно сдвинуто от него на половину ширины (60 см). Поворачиваем петлю — полотно описывает дугу вокруг края. Так же делают крышки сундуков, ворота, рычаги.

`Box Extent` — это **половина** размера коробки: `150, 150, 110` — зона 3 × 3 × 2.2 м. Игрок попадает в неё, ещё не дойдя до двери.

</details>

> 🧪 **Посчитай сам**, прежде чем ставить в редакторе. Box Extent — это **половина** размера коробки.

```challenge
@id ue-dom4-box
@type predict
@hint Полный размер = 2 × Box Extent.
Box Extent = 150, 150, 110. Какой ширины зона по X, в сантиметрах?
---
float extentX = 150;          // половина
float widthX  = 2 * extentX;
---
300
```

## Шаг 4. «Игрок рядом» — события коллизии

Перейди на вкладку **Event Graph**.

1. В Компонентах выдели `Trigger` → в Сведениях внизу раздел **События** → у **On Component Begin Overlap** нажми **+**. В графе появился красный узел-событие.
2. Из выхода **Other Actor** потяни провод → в поиске `Cast To BP_EmanuelPlayer` → выбери.
3. Из белого выхода Cast (верхний, без подписи) → `Enable Input`. Вход **Player Controller** ← узел `Get Player Controller` (Player Index 0).
4. То же для **On Component End Overlap** → Cast To BP_EmanuelPlayer → `Disable Input` (с тем же Get Player Controller).

```console
[On Component Begin Overlap (Trigger)] ─▶ [Cast To BP_EmanuelPlayer] ─▶ [Enable Input]
          Other Actor ─────────────────────▶ Object          Player Controller ◀─ [Get Player Controller 0]

[On Component End Overlap (Trigger)]   ─▶ [Cast To BP_EmanuelPlayer] ─▶ [Disable Input]
```

<details>
<summary>🔎 Подробнее: что такое Cast и зачем он здесь</summary>

В зону может зайти что угодно: игрок, ящик, который ты толкаешь, даже трава (если у неё есть коллизия). Событие даёт **Other Actor** — «кто-то», просто актор.

**Cast To BP_EmanuelPlayer** спрашивает: «этот кто-то — Emanuel?»

- да → идём по верхнему белому выходу, и у нас в руках уже не «какой-то актор», а именно персонаж (можно брать его переменные);
- нет → идём по выходу **Cast Failed** (ничего не делаем).

Это как в C++ `dynamic_cast<Player*>(actor)`: проверка типа с возможностью получить «правильный» указатель.

</details>

<details>
<summary>🔎 Подробнее: Enable Input — почему без него E не сработает</summary>

По умолчанию клавиши слышит только тот, кем управляет игрок (Emanuel) и его контроллер. Обычный актор вроде двери ввод **не получает** — иначе каждая дверь в мире открывалась бы по `E`, где бы ты ни стоял.

`Enable Input` говорит: «пока игрок рядом — передавай мне его клавиши». `Disable Input` — «отошёл, больше не слушаю». Так `E` работает только у ближайшей двери.

</details>

## Шаг 5. Плавное открытие — Timeline

1. Правый клик по графу → **Add Timeline…** → имя `DoorTimeline`.
2. Двойной клик по узлу Timeline — откроется его редактор:
   - кнопка **+ Track** → **Float Track** → имя `Alpha`;
   - правый клик по графику → **Add key**: время `0`, значение `0`; второй ключ: время `0.6`, значение `1`;
   - вверху **Length** = `0.6`.
   Закрой вкладку Timeline, вернись в Event Graph.
3. Из выхода **Update** Timeline: узел `Lerp` (Float) — **A** = `0`, **B** = `90`, **Alpha** ← выход `Alpha` таймлайна.
4. Результат Lerp → вход **Z (Yaw)** узла `Make Rotator`.
5. Перетащи `Hinge` из Компонентов в граф → из него `Set Relative Rotation` → **New Rotation** ← Make Rotator. Белый провод: **Update** → Set Relative Rotation.

```console
[DoorTimeline] Update ─────────────────────────────▶ [Set Relative Rotation]  Target: Hinge
               Alpha ─▶ [Lerp 0…90] ─▶ [Make Rotator: Yaw] ─▶ New Rotation
```

<details>
<summary>🔎 Подробнее: как работает Timeline</summary>

Timeline — это **маленький проигрыватель кривой**. Ты рисуешь график «значение от времени» (у нас — от 0 до 1 за 0.6 с), а Timeline проигрывает его и **каждый кадр** выдаёт текущее значение через выход **Update**.

| Вход | Что делает |
|---|---|
| Play | играть вперёд с текущего места |
| Reverse | играть назад |
| Play from Start | с начала |
| Stop | остановить |

Мы проигрываем **0 → 1**, а Lerp превращает это в **0° → 90°**. Почему не нарисовать сразу 0 → 90? Можно. Но 0…1 — универсальная «доля пути»: тот же Timeline подойдёт для яркости лампы, цвета, позиции — меняешь только Lerp.

Хочешь, чтобы дверь открывалась с «замедлением» в конце? В редакторе Timeline выдели ключи → правый клик → **Auto** — кривая станет плавной.

</details>

```challenge

Прошло 0,3 с из 0,6 — Alpha = 0.5. На какой угол открыта дверь, в градусах?
---

45
```

## Шаг 6. E открывает и закрывает — Flip Flop

1. Правый клик → набери `IA_Interact` → **EnhancedInputAction IA_Interact**.
2. Из **Started** → узел **Flip Flop**.
3. **A** → вход **Play** таймлайна, **B** → вход **Reverse**.
4. **Компилировать** → **Сохранить**.

<details>
<summary>🔎 Подробнее: Flip Flop против Branch</summary>

**Flip Flop** — переключатель: первый раз идёт по **A**, второй — по **B**, третий — снова по **A**… Помнит сам, где был. Идеален для «вкл/выкл».

Можно сделать то же через переменную `IsOpen` и **Branch** (если открыта — Reverse, иначе Play; затем `IsOpen = NOT IsOpen`). Это длиннее, но переменную можно **читать** снаружи: например, чтобы сохранить состояние двери или закрыть все двери разом. Попробуй переделать в бонусе.

</details>

### Вся логика двери по шагам

Тот же граф в виде C++. Жми «Шаг ▶» и смотри, как меняются значения. Знак вопроса — сначала предскажи.

```steps
@id ue-dom4-steps
# BP_Door: игрок подошёл и дважды нажал E
void OnTriggerBeginOverlap(AActor* Other)
{
    if (Cast<BP_EmanuelPlayer>(Other))
        EnableInput(GetPlayerController(0));
}
void OnInteractStarted()                      // IA_Interact, клавиша E
{
    if (FlipFlop())  DoorTimeline.Play();     // выход A
    else             DoorTimeline.Reverse();  // выход B
}
void DoorTimelineUpdate(float Alpha)          // каждый кадр, пока играет
{
    Hinge->SetRelativeRotation(FRotator(0, Lerp(0, 90, Alpha), 0));
}
---
1 | Other=Emanuel, Ввод=выкл, FlipFlop_дальше=A, Alpha=0, Угол=0° | Emanuel вошёл в зону `Trigger` — сработало Begin Overlap.
3 | | **Cast**: этот «кто-то» — Emanuel? Да, идём по верхнему выходу.
4 | Ввод=вкл | **Enable Input**: теперь дверь слышит клавиши игрока.
6 | | Игрок нажал **E** — событие IA_Interact, выход **Started**.
8 | FlipFlop_дальше=B | Flip Flop в первый раз идёт по **A** → **Play**.
13 | Alpha=0.5, Угол=45° | Timeline каждый кадр выдаёт Alpha. Через 0,3 с — середина кривой.
?13 | Alpha=1, Угол=90° | 0,6 с — конец кривой: дверь открыта.
6 | | **E** ещё раз.
9 | FlipFlop_дальше=A | Теперь Flip Flop идёт по **B** → **Reverse**.
13 | Alpha=0, Угол=0° | Timeline проигрывается назад — дверь закрылась.
```

## Шаг 7. Поставить дверь в дом

1. Перетащи `BP_Door` из каталога на уровень.
2. **Расположение** `-2100, -60, 20`, **Вращение** `0, 0, 0`.
3. Проверь: полотно ровно закрывает проём 120 × 220, петля — у левого края (Y = −60).
4. ▶ Play → подойди к двери → `E` → откроется внутрь. `E` ещё раз — закроется.

**Должно получиться:** дверь открывается на 90° внутрь дома за 0.6 с; отойдёшь от двери — `E` не работает.

```checklist
Этап 4 готов, если:
- IA_Interact на клавише E в IMC_Default
- BP_Door: Hinge → DoorMesh, Trigger; компилируется без ошибок
- дверь открывается и закрывается по E, плавно
- вдали от двери E ничего не делает
- могу объяснить, зачем петля, Cast и Enable Input
```

## Если не получилось

| Что видно | Причина | Что сделать |
|---|---|---|
| E не делает ничего | нет Enable Input / Cast не прошёл / IMC не сохранён | поставь Print String после Cast — дошло ли? |
| дверь крутится вокруг центра | вращаешь DoorMesh, а не Hinge | Target у Set Relative Rotation — Hinge |
| E срабатывает, но дверь стоит, в Журнале предупреждение про Mobility / Static | у Hinge или DoorMesh подвижность Static | в блюпринте выдели компонент → Сведения → **Подвижность: Подвижный** (Movable) ([что это](../ref/02-aktory-i-komponenty.md#подвижность-static-stationary-movable)) |
| дверь открывается наружу | знак угла | Lerp B = −90 |
| дверь мгновенно «прыгает» | Length таймлайна 0 или нет ключа 0.6 | проверь ключи и Length |
| открывается и сразу закрывается | событие Triggered вместо Started | бери выход Started |
| персонаж застревает в открытой двери | дверь блокирует проход | открой на 100° или сдвинь петлю |
| Cast всегда Failed | персонаж другого класса | Cast To `BP_ThirdPersonCharacter` (родитель тоже подойдёт) |

<details>
<summary>🔎 Подробнее: как отлаживать блюпринт</summary>

1. **Print String** — поставь в цепочку, выведет текст на экран в игре. Лучший первый шаг: «дошло ли выполнение до сюда?»
2. **Смотреть выполнение вживую:** во время игры открой BP_Door, вверху выбери экземпляр (выпадающий список «Debug Object»). Белые провода, по которым идёт выполнение, будут **светиться**.
3. **Точка останова:** правый клик по узлу → **Add Breakpoint** (`F9`). Игра замрёт на этом узле, можно навести мышь на провода и увидеть значения. Почти как в отладчике C++.

</details>

> 🧪 **E у двери ничего не делает?** Подсказки по одной:

```hints
Идея: Цепочка длинная: зона → Cast → Enable Input → E → Flip Flop → Timeline. Найди, в каком месте она рвётся, — не чини всё подряд.
План: Поставь **Print String** после Cast и ещё один после Started. Не печатается первый — дело в зоне или Cast. Печатается первый, но не второй — дело во вводе: IMC или Enable Input. Печатаются оба — смотри Timeline и Hinge.
Ключ: Чаще всего виноваты несохранённый `IMC_Default` или Cast к другому классу (тогда бери `BP_ThirdPersonCharacter`).
```

## Проверь себя

```quiz
В: Зачем двери отдельный компонент Hinge?
+ Чтобы вращать дверь вокруг края, а не вокруг её центра
- Без него дверь не видна
- Это требование Box Collision
= Объект вращается вокруг своей точки опоры; петля — точка опоры на краю.

В: Что произойдёт без Enable Input?
+ Дверь не получит нажатия E
- E будет открывать все двери в мире
- Ничего, ввод работает и так
= Обычный актор по умолчанию не получает ввод игрока.

В: Timeline выдаёт Alpha от 0 до 1. Lerp(A = 0, B = 90). Какой угол при Alpha = 0.5?
+ 45°
- 90°
- 0.5°
= Lerp — доля пути: 0 + (90 − 0) × 0.5.

В: Что делает Flip Flop?
+ Чередует выходы A и B при каждом вызове
- Выполняет A и B одновременно
- Случайно выбирает A или B
= Переключатель с памятью — идеален для «открыть/закрыть».

В: Box Extent = (150, 150, 110). Какого размера зона?
+ 300 × 300 × 220 см
- 150 × 150 × 110 см
- 75 × 75 × 55 см
= Extent — половина размера коробки.
```

## Бонус

```boss
# Дверь с характером
@id ue-dom-04
Улучши BP_Door, не ломая того, что работает.

1. Замени Flip Flop на переменную **IsOpen** (Boolean) + **Branch**.
2. Добавь переменную **OpenAngle** (Float, 90) с глазом 👁 (**Instance Editable**) — у каждой двери на уровне свой угол в Сведениях.
3. Поставь вторую дверь во внутренний проём (100 × 210): у этой копии поменяй масштаб полотна и OpenAngle = −100.
4. Дверь закрывается сама через 5 секунд, если её не закрыли (**Delay** → Reverse).

<details>
<summary>Подсказка</summary>

Instance Editable: в панели «Мой Blueprint» выдели переменную → в Сведениях галочка **Instance Editable** (или кликни по закрытому глазу рядом с ней). Тогда она появится в Сведениях каждой двери на уровне. В Lerp подавай B ← OpenAngle. Для второй двери проём 100, значит смещение полотна 50, масштаб Y 1.0, высота 210 → Z масштаб 2.1, смещение Z 105.

</details>
```
