# Этап 9. Финал: игра в .exe

> Последний этап: проходим дом как игрок, ловим недочёты, проверяем производительность, превращаем дом в блюпринт-«префаб» и собираем игру в .exe, которую можно отправить другу.

[← Подсказки на экране](08-podskazki.md) / [О курсе](00-dom-o-kurse.md)

---

**К концу этапа:** у тебя есть папка с игрой: запускаешь `.exe` — появляешься в поле, бежишь по дорожке, открываешь дверь, включаешь свет, толкаешь ящик. Без редактора.

> ✅ **Проверено.** Карта по умолчанию `num1` и режим `BP_EmanuelGameMode` уже стоят; места на дисках хватает (C: ~189 ГБ, D: ~279 ГБ). **Visual Studio не установлена**, а этому проекту она нужна — см. шаг 0. Саму упаковку я не запускал: она идёт до часа и сильно грузит компьютер.

## Чему научишься

- **плейтест** — проверка игры глазами игрока, со списком;
- **stat unit / stat fps** — измерить, где тормозит — [Производительность](../ref/06-proizvoditelnost.md);
- **Преобразовать выбранное в класс Blueprint** — сделать из дома многоразовый объект;
- настройки **упаковки**: карты, конфигурация сборки;
- **Платформы → Упаковка проекта** и что делать, если упаковка не прошла.

## Что понадобится

- все этапы 1–8;
- ~10 ГБ свободного места (MetaHuman и текстуры весят много);
- время: первая упаковка может идти **30–90 минут** (компиляция шейдеров).
- **Visual Studio 2022** — обязательно для этого проекта (см. шаг 0).

---

## Шаг 0. Поставить Visual Studio

Обычный блюпринт-проект Unreal упаковывает без компилятора — берёт готовый `.exe` движка. Но **твой проект — не обычный**: при скачивании MetaHuman в него сами включились плагины `LiveLink`, `LiveLinkControlRig`, `AppleARKitFaceSupport`, а ещё раньше — `PythonScriptPlugin`. В них есть игровой код, а в стандартном `.exe` движка их нет. Поэтому при упаковке Unreal соберёт **свой** `.exe` — и для этого нужен компилятор C++.

1. Скачай **Visual Studio 2022 Community** (бесплатно) с `visualstudio.microsoft.com`.
2. В установщике отметь нагрузку **«Разработка игр на C++»** (Game development with C++). Справа убедись, что отмечены **Windows 11 SDK** и **Unreal Engine installer** (если есть).
3. Установи (~10–15 ГБ), перезагрузи компьютер.
4. В Unreal: **Платформы → Управление SDK** — у Windows должна быть зелёная галочка.

<details>
<summary>🔎 Подробнее: как я это выяснил и можно ли обойтись без Visual Studio</summary>

Сборщик Unreal (UnrealBuildTool) решает, нужен ли «свой» `.exe`, функцией `RequiresTempTargetForCodePlugin`: если в проекте **включён плагин с игровым кодом, который в движке по умолчанию выключен**, проект считается кодовым. Я проверил `.uplugin` твоих плагинов:

| Плагин | По умолчанию | Игровой код |
|---|---|---|
| LiveLink | выключен | да (Runtime) |
| LiveLinkControlRig | выключен | да |
| AppleARKitFaceSupport | выключен | да |
| PythonScriptPlugin | выключен | да (PythonScriptPluginPreload) |

Обойтись без Visual Studio можно, только если **выключить** все четыре (**Правка → Плагины**). Но LiveLink нужен MetaHuman для захвата лица, а Python — мне для работы с редактором. Проще поставить Visual Studio один раз — она пригодится и для C++ в Unreal.

</details>

## Шаг 1. Плейтест

Нажми ▶ Play и пройди **весь** маршрут игрока, как будто видишь его впервые. Отмечай, что не так:

```checklist
Плейтест:
- появляюсь на дорожке, дом виден сразу
- дорожка ровная, трава на неё не лезет
- у двери появляется подсказка, E открывает и закрывает
- в доме можно пройти везде: между мебелью, через внутренний проём
- ни за что не цепляюсь, не застреваю на пороге
- выключатели работают, подсказки у них свои
- ящик толкается и не улетает в небо
- через окно видно поле
- ночью в окнах горит свет (если оставил ночь)
- за забор можно выйти через проход
```

<details>
<summary>🔎 Подробнее: как проводят плейтест в студиях</summary>

1. **Свежий взгляд.** Лучше всего — дать поиграть другу и **молча смотреть**. Где он растерялся, там и проблема — даже если тебе «всё очевидно».
2. **Список, а не память.** Всё замеченное — сразу в список, по одной строке: «застрял у стола в гостиной». Чинить — после.
3. **Ломай специально.** Прыгай на мебель, забегай в углы, жми E двадцать раз подряд, вставай между дверью и стеной. Игроки делают именно это.
4. **Приоритеты.** Сначала то, что ломает игру (застрял, провалился), потом то, что раздражает (подсказка мигает), потом красота.

</details>

## Шаг 2. Производительность

1. ▶ Play → консоль (`` ` ``) → `stat unit`.
2. Постой в доме, посмотри на поле, на дом снаружи. Запиши **Frame** и **GPU** (в миллисекундах).
3. Ориентир: **16.7 мс = 60 FPS**, 33 мс = 30 FPS.

| Если GPU слишком большой | Попробуй |
|---|---|
| в поле | `grass.DensityScale 0.6`, меньше Cull Distance у травы |
| в доме | меньше Attenuation Radius ламп, Cast Shadows ✘ у плафонов |
| везде | спидометр над миром → **Масштабируемость окна просмотра** → «выс.» вместо «эпич.» ([картинка](../ref/06-proizvoditelnost.md#меню-производительности-и-качество)) |

<details>
<summary>🔎 Подробнее: Game, Draw, GPU — что значат числа</summary>

| Строка | Что считает | Если она главная |
|---|---|---|
| **Frame** | весь кадр | — |
| **Game** | логика: блюпринты, физика, ИИ | много Event Tick, тяжёлые циклы |
| **Draw** | подготовка к отрисовке на процессоре | слишком много отдельных объектов |
| **GPU** | работа видеокарты | трава, свет, тени, разрешение |

Кадр не может быть быстрее самой медленной части. Если GPU = 25, а Game = 5 — оптимизировать блюпринты бесполезно, упираешься в видеокарту.

В нашем доме почти наверняка главный — **GPU** (трава и Lumen).

</details>

```challenge
@id ue-dom9-fps
@type predict
@hint FPS = 1000 / мс на кадр.
В поле `stat unit` показал Frame = 33.3 мс. Сколько это FPS? Целое число.
---
float frameMs = 33.3;
int fps = Round(1000 / frameMs);
---
30
```

## Шаг 3. Дом — в блюпринт

Сейчас дом — группа из ~20 акторов. Сделаем из него **один объект**, который можно поставить второй раз.

1. Выдели в Структуре **все детали дома** (стены, пол, крышу; без мебели, двери и света — их оставим отдельно).
2. Кнопка **Blueprint** на панели инструментов → **Преобразовать выбранное в класс Blueprint…**
3. Режим — **Harvest Components** («собрать компоненты»), имя `BP_HouseShell`, папка `House/Blueprints` → **Выбрать**.
4. На уровне вместо 20 акторов — один `BP_HouseShell` с теми же стенами внутри.

<details>
<summary>🔎 Подробнее: режимы преобразования в блюпринт</summary>

| Режим | Что получится | Когда |
|---|---|---|
| **Harvest Components** | все меши становятся компонентами одного блюпринта | статичные постройки: дом, руины, мост |
| Subobjects | похоже, но сохраняет иерархию акторов | сложные наборы |
| Child Actors | каждый актор — «дочерний актор» внутри | если внутри есть свои блюпринты с логикой |

Плюс блюпринта перед группой: он **многоразовый**. Поставь второй `BP_HouseShell` в стороне — вот и деревня. Поменяй что-то в блюпринте — изменятся все дома сразу.

**Почему без двери и света?** У них своя логика и свои настройки экземпляра (Target Light, HintMessage). Их удобнее оставить отдельными акторами на уровне — или, в бонусе, сделать **Child Actor** компонентами в доме.

</details>

## Шаг 4. Настройки упаковки

1. **Правка → Project Settings…** (`Ctrl+Alt+P`).
2. **Проект → Карты и режимы** (Maps & Modes): **Game Default Map** = `num1` (уже стоит), **Default GameMode** = `BP_EmanuelGameMode`.
3. **Проект → Упаковка** (Packaging):
   - **Build Configuration** → `Development` (для первой сборки; `Shipping` — финальная, без консоли);
   - раскрой **Дополнительные** (Advanced) → **List of maps to include in a packaged build** → **+** → выбери `num1`.
4. **Проект → Описание** (Description): **Project Name** — `Мой дом`, можно поставить свою иконку.

<details>
<summary>🔎 Подробнее: Development или Shipping</summary>

| | Development | Shipping |
|---|---|---|
| Консоль (`` ` ``), `stat fps` | есть | нет |
| Логи | подробные | минимальные |
| Скорость | чуть медленнее | быстрее всего |
| Для чего | проверить, что всё работает, ловить ошибки | отдать игрокам |

Начинай с **Development**: если что-то не так, консоль и логи помогут разобраться. Когда всё хорошо — собери Shipping.

</details>

## Шаг 5. Упаковка

![Меню Платформы: пункт 2 — Упаковка проекта](../img/menu-platformy.png)

1. Сохрани всё (`Ctrl+Shift+S`).
2. **Платформы → Упаковка проекта → Windows** (Package Project).
3. Выбери папку для игры — **не** внутри `prog2`, например `D:\Desktop\MyHouseGame`.
4. Справа внизу появится окно прогресса. Не закрывай редактор. Ход — в **Журнале выходных данных** (или «Показать журнал» в окне прогресса).
5. Готово — в папке появится `Windows\prog2.exe`. Запусти его.

**Должно получиться:** игра запускается без редактора, всё работает как в ▶ Play.

<details>
<summary>🔎 Подробнее: что делает упаковка</summary>

| Этап | Что происходит |
|---|---|
| **Cook** (приготовить контент) | ассеты переводятся из формата редактора в формат игры: текстуры сжимаются под видеокарту, шейдеры компилируются для всех нужных вариантов |
| **Build** | собирается исполняемый файл (для блюпринт-проекта — берётся готовый) |
| **Stage** | всё раскладывается по папкам |
| **Package** | контент упаковывается в `.pak` / `.utoc` |

Поэтому первый раз долго: шейдеры для всех материалов собираются заново. Следующие упаковки — быстрее, кэш остаётся.

</details>

```checklist
Этап 9 готов, если:
- плейтест пройден, найденные проблемы исправлены
- знаю свои мс GPU в поле и в доме
- стены дома — один BP_HouseShell
- num1 в списке карт для упаковки
- игра собралась и запускается из .exe без редактора
```

## Если не получилось

| Что видно | Причина | Что сделать |
|---|---|---|
| «Unable to find valid C++ toolchain», ругается на SDK | нет Visual Studio — а проекту она нужна (шаг 0) | установи Visual Studio 2022 Community с нагрузкой «Разработка игр на C++» |
| в игре чёрный экран / не та карта | карта не задана | Game Default Map = num1, num1 в списке карт |
| появляется не Emanuel | Default GameMode проекта не тот | Карты и режимы → Default GameMode |
| «Unknown Cook Failure» | ошибка в каком-то ассете | в Журнале ищи первую строку `Error:` — там имя ассета |
| игра весит много ГБ | MetaHuman и 4K-текстуры | нормально; уменьшить — LOD MetaHuman, текстуры 2K |
| в .exe нет консоли | сборка Shipping | для проверки — Development |
| нет травы в игре | grass.Enable 0 осталось | в редакторе `grass.Enable 1` не сохраняется; в игре трава есть по умолчанию |

> 🧪 **Упаковка упала с ошибкой?** Подсказки по одной:

```hints
Идея: Последняя строка ошибки почти всегда — просто «упаковка не удалась». Настоящая причина написана **раньше**.
План: Журнал выходных данных → поиск по `Error:` → **первая** такая строка. В ней обычно есть имя ассета или слово toolchain / SDK.
Ключ: `toolchain` или `SDK` — поставь Visual Studio (шаг 0). Имя ассета — открой его и исправь ошибку (часто материал не компилируется).
```

Дом построен — поздравляю! Ты прошёл путь от «куда нажать» до своей игры. Дальше — по интересу:

