# Сравнения: что выбрать и почему

> Четыре сравнения, которые отвечают на самые частые вопросы: **как пишут сейчас** вместо того,
> что в учебнике; **что появилось в какой версии** языка; **какой контейнер брать**;
> и **сколько способов** решить одну задачу.
>
> Все таблицы получены проверкой на твоём компиляторе, а не переписаны откуда-то.
> Замеры скорости сделаны на твоей машине.

## 1. Старый способ → современный

Главная причина расхождений между учебником и этим справочником — возраст материала. Слева то, что ты увидишь в книгах и видео, справа — как пишут сейчас. **Старое надо уметь читать, писать так самому не надо.**

| Задача | Как в учебниках | Как сейчас | Почему поменяли |
|---|---|---|---|
| Массив чисел | `int a[100]; int n;` | `std::vector<int> v;` | размер не надо угадывать заранее, память сама освободится |
| Память | `new int[n]` … `delete[] a` | `std::vector<int> v(n);` | забытый `delete` — утечка; `vector` освобождает сам |
| Текст | `char name[50]; strcpy(...)` | `std::string name;` | длина не проверяется — источник порчи памяти |
| Пустой указатель | `NULL` | `nullptr` | `NULL` — это просто `0`, путается с числом |
| Вывод | `printf("%d\n", x)` | `std::cout` / `std::format` | `printf` верит на слово: `%d` для `double` даёт мусор |
| Форматирование | `setw`, `setprecision` | `std::format("{:<10}{:.2f}")` | настройки не «залипают», и кириллица не разъезжается |
| Константа | `#define SIZE 10` | `const int SIZE = 10;` | `#define` не знает типов и области видимости |
| Приведение типа | `(int)x` | `static_cast<int>(x)` | C-style cast молча делает **любое** преобразование |
| Псевдоним типа | `typedef long long ll;` | `using ll = long long;` | читается слева направо |
| Случайные числа | `rand() % 6` | `<random>` | у `rand()` хуже распределение |
| Удаление по условию | `v.erase(std::remove_if(...), v.end())` | `std::erase_if(v, ...)` | нечего забыть — раньше теряли `v.end()` |
| Обход контейнера | `for (int i = 0; i < n; i++)` | `for (const auto &x : v)` | нет индексов — нет выхода за границы |
| Проверка ключа | `if (m.count(key) > 0)` | `if (m.contains(key))` | читается как вопрос |
| Тип итератора | `std::map<std::string,int>::iterator it` | `auto it` | тип длинный и смысла не несёт |
| Пауза в конце | `system("pause")` | `std::cin.get()` | не запускает внешнюю программу |
| Все заголовки сразу | `#include <bits/stdc++.h>` | конкретные заголовки | нестандартно, есть только в GCC |
| Убрать `std::` | `using namespace std;` | писать `std::` | иначе своя `count` конфликтует с `std::count` |

Подробные разборы четырёх самых важных пунктов (`using namespace std`, `new`/`delete`, `printf`, C-style cast) — в [разделе 24](ref/09-spravka.md#24-устаревшее-что-встретишь-в-учебниках-и-чем-это-заменить).

### Одна и та же программа: тогда и сейчас

Задача: прочитать пять чисел, вывести их по возрастанию.

```cpp
// ❌ Стиль 2003 года — так пишут в старых учебниках
#include <cstdio>
#include <cstdlib>

int main() {
  int n = 5;
  int *a = (int *)malloc(n * sizeof(int));     // память вручную
  for (int i = 0; i < n; i++)
    scanf("%d", &a[i]);                        // без проверки: буква = мусор
  for (int i = 0; i < n - 1; i++)              // сортировка руками
    for (int j = 0; j < n - 1 - i; j++)
      if (a[j] > a[j + 1]) {
        int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
      }
  for (int i = 0; i < n; i++)
    printf("%d ", a[i]);
  free(a);                                     // забудешь — утечка
  return 0;
}
```

```cpp
// ✅ Тот же результат сегодня
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
  std::vector<int> v;
  int x = 0;
  while (v.size() < 5 && std::cin >> x)        // чтение проверяется само
    v.push_back(x);

  std::sort(v.begin(), v.end());               // сортировка одной строкой

  for (int value : v)
    std::cout << value << " ";
  return 0;                                    // память освободится сама
}
```

Второй вариант короче в три раза, и в нём **физически нет** места для четырёх классических ошибок: утечки памяти, выхода за границы, непроверенного ввода и опечатки в сортировке.

Есть и практическое следствие: **старый вариант не проходит твои же флаги сборки.** С `-Wsign-conversion` компилятор скажет:

```
warning: conversion to 'long long unsigned int' from 'int' may change the sign of the result
    6 |   int *a = (int *)malloc(n * sizeof(int));
```

Чеклист «предупреждений ноль» с таким кодом невыполним, и это не придирка: именно в таких местах и возникают ошибки, которые потом ищут часами.

## 2. Что появилось в какой версии C++

Проверено запуском компилятора со всеми пятью стандартами (`-std=c++11/14/17/20/23` плюс `-pedantic-errors`, чтобы GCC не разрешал ничего «в долг»):

| Возможность | C++11 | C++14 | C++17 | C++20 | C++23 |
|---|:---:|:---:|:---:|:---:|:---:|
| `auto`, range-for (`for (int x : v)`) | ✅ | ✅ | ✅ | ✅ | ✅ |
| Лямбды `[](int x){ ... }` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `nullptr` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `using` вместо `typedef` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `std::to_string`, `std::stoi` | ✅ | ✅ | ✅ | ✅ | ✅ |
| Структурные привязки `auto [a, b]` | — | — | ✅ | ✅ | ✅ |
| `if (auto it = ...; условие)` | — | — | ✅ | ✅ | ✅ |
| `std::optional` | — | — | ✅ | ✅ | ✅ |
| `std::clamp` | — | — | ✅ | ✅ | ✅ |
| `std::gcd`, `std::lcm` | — | — | ✅ | ✅ | ✅ |
| `std::string_view` | — | — | ✅ | ✅ | ✅ |
| `map::contains`, `set::contains` | — | — | — | ✅ | ✅ |
| `std::erase_if` | — | — | — | ✅ | ✅ |
| `std::format` | — | — | — | ✅ | ✅ |
| `std::ranges::sort`, `views::filter` | — | — | — | ✅ | ✅ |
| `str.contains("...")` у `string`/`string_view` | — | — | — | — | ✅ |
| `std::println`, `std::print` | — | — | — | — | ✅ * |
| `std::ranges::to<std::vector>()` | — | — | — | — | ✅ |
| `views::enumerate`, `views::zip` | — | — | — | — | ✅ |
| `std::expected<T, E>` | — | — | — | — | ✅ |

`*` `std::println` на твоей сборке (MinGW) собирается только с `-std=c++23` **и** дополнительным `-lstdc++exp` при линковке — с кнопкой `Ctrl+Alt+R` (обычная сборка одного файла) не заработает. Пока печатай через `std::format` + `std::cout`.

**У тебя выбран C++20** (прописан в `settings.json`), поэтому всё до C++20 включительно доступно из коробки. Сам компилятор — g++ 15.2 — понимает и **C++23**, но только с флагом `-std=c++23` (по `Ctrl+Alt+R` сборка идёт в C++20, так что строки из последней колонки по умолчанию не соберутся). Знать таблицу полезно:

- если код с `std::format` не собирается у одногруппника — у него стандарт ниже или GCC старше 13;
- если материал в интернете обходится без `contains`/`format` — он написан до 2020 года, и там наверняка есть и другие устаревшие приёмы;
- если увидел `std::println`, `std::expected` или `views::enumerate` — это уже C++23; попробовать можно, добавив `-std=c++23` в сборку (а для `std::println` ещё и `-lstdc++exp`).

Проверить свой стандарт можно так:

```cpp
#include <iostream>
int main() { std::cout << __cplusplus << "\n"; }   // C++20 → 202002, C++23 → 202302
```

## 3. Какой контейнер выбрать

### По задаче

| Вопрос задачи | Контейнер | Почему |
|---|---|---|
| «список по порядку», «третий элемент» | `std::vector` | индексы, порядок сохраняется |
| «найти по имени», «для каждого X хранить Y» | `std::map` | поиск по ключу, отсортирован по нему |
| «а это уже было?», «только уникальные» | `std::set` | дубликаты игнорируются сами |
| «две величины вместе» | `std::pair` | без объявления своего типа |
| «несколько полей об одном объекте» | `struct` | у полей есть имена |
| «таблица», «матрица» | `vector<vector<...>>` | строка и столбец |
| «нужна только скорость, порядок не важен» | `std::unordered_map` | хеш-таблица |

### По свойствам

| | `vector` | `map` | `set` | `unordered_map` |
|---|---|---|---|---|
| Доступ по индексу | ✅ `v[i]` | — | — | — |
| Доступ по ключу | — | ✅ | — | ✅ |
| Порядок при переборе | как добавлял | по возрастанию ключа | по возрастанию | **произвольный** |
| Дубликаты | хранит | ключи уникальны | не хранит | ключи уникальны |
| Поиск | перебором | быстро | быстро | очень быстро |
| Что требует от типа | ничего | `operator<` | `operator<` | хеш-функцию |

### Насколько важна скорость: замер

Программа-замер на **твоей** машине: 50 000 записей, 20 000 поисков по строковому ключу.

```
vector + find_if : 1304 мс
map              :    7 мс      ← в 186 раз быстрее
unordered_map    :    1 мс      ← в 1300 раз быстрее
```

Выглядит убедительно — но вот тот же замер на **100 записях** (столько бывает в учебной задаче):

```
vector + find_if :    4 мс
map              :    0 мс
unordered_map    :    0 мс
```

Четыре миллисекунды на двадцать тысяч поисков. Разницы нет никакой.

> **Вывод честный:** пока данных мало, выбирай контейнер **по смыслу задачи**, а не по скорости. «Найти по имени» — это `map`, потому что так короче и понятнее код, а не потому что быстрее. Скорость начинает решать на десятках тысяч элементов — и тогда замер, а не догадки.
>
> `unordered_map` быстрее `map`, но перебор идёт в произвольном порядке — вывод на экран будет «прыгать» между запусками. Для учебных задач это заметнее, чем миллисекунды. Подробнее — [раздел 13](ref/06-konteynery.md#13-stdunordered_map).

## 4. Одна задача — три решения

Задача: **сумма положительных чисел в векторе.** Все три варианта дают одинаковый ответ (проверено запуском), но читаются по-разному.

```cpp
// Решение 1: ручной цикл. Понятно всем и всегда.
long long sum = 0;
for (int x : v)
  if (x > 0)
    sum += x;
```

```cpp
// Решение 2: алгоритм с накопителем.
#include <numeric>

long long sum = std::accumulate(v.begin(), v.end(), 0LL,
                                [](long long acc, int x) { return x > 0 ? acc + x : acc; });
```

```cpp
// Решение 3: ranges (C++20). Читается как фраза: «отфильтровать и сложить».
#include <ranges>

long long sum = 0;
for (int x : v | std::views::filter([](int y) { return y > 0; }))
  sum += x;
```

| | Плюсы | Минусы | Когда брать |
|---|---|---|---|
| Ручной цикл | понятен без подготовки, легко отладить пошагово | четыре строки вместо одной | **по умолчанию, пока учишься** |
| `accumulate` | одна операция, видно замысел | лямбда с накопителем читается не сразу | когда цикл — только ради суммы |
| `ranges` | ближе всего к формулировке задачи | самый новый синтаксис, требует C++20 | когда условий несколько и они складываются в цепочку |

**Что выбрать?** Пока учишься — **ручной цикл**: его видно в отладчике по шагам, и в нём нельзя запутаться. Алгоритмы стоит узнавать, потому что в чужом коде они везде, и `std::sort` руками писать точно не надо. А `ranges` — приятная вещь, к которой имеет смысл прийти позже.

Совет не в том, чтобы всегда писать короче. **Короче ≠ понятнее.** Хорошая мера: если через месяц ты сам не прочитаешь свою строку без запинки — она слишком умная.

### Та же мысль на сортировке

```cpp
std::sort(v.begin(), v.end());                        // классика, работает всегда
std::sort(v.begin(), v.end(), std::greater<int>());   // по убыванию
std::ranges::sort(v);                                 // C++20, короче на два вызова
```

Все три строки в учебниках и на форумах встречаются постоянно — узнавать надо все, писать можно любую.

## 5. Что дорого, а что бесплатно

Мелочь, из которой складывается «программа тормозит на больших данных».

| Дорого | Дешёво | Разница |
|---|---|---|
| `for (std::string s : names)` | `for (const std::string &s : names)` | копия каждой строки на каждом витке |
| `void f(std::vector<int> v)` | `void f(const std::vector<int> &v)` | копия всего вектора при каждом вызове |
| `std::endl` в цикле | `"\n"` | `endl` сбрасывает буфер на диск каждый раз |
| поиск перебором в `vector` | `map` / `set` | см. замер выше |
| `v.insert(v.begin(), x)` | `v.push_back(x)` | вставка в начало сдвигает весь вектор |

Для `int`, `double`, `bool`, `char` копия ничего не стоит — там пиши как удобнее. Правило `const auto &` касается **строк, векторов, словарей и структур**.

> Не оптимизируй заранее. Сначала пусть программа будет правильной и понятной; ускорять её стоит тогда, когда стало заметно медленно — и после замера, а не по догадке. Единственное исключение — `const auto &` в range-for: это не оптимизация, а просто нормальный способ писать.
