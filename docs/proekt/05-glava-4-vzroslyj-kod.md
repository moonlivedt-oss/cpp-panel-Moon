## Квест 12. Порядок в папке

**Нужна тема:** [Разделение на файлы](../ref/19-razdelenie.md).

`main.cpp` к этому моменту перевалил за несколько сотен строк. Разложите игру по файлам:

- `hero.h` / `hero.cpp` — класс героя; `monster.h` / `monster.cpp` — монстры; `map.h` / `map.cpp` — карта и движение; `save.h` / `save.cpp` — сохранение;
- в `.h` — только объявления, в `.cpp` — тела; в каждом заголовке `#pragma once`;
- `main.cpp` остаётся коротким: создать героя, загрузить карту, запустить игровой цикл.

```checklist
Квест 12 готов, если:
- игра собирается командой со всеми .cpp (или одной кнопкой / CMake) без предупреждений
- в заголовках нет тел функций (кроме маленьких inline)
- main.cpp помещается на один экран
```

> 💾 **Сохраните версию:** `git add . && git commit -m "Квест 12: Порядок в папке"` — к ней всегда можно вернуться (`git log`, `git checkout`).

## Квест 13. Ничто не роняет игру

**Нужны темы:** [Исключения](../ref/14-isklyucheniya.md) и [`string_view`](../ref/15-string-view.md).

- `loadGame` при битом файле **бросает** `std::runtime_error` с понятным текстом («строка 3: hp не число»), а `main` ловит его, показывает сообщение и предлагает начать новую игру;
- разбор команд принимает `std::string_view` и режет строку без копий: `go north`, `take sword`;
- неизвестная команда — обычное сообщение, а не исключение: исключения — только для настоящих сбоев.

```checklist
Квест 13 готов, если:
- испорченный вручную файл сохранения не роняет игру, а даёт понятное сообщение
- в функциях разбора команд нет копий строк (параметры — std::string_view)
- try / catch стоит в одном месте — там, где можно что-то сделать с ошибкой
```

> 💾 **Сохраните версию:** `git add . && git commit -m "Квест 13: Ничто не роняет игру"` — к ней всегда можно вернуться (`git log`, `git checkout`).

## Квест 14. Инвентарь без лишних копий

**Нужны темы:** [Перемещение](../ref/23-peremeshchenie.md) и [Диапазоны](../ref/16-ranges.md).

- Предмет — `struct Item` с именем, описанием и ценой. Из сундука в инвентарь он **переезжает**: `std::move` и `emplace_back`, а не копия;
- команда `inv` сортирует инвентарь по цене проекцией: `std::ranges::sort(items, {}, &Item::price)`;
- команда `junk` показывает дешёвые предметы конвейером `views::filter`, а `sell junk` продаёт их разом через `std::erase_if`.

```checklist
Квест 14 готов, если:
- подобранный предмет исчезает из сундука (он переехал, а не скопировался)
- сортировка и фильтр — без ручных циклов с индексами
- продажа хлама прибавляет золото и не оставляет «дыр» в инвентаре
```

> 💾 **Сохраните версию:** `git add . && git commit -m "Квест 14: Инвентарь без лишних копий"` — к ней всегда можно вернуться (`git log`, `git checkout`).

## Квест 15. Одна таблица добычи для всего

**Нужны темы:** [Шаблоны](../ref/17-shablony.md) и [Умные указатели](../ref/18-umnye-ukazateli.md).

- Шаблон `WeightedTable<T>`: `add(value, weight)` и `roll(rng)` — случайный выбор с весами;
- одна и та же таблица работает и для добычи (`WeightedTable<Item>`), и для встреч (`WeightedTable<MonsterKind>`);
- фабрика `makeMonster(MonsterKind)` возвращает `std::unique_ptr<Monster>` — владелец у монстра всегда один.

```checklist
Квест 15 готов, если:
- WeightedTable написан один раз и используется минимум для двух разных типов
- редкость легко поменять числом веса, код выбора не трогается
- в игре нет new / delete
```

> 💾 **Сохраните версию:** `git add . && git commit -m "Квест 15: Одна таблица добычи для всего"` — к ней всегда можно вернуться (`git log`, `git checkout`).

## Квест 16. Сборка на CMake

**Нужна тема:** [CMake](../ref/24-cmake.md).

Командой `g++ *.cpp` игру уже неудобно собирать: файлов много, а для проверки логики хочется отдельную программу-тест. Переведите проект на CMake:

- библиотека `dungeon_core` — вся логика (герой, монстры, карта, сохранение, таблица добычи); папка `include/` отдана ей как `PUBLIC`;
- программа `game` — только `main.cpp` + `target_link_libraries(game PRIVATE dungeon_core)`;
- программа `combat_test` проверяет 2–3 функции боя и возвращает `0`/`1`; подключена через `enable_testing()` и `add_test`;
- строгие предупреждения на обе программы; две сборки рядом — `build-debug` и `build-release`.

```checklist
Квест 16 готов, если:
- cmake -S . -B build && cmake --build build собирает всё без предупреждений
- ctest --test-dir build --output-on-failure — зелёный
- добавить новый .cpp в логику = дописать одну строку в add_library
```

> 💾 **Сохраните версию:** `git add . && git commit -m "Квест 16: Сборка на CMake"` — к ней всегда можно вернуться (`git log`, `git checkout`).
