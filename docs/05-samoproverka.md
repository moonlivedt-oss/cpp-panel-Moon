# Самопроверка: что напечатает этот код?

> Шестнадцать вопросов на те самые места, где C++ ведёт себя не так, как кажется.
> Впиши, что, по-твоему, напечатает код, и нажми «Проверить»; объяснение — под «Почему так». **Все ответы получены запуском** на твоём компиляторе.
>
> Это не экзамен. Смысл в том, чтобы узнать ловушку сейчас, а не в своей программе через месяц.

## Числа

### 1. Деление

```challenge
@id cqm8xyg
@type predict
Что напечатает этот код?
---
std::cout << 7 / 2 << " " << 7 / 2.0;
---
3 3.5
```

<details><summary>Почему так</summary>

Оба операнда целые → результат целый, дробная часть **отбрасывается** (не округляется!). Стоит одному операнду стать дробным — считается в `double`.
→ [раздел 5](ref/03-logika-cikly.md#ловушка-целочисленное-деление)
</details>

### 2. Среднее из двух

```challenge
@id ct81hro
@type predict
Что напечатает этот код?
---
int n = 3;
double avg = n / 2;
std::cout << avg;
---
1
```

<details><summary>Почему так</summary>

Не `1.5`. Деление `3 / 2` целочисленное и произошло **до** того, как результат попал в `double`. Тип переменной слева ни на что не влияет.

Правильно: `double avg = n / 2.0;`
</details>

### 3. Приведение не там

```challenge
@id ceym4q5
@type predict
Что напечатает этот код?
---
int a = 5, b = 2;
std::cout << static_cast<double>(a / b);
---
2
```

<details><summary>Почему так</summary>

`static_cast` применён к **результату**, а деление уже случилось в целых. Приводить надо операнд: `static_cast<double>(a) / b`.
</details>

### 4. Символ или число?

```challenge
@id c16wrffw
@type predict
Что напечатает этот код?
---
char c = '5';
std::cout << c << " " << c + 0 << " " << c - '0';
---
5 53 5
```

<details><summary>Почему так</summary>

`c` печатается как символ `5`, но внутри лежит **код** символа — 53. Вычитание `- '0'` превращает символ в цифру.
→ [раздел 2](ref/01-osnovy.md#ловушка-char--это-символ-а-не-число)
</details>

### 5. Остаток с минусом

```challenge
@id cw1hl9c
@type predict
Что напечатает этот код?
---
std::cout << -7 % 3 << " " << 7 % -3;
---
-1 1
```

<details><summary>Почему так</summary>

Знак берётся от **левого** операнда. Поэтому «последняя цифра числа» через `n % 10` для отрицательных даёт минус — нужен `std::abs(n) % 10`.
→ [раздел 5](ref/03-logika-cikly.md#ловушка--с-отрицательными-числами)
</details>

### 6. Дробные и равенство

```challenge
@id c11qcvyx
@type predict
Что напечатает этот код?
---
std::cout << (0.1 + 0.2 == 0.3);
---
0
```

<details><summary>Почему так</summary>

То есть **ложь**. `0.1` в двоичной системе — бесконечная дробь, хранится приближение, погрешности накапливаются. Сравнивать надо с допуском: `std::abs(a - b) < 1e-9`.
→ [раздел 5](ref/03-logika-cikly.md#ловушка-сравнение-дробных-на-равенство)
</details>

### 7. Сумма больших чисел

```challenge
@id c15zw7me
@type predict
Что напечатает этот код?
---
std::vector<int> v = {2000000000, 2000000000};
int s1 = std::accumulate(v.begin(), v.end(), 0);
long long s2 = std::accumulate(v.begin(), v.end(), 0LL);
std::cout << s1 << " | " << s2;
---
-294967296 | 4000000000
```

<details><summary>Почему так</summary>

Начальное значение задаёт тип, в котором идёт сложение. С `0` сумма считается в `int` и молча переполняется — результат отрицательный. С `0LL` всё верно.
→ [раздел 18](ref/07-algoritmy.md#18-алгоритмы)
</details>

## Знаковость

### 8. Беззнаковое вычитание

```challenge
@id c1tym8e5
@type predict
Что напечатает этот код?
---
unsigned int u = 3;
std::cout << (u - 5);
---
4294967294
```

<details><summary>Почему так</summary>

У `unsigned` не бывает отрицательных значений: `3 - 5` «заворачивается» к максимуму. Отсюда правило — читать пользовательский ввод только в `int`.
→ [раздел 2](ref/01-osnovy.md#ловушка-unsigned-и-пользовательский-ввод)
</details>

### 9. Размер больше минус единицы?

```challenge
@id c295rvp
@type predict
Что напечатает этот код?
---
std::vector<int> v = {1, 2, 3};
std::cout << (v.size() > -1);
---
0
```

<details><summary>Почему так</summary>

**Ложь** — хотя размер 3, и он явно больше −1. Перед сравнением `-1` превращается в огромное беззнаковое число, и `3 > 18446744073709551615` действительно ложь.

Именно об этом предупреждает `-Wsign-compare`.
</details>

### 10. Пустой вектор

```challenge
@id cxzn2e9
@type predict
Что напечатает этот код?
---
std::vector<int> v;
std::cout << (v.size() - 1);
---
18446744073709551615
```

<details><summary>Почему так</summary>

`size()` беззнаковый: `0 - 1` даёт максимум. Поэтому `for (std::size_t i = 0; i < v.size() - 1; ++i)` на пустом векторе уходит в бесконечный цикл и портит память.

Пиши `i + 1 < v.size()`.
→ [раздел 2](ref/01-osnovy.md#stdsize_t--почему-компилятор-ругается-на-vsize)
</details>

## Контейнеры

### 11. Чтение из словаря

```challenge
@id c12d9dt
@type predict
Что напечатает этот код?
---
std::map<std::string, int> m;
m["a"] = 1;
int val = m["b"];
std::cout << val << " " << m.size();
---
0 2
```

<details><summary>Почему так</summary>

Размер стал **два**: обращение `m["b"]` при чтении молча создало ключ `"b"` со значением `0`. Читать надо через `m.at()`, `m.find()` или `m.contains()`.
→ [раздел 12](ref/06-konteynery.md#главная-ловушка--при-чтении-создаёт-элемент)
</details>

### 12. Изменение в цикле

```challenge
@id c1r4fuw2
@type predict
Что напечатает этот код?
---
std::vector<int> v = {1, 2, 3};
for (int x : v)
  x *= 2;
std::cout << v[0] << v[1] << v[2];
---
123
```

<details><summary>Почему так</summary>

Вектор не изменился: `int x` — **копия** элемента, умножается она. Чтобы менять на месте, нужна ссылка: `for (int &x : v)`.
→ [раздел 8](ref/03-logika-cikly.md#какой-цикл-когда)
</details>

### 13. Подстрока

```challenge
@id cd0310g
@type predict
Что напечатает этот код?
---
std::string s = "hello";
std::cout << s.substr(1, 3);
---
ell
```

<details><summary>Почему так</summary>

Второй аргумент — **сколько символов**, а не «до какой позиции». Частая ошибка: ждут `ello`.
</details>

## Условия

### 14. Цепочка сравнений

```challenge
@id c1vfyefq
@type predict
Что напечатает этот код?
---
int x = 15;
std::cout << (1 < x < 10);
---
1
```

<details><summary>Почему так</summary>

То есть **истина** — хотя 15 явно не между 1 и 10. Считается слева направо: `1 < 15` → `true` → `1`, затем `1 < 10` → истина. Условие истинно для любого `x`.

Правильно: `x > 1 && x < 10`.
→ [раздел 6](ref/03-logika-cikly.md#цепочки-сравнений--так-нельзя)
</details>

## Текст и вывод

### 15. Длина русской строки

```challenge
@id c1jgvu85
@type predict
Что напечатает этот код?
---
std::string ru = "Привет";
std::cout << ru.length();
---
12
```

<details><summary>Почему так</summary>

Не `6`. В UTF-8 русская буква занимает два байта, а `length()` считает **байты**. Поэтому русский текст нельзя перебирать через `s[i]` и резать через `substr`.
→ [раздел 10](ref/05-stroki.md#10-stdstring)
</details>

### 16. Таблица с русскими подписями

```challenge
@id cxm0dvr
@type predict
Что напечатает этот код?
---
std::cout << "[" << std::setw(8) << "Имя" << "] ["
          << std::setw(8) << "Name" << "]";
---
[     Имя] [    Name]
```

<details><summary>Почему так</summary>

Столбцы разной ширины: `setw` отсчитывает **байты**, а «Имя» занимает 6 байт против 4 у «Name». На экране колонки разъезжаются.

Лечится `std::format`, который считает символы:
```cpp
std::cout << std::format("[{:>8}] [{:>8}]", "Имя", "Name");
```
→ [раздел 4](ref/02-vvod-vyvod.md#stdformat--современный-способ-c20)
</details>

## Сколько правильных?

| Правильных | Что это значит |
|---|---|
| 13–16 | Ловушки ты знаешь. Дальше — [примеры программ](examples/README.md) и задачник |
| 8–12 | Нормальный результат. Перечитай разделы по ссылкам под теми ответами, где ошибся |
| меньше 8 | Не расстраивайся: почти каждый вопрос здесь — это чья-то потерянная пара часов. Пройди [шпаргалку](01-shpargalka.md) и вернись |

Промахи полезнее попаданий: каждый показывает, где интуиция расходится с языком. Именно эти места и стоит перечитать.
