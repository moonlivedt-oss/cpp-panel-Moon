# Задачник — отработка тем

> Задачи построены на тех же темах, что `les_3`, но каждая добавляет один новый поворот.
> Порядок внутри блока — от простого к сложному. Блоки можно брать не подряд.

---

## Как отрабатывать тему

Один цикл на каждую задачу — примерно 20–30 минут:

1. **Прочитал условие → закрыл файл.** Пиши по памяти, не подглядывая в примеры.
2. **Написал → собрал с `Ctrl+Alt+R`.** Предупреждений ноль.
3. **Прогнал тест-план из 6 значений:** буква, пустой Enter, `0`, `-5`, `2000000000`, границы.
4. **Сломалось → нашёл причину, а не просто починил.** Таблица «симптом → причина» — в [00-НАЧНИ-ОТСЮДА.md](00-НАЧНИ-ОТСЮДА.md), раздел 23.
5. **Заработало → прочитал «Ловушка» под задачей.** Учёл её? Если нет — вернись к пункту 2.

Тема считается закрытой, когда можешь написать **три задачи блока подряд без подглядывания**.

**Отметки сложности:** 🟢 знаешь всё нужное · 🟡 нужен один новый приём · 🔴 требует подумать

**Подсказки спрятаны под треугольником** — открывай только после 15 минут собственных попыток. Раньше — обесценишь задачу.

**«Пример»** под условием показывает вход и ожидаемый выход — сверяйся с ним, когда «вроде работает».

**⭐ Бонус** — необязательный поворот для тех, кому основной задачи мало. Он её не усложняет: сначала базовое условие, звёздочка — на десерт.

**Два блока не на «написать с нуля», а на чтение чужого кода** — самый недооценённый навык: [🐛 Найди баг](#блок-l-найди-баг) и [🔧 Перепиши по-современному](#блок-m-перепиши-по-современному).

## Блок A. Вывод и форматирование

Разминка. Здесь нет логики, только аккуратность вывода — то, на чём в `les_3` были склеенные строки.

### A1. Визитка 🟢
Вывести своё имя, возраст и город тремя строками, обрамлёнными рамкой из `=`.
**Тренирует:** `cout`, `"\n"`, ровный вывод.
**Ловушка:** рамка должна быть одинаковой длины сверху и снизу.

### A2. Таблица умножения 🟢
Таблица 5×5 ровными столбцами.
**Тренирует:** вложенный цикл, `std::setw` из `<iomanip>`.
**Ловушка:** без `setw(4)` столбцы поедут, как только числа станут двузначными.

### A3. Ёлочка 🟡
Пирамида из `*` высотой `n`, по центру.
```
   *
  ***
 *****
```
**Тренирует:** вложенный цикл, где внутренних циклов два — пробелы и звёздочки.
**Ловушка:** количество пробелов в строке `i` — это `n - i - 1`, легко ошибиться на единицу.

### A4. Рамка 🟡
Прямоугольник `n × m` из `#`, пустой внутри.
**Тренирует:** условие внутри вложенного цикла.
**Ловушка:** `n` или `m` равные 1 и 2 — рамка не должна разваливаться.

### A5. Шахматная доска 🟡
Доска 8×8 из символов `#` и `.` в шахматном порядке.
**Тренирует:** `(i + j) % 2`.
**Ловушка:** очевидная проверка `i % 2 == 0` даёт полосы, а не клетки.

## Блок B. Ввод, типы и переполнение

Здесь живут самые дорогие ошибки из `les_3`. Каждая задача проверяется вводом буквы.

### B1. Чек в кафе 🟢
Три позиции заказа (цены целыми рублями). Выведи итог, средний чек и «с доставкой» (× 2 к итогу).
**Пример:** `150 200 100` → итог `450`, средний `150.0`, с доставкой `900`.
**Тренирует:** типы результата.
**Ловушка:** «с доставкой» на больших ценах не влезет в `int` — держи в `long long`; средний чек — `double`, а не `sum / 3` целочисленным делением.
**⭐ Бонус:** добавь чаевые 10% от итога и выведи финальную сумму с двумя знаками после точки.

### B2. Обмен значений 🟢
Ввести два числа, поменять местами, вывести. Сначала через третью переменную, потом через `std::swap`.
**Тренирует:** понимание, что переменная — это ячейка.

### B3. Калькулятор 🟡
Ввести число, знак операции (`+ - * /`), второе число. Вывести результат.
**Тренирует:** `switch` по `char`, обработка ошибок.
**Ловушка:** деление на ноль — это падение программы, а не «бесконечность». Проверь до деления. Ещё: `10 / 4` для целых даст `2`.

### B4. Сумма 1..n двумя способами 🟡
Посчитать сумму циклом и по формуле `n * (n + 1) / 2`. Вывести оба результата.
**Тренирует:** переполнение вживую.
**Ловушка:** попробуй `n = 100000` в `int` — увидишь разные ответы. Потом почини через `1LL *` и сравни снова.

### B5. Безопасный ввод в диапазоне 🟡
Написать `readIntInRange(prompt, lo, hi)` — просит число, пока не введут корректное **и** попадающее в `[lo, hi]`.
**Тренирует:** `cin.clear()`, `cin.ignore()`, цикл-валидатор.
**Ловушка:** без `ignore` получится бесконечный цикл. Проверь вводом `abc`.

> Это заготовка на все следующие задачи. Напиши её один раз хорошо — дальше просто копируй.

### B6. Имя и возраст 🟢
Спросить имя (строкой целиком, с пробелами), потом возраст числом. Вывести обе величины.
**Тренирует:** `getline` вместе с `>>`.
**Ловушка:** `cin >> age` оставляет в буфере Enter, и следующий `getline` вернёт пустую строку. Нужен `cin.ignore()` между ними.

## Блок C. Формулы и единицы

Прямое продолжение задачи про сантиметры и дюймы.

### C1. Одометр проката 🟢
Взял машину за границей — одометр в милях, а тебе привычнее километры. Переведи введённое расстояние в обе стороны. `1 миля = 1.609344 км`.
**Пример:** `100` миль → `160.93` км; `100` км → `62.14` мили.
**Ловушка:** коэффициент — именованная `const double`, а не число посреди кода.
**⭐ Бонус:** посчитай стоимость бензина на эту дистанцию при расходе 8 л/100 км и цене за литр с клавиатуры.

### C2. Прогноз для друга за границей 🟢
Друг присылает погоду в Фаренгейтах, а ты живёшь в Цельсиях. Переведи введённый Цельсий сразу в Фаренгейт и Кельвин. `F = C * 9 / 5 + 32`, `K = C + 273.15`.
**Пример:** `25` °C → `77.0` °F, `298.15` K.
**Ловушка:** `9 / 5` в целых числах даст `1`. Пиши `9.0 / 5.0`.
**⭐ Бонус:** добавь обратный перевод — из Фаренгейта в Цельсий, и проверь, что `25 → 77 → 25`.

### C3. Секунды в часы 🟡
Ввести число секунд, вывести в формате `чч:мм:сс` с ведущими нулями.
**Тренирует:** `/` и `%` вместе, `setw(2)` и `setfill('0')`.
**Ловушка:** `3661` должно дать `01:01:01`, а не `1:1:1`.

### C4. Корзина со скидкой 🟢
Цена товара и процент скидки по промокоду — посчитай, сколько платить, с округлением до копеек.
**Пример:** цена `1000`, скидка `15` % → к оплате `850.00`.
**Тренирует:** `setprecision(2)` и `fixed`.
**Ловушка:** скидка больше 100 % или отрицательная — отсеки (иначе «доплатят тебе»).
**⭐ Бонус:** после скидки добавь НДС 20 % и покажи две строки — «со скидкой» и «итог с НДС».

### C5. Площади фигур 🟡
Круг (по радиусу), прямоугольник, треугольник по трём сторонам (формула Герона).
**Тренирует:** `<cmath>`, `sqrt`, `M_PI` или своя константа.
**Ловушка:** перед Героном проверь, что треугольник вообще существует — иначе под корнем окажется отрицательное число и получится `nan`.

### C6. Расстояние между точками 🟢
Ввести координаты двух точек, вывести расстояние.
**Тренирует:** `sqrt`, `pow`.
**Ловушка:** `pow(x, 2)` работает, но `(x2 - x1) * (x2 - x1)` точнее и быстрее.

## Блок D. Ветвления

### D1. Знак числа 🟢
Положительное / отрицательное / ноль.
**Ловушка:** ноль — отдельная ветка, а не «иначе».

### D2. Максимум из трёх 🟢
Найти наибольшее из трёх чисел, **не используя** `std::max`.
**Ловушка:** равные значения не должны ломать логику. Проверь `5 5 5` и `5 5 3`.
**⭐ Бонус:** выведи и **второе** по величине — на трёх числах это отличная разминка перед J5.

### D3. Квадратное уравнение 🔴
Ввести `a`, `b`, `c`. Вывести корни.
**Тренирует:** разбор случаев.
**Ловушка:** случаев не три, а **пять**: `D > 0`, `D == 0`, `D < 0`, плюс `a == 0` (уравнение линейное) и `a == 0 && b == 0`.

<details>
<summary>Подсказка</summary>

Начни с `if (a == 0)` — это отдельная ветка ещё до дискриминанта. Внутри неё снова развилка: `b == 0` (либо любой корень, либо ни одного) или обычное линейное уравнение `x = -c / b`.

Для `double` не сравнивай с нулём через `==`. Пиши `std::abs(a) < 1e-9`.
</details>

### D4. Високосный год 🟡
Написать самому, не подглядывая в `les_3`.
**Ловушка:** проверь `1900` (не високосный), `2000` (високосный), `2024` (високосный). Формула, которая ошибается на `1900`, — самая частая.

### D5. Точка в фигуре 🟡
Ввести координаты точки и проверить: внутри круга радиуса `R` с центром в начале координат? Внутри прямоугольника?
**Ловушка:** на самой границе — это внутри или снаружи? Решить и написать в комментарии, какое решение выбрал.

### D6. Ход коня 🟡
Прямое продолжение задачи про ферзя. Ввести две клетки, ответить, может ли конь пойти.
**Тренирует:** та же схема, другое правило.
**Ловушка:** правило коня — `dx * dy == 2` (то есть 1×2 или 2×1). Не забудь проверку выхода за доску **для всех четырёх** координат — именно на ней в `les_3` была опечатка.

### D7. Все фигуры сразу 🔴
Ввести фигуру (`К` — король, `Л` — ладья, `С` — слон, `Ф` — ферзь, `N` — конь) и две клетки. Ответить, возможен ли ход.
**Тренирует:** функции, `switch`, переиспользование кода.
**Ловушка:** проверка «на доске ли» пишется **один раз** отдельной функцией. Если она у тебя скопирована в пять мест — задача не решена.

### D8. Классификация треугольника 🔴
Ввести три стороны. Вывести: существует ли; равносторонний / равнобедренный / разносторонний; остроугольный / прямоугольный / тупоугольный.
**Тренирует:** несколько независимых классификаций подряд.
**Ловушка:** после «не существует» — сразу `return`, а не продолжение расчётов. Ровно этот баг был в `les_3`.

<details>
<summary>Подсказка</summary>

Отсортируй стороны (`std::sort`), тогда `c` — наибольшая, и вид угла определяется одним сравнением:
`a² + b² > c²` — остроугольный, `==` — прямоугольный, `<` — тупоугольный.

Квадраты считай в `long long`.
</details>

## Блок E. switch

### E1. День недели 🟢
Число 1–7 → название дня.
**Ловушка:** `default` обязателен — что если ввели 0 или 9?

### E2. Месяц и время года 🟡
Номер месяца → название месяца **и** время года.
**Тренирует:** несколько `case` подряд без `break`.
**Ловушка:** зима — это 12, 1, 2. Три несоседних числа в одной группе.

### E3. Оценка словами 🟢
1–5 → «неудовлетворительно» … «отлично».

### E4. Римские цифры 🟡
Число 1–10 → римская запись. Потом обратно: римская → число.
**Ловушка:** `switch` по строке не работает. Для обратного перевода нужен `if/else` со сравнением строк.

### E5. Меню-калькулятор 🔴
Программа в цикле: показывает меню, ждёт выбор, выполняет действие, возвращается в меню. Выход по `0`.
**Тренирует:** `while (true)` + `switch` + `break` из цикла.
**Ловушка:** `break` внутри `switch` выходит **из switch**, а не из цикла. Понадобится флаг или `return`.

## Блок F. Циклы

### F1. Чётные и нечётные 🟢
Все чётные от 1 до `n`, затем все нечётные — в обратном порядке.
**Ловушка:** `n < 1` — цикл не должен выполниться ни разу и не должен ничего печатать.

### F2. Факториал 🟡
`n!` для введённого `n`.
**Тренирует:** накопление в цикле, переполнение.
**Ловушка:** `20!` — последнее, что влезает в `long long`. Проверь `21!` и посмотри, что будет. Ограничь ввод.

### F3. Степень без `pow` 🟢
Возвести `a` в степень `n` циклом.
**Ловушка:** `n == 0` даёт `1`. Отрицательная степень — отдельный разговор, реши, что делаешь.

### F4. Фибоначчи 🟡
Вывести первые `n` чисел Фибоначчи.
**Пример:** `n = 8` → `0 1 1 2 3 5 8 13`.
**Ловушка:** хранить нужно только два последних числа, массив не требуется. И снова `long long` — рост быстрый.
**⭐ Бонус:** выведи только **чётные** числа Фибоначчи среди первых `n` и заметь закономерность — каждое третье.

### F5. Простое ли число 🟡
**Тренирует:** ранний выход из цикла.
**Ловушка:** `1` — не простое, `2` — простое. Делители достаточно проверять до `sqrt(n)` — подумай, почему это правда, прежде чем писать.

### F6. Все простые до n 🟡
Список простых чисел от 2 до `n`.
**Тренирует:** цикл в цикле, переиспользование функции из F5.
**Ловушка:** если написал F5 функцией — здесь работы на три строки. Если не функцией — переписывай.

### F7. НОД и НОК 🟡
Алгоритм Евклида.
**Тренирует:** цикл с двумя меняющимися переменными.
**Ловушка:** `НОК = a * b / НОД` переполняется. Дели **до** умножения: `a / НОД * b`.

<details>
<summary>Подсказка — алгоритм Евклида</summary>

```cpp
while (b != 0) {
  int t = b;
  b = a % b;
  a = t;
}
// в a лежит НОД
```
Четыре строки. Стоит один раз разобрать, почему это работает.
</details>

### F8. Угадай число 🟡
Компьютер загадывает от 1 до 100, пользователь угадывает, программа отвечает «больше»/«меньше». Ограничение — 7 попыток.
**Тренирует:** случайные числа (лучше `<random>`, чем старый `rand()`), цикл с двумя условиями выхода.
**Ловушка:** с `rand()` без `srand` число одно и то же при каждом запуске; с `<random>` этой ловушки нет.
**⭐ Бонус:** поменяй роли — теперь **загадывает пользователь, а угадывает компьютер** (делением пополам). Всегда ли он укладывается в 7 попыток? Почему именно 7?

### F9. Таблица квадратов и кубов 🟢
От 1 до `n`, три ровных столбца.
**Ловушка:** куб числа 2000 не влезает в `int`.

### F10. Сумма ряда 🟡
Посчитать `1 + 1/2 + 1/3 + ... + 1/n`.
**Ловушка:** `1 / i` в целых числах — это ноль для всех `i > 1`. Нужно `1.0 / i`.

## Блок G. Цифры числа

Продолжение девятого задания. Все задачи — на связку `% 10` и `/ 10`.

### G1. Произведение цифр 🟢
**Ловушка:** ноль среди цифр обнуляет всё — так и должно быть, но проверь, что не сломалось.

### G2. Количество цифр 🟢
**Ловушка:** у числа `0` одна цифра, а не ноль. Цикл `while (n > 0)` даст неверный ответ.

### G3. Перевернуть число 🟡
`1234` → `4321`.
**Тренирует:** накопление `res = res * 10 + цифра`.
**Ловушка:** отрицательные числа; и `1000` перевернётся в `1`, что правильно.
**⭐ Бонус:** заодно ответь, палиндром ли число, — не переписывая логику, а сравнив перевёрнутое с оригиналом.

### G4. Палиндром 🟢
Читается ли число одинаково в обе стороны.
**Тренирует:** переиспользование G3 — если написал функцией, здесь одна строка.

### G5. Максимальная и минимальная цифра 🟡
**Ловушка:** начальное значение минимума нельзя брать нулём — возьми `9` или первую цифру.

### G6. В двоичную систему 🔴
Перевести число в двоичную запись.
**Тренирует:** `% 2` и `/ 2`, вывод в обратном порядке.
**Ловушка:** цифры получаются с конца. Либо копи в `std::string` и разворачивай, либо используй рекурсию.

### G7. Из двоичной в десятичную 🟡
Ввести число вида `1011`, вывести `11`.
**Ловушка:** ввод содержит только `0` и `1` — проверь это.

### G8. Счастливый билет 🟡
Шестизначный номер: счастливый, если сумма первых трёх цифр равна сумме последних трёх.
**Тренирует:** извлечение групп цифр.
**Ловушка:** проверь, что число действительно шестизначное. `000123` при вводе станет `123`.

### G9. Сумма цифр до одной цифры 🟡
Складывать цифры, пока не останется одна: `9875 → 29 → 11 → 2`.
**Тренирует:** цикл вокруг цикла, переиспользование функции суммы цифр.

## Блок H. Даты

### H1. Номер дня в году 🟡
Ввести день, месяц, год → какой это день по счёту.
**Тренирует:** `switch` + високосность вместе.
**Ловушка:** февраль зависит от года. Функцию `isLeapYear` пиши один раз.

### H2. Корректна ли дата 🟡
Проверить, что дата существует.
**Ловушка:** `31.02` и `31.04` не существуют — нужны дни в месяце, а не просто `день <= 31`.

### H3. Следующий день 🔴
Ввести дату, вывести следующую.
**Ловушка:** три перехода подряд — конец месяца, конец года, `31.12` → `01.01` следующего. Обязательно проверь `28.02.2024` и `28.02.2023`.

### H4. Дней между датами 🔴
Две даты одного года → сколько дней между ними.
**Тренирует:** переиспользование H1 — разность номеров дней.
**Ловушка:** если даты введены в обратном порядке, ответ должен остаться положительным.

### H5. День недели по дате 🔴
Формула Зеллера.
**Тренирует:** аккуратная работа с `%` при отрицательных числах.
**Ловушка:** в C++ `-7 % 5` даёт `-2`, а формуле нужен неотрицательный остаток. Пиши `((x % 7) + 7) % 7`.

## Блок L. Найди баг

🐛 Не писать с нуля, а **читать чужой код** — навык, который отдельно почти не тренируют, а в работе он главный. Здесь код собирается (или почти), но работает не так. Задача: найти **на каком входе** он врёт и **почему**, а уже потом чинить. Все баги — из ловушек справочника ([11-oshibki](ref/11-oshibki.md), [12-lovim-bagi](ref/12-lovim-bagi.md)).

Смотри не на «где красиво», а на «что будет при `0`, пустом, отрицательном, огромном».

### L1. Сумма врёт на больших числах 🟡
```cpp
// Сумма 1 + 2 + ... + n. На n = 100000 выдаёт отрицательное число.
int sumTo(int n) {
  int sum = 0;
  for (int i = 1; i <= n; ++i)
    sum += i;
  return sum;
}
```
<details><summary>Разбор</summary>

Сумма до 100000 — это ~5 миллиардов, в `int` не влезает: **переполнение**. Тип суммы должен быть `long long` (`long long sum = 0;`). Раздел про [переполнение](ref/01-osnovy.md#2-типы-данных).
</details>

### L2. Зависает на пустом векторе 🔴
```cpp
// Печатает все элементы, кроме последнего. На пустом векторе крутится вечно.
void printExceptLast(const std::vector<int> &v) {
  for (std::size_t i = 0; i < v.size() - 1; ++i)
    std::cout << v[i] << " ";
}
```
<details><summary>Разбор</summary>

`v.size()` — беззнаковое. Для пустого вектора `v.size() - 1` — это не `-1`, а огромное число (`size_t` ушёл «в минус»). Цикл почти бесконечный и лезет за границы. Чини переносом: `i + 1 < v.size()`. Раздел про [`size_t`](ref/01-osnovy.md#2-типы-данных).
</details>

### L3. «5» печатает лишнее 🟢
```cpp
// По баллу 3–5 печатает словами. Но для 5 выводит "отлично хорошо".
void grade(int score) {
  switch (score) {
    case 5: std::cout << "отлично";
    case 4: std::cout << "хорошо"; break;
    case 3: std::cout << "удовлетворительно"; break;
  }
}
```
<details><summary>Разбор</summary>

После `case 5` нет `break` — управление **проваливается** в `case 4`. Добавь `break;` после «отлично». Раздел про [`switch`](ref/03-logika-cikly.md#switch--выбор-из-фиксированного-списка).
</details>

### L4. Средний балл всегда целый 🟢
```cpp
// Среднее по вектору. Для {5, 4, 4} выдаёт 4, а не 4.33.
double average(const std::vector<int> &v) {
  int sum = 0;
  for (int x : v)
    sum += x;
  return sum / v.size();
}
```
<details><summary>Разбор</summary>

`sum / v.size()` — деление двух целых: дробная часть отброшена (и заодно `int` со `size_t` — предупреждение). Приведи к дробному **обе** части: `static_cast<double>(sum) / static_cast<double>(v.size())`. Раздел про [целочисленное деление](ref/03-logika-cikly.md#5-арифметика-и-её-ловушки).
</details>

### L5. Максимум иногда огромный и отрицательный 🟡
```cpp
// Максимум вектора.
int maxOf(const std::vector<int> &v) {
  int best;
  for (int x : v)
    if (x > best)
      best = x;
  return best;
}
```
<details><summary>Разбор</summary>

`int best;` без значения — внутри **мусор**, и первое сравнение идёт с ним. Начинай с реального элемента: `int best = v[0];` (проверив, что вектор непуст), тогда и цикл — со второго. Раздел про [неинициализированные переменные](ref/01-osnovy.md#переменная-без-начального-значения-содержит-мусор).
</details>

### L6. Повторный ввод зависает на букве 🔴
```cpp
// Повторяет запрос, пока не введут число. На "abc" крутится вечно.
int readInt() {
  int n = 0;
  while (!(std::cin >> n)) {
    std::cin.clear();
    std::cout << "Повторите: ";
  }
  return n;
}
```
<details><summary>Разбор</summary>

`clear()` снимает флаг ошибки, но `abc` **остаётся в буфере** — следующий `>>` снова спотыкается о те же буквы. Не хватает `std::cin.ignore(...)` после `clear()`, чтобы выбросить плохой ввод. Раздел про [безопасное чтение](ref/02-vvod-vyvod.md#безопасное-чтение--держи-под-рукой).
</details>

## Блок M. Перепиши по-современному

🔧 Много кода в интернете и учебниках написано в старом стиле — он работает, но так **уже не пишут**. Узнавать его надо (его вокруг полно), а писать самому — нет. Задача: взять фрагмент и переписать на современный C++. Все замены — из [раздела 24 «Устаревшее»](ref/09-spravka.md#24-устаревшее-что-встретишь-в-учебниках-и-чем-это-заменить).

### M1. `using namespace std;` 🟢
```cpp
using namespace std;

int count = 0;               // конфликтует с std::count
cout << "введите: ";
cin >> count;
```
<details><summary>Как надо</summary>

Убрать `using namespace std;`, писать `std::` перед именами. Заодно исчезнет конфликт `count` с `std::count`:
```cpp
int count = 0;
std::cout << "введите: ";
std::cin >> count;
```
</details>

### M2. `new` / `delete` 🟡
```cpp
int n = 10;
int* arr = new int[n];       // выделили руками
for (int i = 0; i < n; ++i)
  arr[i] = i * i;
// ... сто строк ...
delete[] arr;                // забудешь — утечка
```
<details><summary>Как надо</summary>

`std::vector` — память сама, освобождение само:
```cpp
std::vector<int> arr(n);
for (int i = 0; i < n; ++i)
  arr[i] = i * i;
// освободится на выходе из области видимости
```
</details>

### M3. `#define` и C-style cast 🟢
```cpp
#define SIZE 10              // препроцессор, не знает типов

double avg = (double)sum / SIZE;   // C-style cast
```
<details><summary>Как надо</summary>

`const` вместо `#define`, `static_cast` вместо `(тип)`:
```cpp
const int SIZE = 10;
double avg = static_cast<double>(sum) / SIZE;
```
</details>

### M4. `rand() % 6` 🟡
```cpp
srand(time(0));
int dice = rand() % 6 + 1;   // распределение слегка неравномерное
```
<details><summary>Как надо</summary>

Генератор из `<random>` с равномерным распределением:
```cpp
std::random_device rd;
std::mt19937 gen(rd());
std::uniform_int_distribution<int> dice(1, 6);
int roll = dice(gen);
```
</details>

### M5. `typedef` и `printf` 🟡
```cpp
typedef long long ll;
ll x = 5;
printf("x = %lld\n", x);     // формат не проверяется по-настоящему
```
<details><summary>Как надо</summary>

`using` читается слева направо, `std::format`/`cout` проверяет типы:
```cpp
using ll = long long;
ll x = 5;
std::cout << std::format("x = {}\n", x);   // или std::cout << "x = " << x << "\n";
```
</details>

## Если застрял

Порядок действий, прежде чем спрашивать:

1. **Прочитал сообщение компилятора целиком?** Первую ошибку, не последнюю.
2. **Поставил `F9` и посмотрел значения в панели Variables?** Половина «непонятных» багов видна за десять секунд.
3. **Вывел промежуточные значения?** `cout << "dx = " << dx << "\n";` — грубо, но работает.
4. **Проверил на самом простом входе?** Не на `12345`, а на `5`.

Не помогло — спрашивай, но так, чтобы осталось чему научиться:

> «Вот задача D3 и мой код. Не переписывай — скажи, на каком входе он ломается и почему.»

Правило вопроса: показывай свой код и проси объяснить причину, а не прислать готовый ответ. Иначе научится тот, кто отвечает.
