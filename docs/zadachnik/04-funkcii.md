# Тема 4. Функции

Функция — это способ дать куску кода имя и переиспользовать его. С этого момента
ваши программы перестают быть «простынёй» в `main` и начинают читаться как план:
«прочитай число → проверь простоту → посчитай». Здесь же — ссылки (изменить
переменную снаружи), возврат нескольких значений и рекурсия.

> **Теория темы.** Опирается на раздел 9 справочника ([открыть теорию](../ref/04-funkcii.md)).
> Там про параметры, передачу по значению и по ссылке, лямбды и `std::optional`.

> **В целой программе.** «Калькулятор» (`../examples/01-kalkulyator.md`) — как задача
> разбита на функции, меню и `switch`.

## Чему вы здесь научитесь

- Выносить логику в функцию с осмысленной сигнатурой (`bool isPrime(int x)`).
- Понимать разницу «по значению» (копия) и «по ссылке» (`&`, сама переменная).
- Возвращать из функции сразу несколько значений через параметры-ссылки.
- Писать рекурсию с обязательным условием остановки.

## Где это пригодится

Ни одна программа больше пары экранов не живёт без функций. Функция — это единица
переиспользования и тестирования: написали `isPrime` один раз — используете везде.
Ссылки лежат в основе того, как C++ передаёт большие объекты без копирования (это
важно для скорости). Рекурсия — естественный язык для деревьев, файловых систем,
разбора выражений.

## 4.1. Факториал функцией 🟢

*Ваша первая функция: даём куску кода имя и зовём его из `main`. Остаётся решить, в какой тип поместится ответ.*

Напишите функцию `factorial(n)`, которая возвращает произведение всех чисел от 1 до
`n`, и используйте её в `main`.

**Формат ввода.** Одно целое число `n` (0 ≤ n ≤ 20). Считаем, что `0! = 1`.

**Формат вывода.** Значение `n!`.

**Пример:**
```
Ввод
5
Вывод
120
```

- **Тренирует:** объявление функции с возвращаемым значением и выбор типа результата.
- **Где пригодится:** комбинаторика (число сочетаний), вероятности, любая формула, которую хочется вызвать по имени.

> **Как подступиться.** Заведите накопитель `= 1` (не 0!) и умножайте в цикле. Ответ большой — подумайте про тип.

> **Выбор типа.** До 20! — снова про выбор типа возвращаемого значения.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# обычные
5 => 120
2 => 2
# края
0 => 1
20 => 2432902008176640000
```

```hints
Идея: Произведение копят так же, как сумму, только старт у копилки — не ноль. И подумайте, какое число получится при `n = 20`: влезет ли оно в `int`?
План: Функция принимает `n`, заводит копилку, в цикле от 2 до `n` умножает её на счётчик и возвращает. `main` только читает `n` и печатает результат вызова.
Ключ: `long long result = 1; for (int i = 2; i <= n; ++i) result *= i;`
```

## 4.2. Обмен по ссылке 🟡

*Хотите, чтобы функция поменяла сами переменные, а не их копии? Дайте ей ссылку — и `swap` заработает по-настоящему.*

Напишите функцию `swapValues`, которая принимает две переменные **по ссылке** и
меняет их значения местами. В `main` прочитайте два числа, вызовите функцию и
напечатайте их после обмена.

**Формат ввода.** Два целых числа через пробел.

**Формат вывода.** Те же два числа в обратном порядке.

**Пример:**
```
Ввод
3 8
Вывод
8 3
```

- **Тренирует:** передачу по ссылке (`int &a`) — изменение переменной вызывающего кода.
- **Где пригодится:** любая функция, которая должна **менять** переданные данные (сортировки, обновление состояния), а не возвращать копию.

> **Как подступиться.** Сначала напишите **без** `&` и убедитесь своими глазами, что в `main` ничего не изменилось — это и есть смысл упражнения.

> **По значению или по ссылке.** Если функция принимает по значению (`int a, int b`), она поменяет местами копии, а в `main` ничего не изменится. Ссылка (`int &a, int &b`) — то, что нужно.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# равные числа; отрицательное
3 7 => 7 3
5 5 => 5 5
-1 9 => 9 -1
```

```hints
Идея: Функция получает не числа, а «таблички» с самими переменными из `main`. Обмен двух значений всегда требует третьего — временного места.
План: Параметры объявите ссылками; внутри сохраните первое во временную переменную, первому дайте второе, второму — сохранённое. В `main` вызов пишется как обычно.
Ключ: `void swapValues(int &a, int &b) { int t = a; a = b; b = t; }`
```

## 4.3. Минимум и максимум сразу 🟡

*Что, если ответов сразу два — и минимум, и максимум? Тогда их удобно вернуть через параметры-ссылки.*

Напишите функцию, которая по массиву чисел находит **и** минимум, **и** максимум.
Так как значений два, верните их через параметры-ссылки. Даны `N` чисел.

**Формат ввода.** `N` (1 ≤ N ≤ 1000), затем `N` целых чисел.

**Формат вывода.** Два числа через пробел: минимум и максимум.

**Пример:**
```
Ввод
5
4 -1 7 3 7
Вывод
-1 7
```

- **Тренирует:** возврат нескольких значений из одной функции через ссылки.
- **Где пригодится:** когда результат — это пара/тройка величин (границы диапазона, координаты, «сколько и на какой позиции»).

> **Как подступиться.** Инициализируйте `mn` и `mx` **первым элементом**, а не нулём — иначе на одних отрицательных ошибётесь.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# одно число; отрицательные
5 3 1 4 1 5 => 1 5
1 42 => 42 42
3 -2 -9 -1 => -9 -1
```

```hints
Идея: Ответов два, а `return` один — пусть функция положит результаты в переменные вызывающего. Стартовать надо с настоящего элемента, а не с «удобного» нуля.
План: Прочитайте числа в вектор. Функция берёт вектор по `const &`, а `mn` и `mx` по ссылке; оба начинает с `v[0]` и за один проход обновляет.
Ключ: `void minMax(const std::vector<int> &v, int &mn, int &mx)`
```

## 4.4. НОД рекурсией 🔴

*Рекурсия — это «сведи задачу к такой же, но поменьше». Евклид именно так и ищет НОД: `gcd(a, b) = gcd(b, a % b)`.*

Напишите **рекурсивную** функцию, вычисляющую наибольший общий делитель двух чисел
по алгоритму Евклида: `gcd(a, b) = gcd(b, a % b)`, а `gcd(a, 0) = a`.

**Формат ввода.** Два целых положительных числа через пробел, каждое до 10^9.

**Формат вывода.** Их наибольший общий делитель.

**Пример:**
```
Ввод
48 36
Вывод
12
```

- **Тренирует:** рекурсию — функция вызывает сама себя, с условием остановки.
- **Где пригодится:** сокращение дробей, работа с ритмами и периодами; сам приём «свести задачу к меньшей такой же» — фундамент рекурсии.

> **Как подступиться.** Условие остановки (`b == 0`) должно стоять **до** рекурсивного вызова. `b` уменьшается каждый шаг, поэтому рекурсия конечна.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# взаимно простые дают 1; большие числа
12 18 => 6
17 5 => 1
1000000000 8 => 8
```

```hints
Идея: НОД не меняется, если большее число заменить остатком от деления на меньшее. Когда второе число стало нулём — первое и есть ответ.
План: Сначала база: если `b == 0`, вернуть `a`. Иначе вернуть результат той же функции для пары `(b, a % b)`. Рекурсия конечна, потому что `b` каждый раз уменьшается.
Ключ: `return b == 0 ? a : gcd(b, a % b);`
```

> Не выходит и с подсказками? Решение с разбором — [внизу страницы](#решения-с-разбором). Открывай его, только когда правда застрял.

## 4.5. Сколько простых в отрезке 🟡

*Главный приём всего программирования: спрятать сложное в функцию, чтобы `main` читался почти словами.*

Напишите функцию `bool isPrime(int x)`, а затем в `main` посчитайте, сколько простых
чисел лежит в отрезке `[a, b]` включительно, вызывая эту функцию.

**Формат ввода.** Два целых числа `a` и `b` (2 ≤ a ≤ b ≤ 100000) через пробел.

**Формат вывода.** Количество простых чисел в отрезке.

**Пример:**
```
Ввод
10 20
Вывод
4
```

- **Тренирует:** разбиение задачи — маленькая функция делает `main` коротким и понятным.
- **Где пригодится:** это главный приём программирования вообще — «спрятать сложное в функцию, чтобы главный код читался словами».

> **Как подступиться.** Сначала напишите `isPrime`, потом в `main` — простой цикл со счётчиком, который её вызывает.

> **Разбор примера.** Простые в [10, 20]: 11, 13, 17, 19 — четыре штуки. Задача не про новый алгоритм, а про то, как одна маленькая функция делает `main` коротким и понятным.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# границы отрезка включаются
2 10 => 4
10 20 => 4
2 2 => 1
```

```hints
Идея: Раздели работу: одна функция отвечает «простое ли число», а `main` только перебирает отрезок и считает «да». Делители дальше корня проверять незачем.
План: `isPrime`: числа меньше 2 — не простые; перебирайте делители `i`, пока `i * i <= x`; нашли делитель — `false`. В `main` пройдите `k` от `a` до `b` и увеличивайте счётчик.
Ключ: `for (int i = 2; i * i <= x; ++i) if (x % i == 0) return false;`
```

## 4.6. Совершенное число? 🟡

*Дайте проверке говорящее имя — `isPerfect` — и код станет самоочевидным. Внутри она сама переберёт делители.*

Число называют совершенным, если оно равно сумме своих делителей, меньших его самого
(например, `6 = 1 + 2 + 3`). Напишите функцию `bool isPerfect(int n)` и в `main`
напечатайте `YES` или `NO`.

**Формат ввода.** Одно целое число `n` (1 ≤ n ≤ 100000).

**Формат вывода.** `YES`, если число совершенное, иначе `NO`.

**Пример 1:**
```
Ввод
28
Вывод
YES
```
**Пример 2:**
```
Ввод
10
Вывод
NO
```

- **Тренирует:** проектирование функции-предиката, которая внутри сама перебирает делители.
- **Где пригодится:** любой критерий-проверка (`isValid`, `isAvailable`, `isPerfect`) — читаемый `main` строится из таких функций.

> **Как подступиться.** Внутри функции сложите делители от 1 до `n/2` (или до `√n` парами) и сравните сумму с `n`. Единицу к совершенным не относят.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# 6 и 28 совершенные; 12 и 1 — нет
6 => YES
28 => YES
12 => NO
1 => NO
```

```hints
Идея: Совершенное — значит, сумма делителей, меньших самого числа, равна ему. Больше половины числа делителей (кроме него самого) не бывает.
План: Функция заводит сумму, перебирает `d` от 1 до `n / 2`, прибавляет делящие нацело и возвращает сравнение суммы с `n`. Единица сама собой даст сумму 0 — не совершенна.
Ключ: `for (int d = 1; d <= n / 2; ++d) if (n % d == 0) sum += d;`
```

## 4.7. Високосный год — функцией 🟡

*Правило с исключениями (400, но не 100…) легко забыть. Соберите его один раз в `isLeapYear` — и зовите где угодно.*

Напишите функцию `bool isLeapYear(int year)`. Год високосный, если делится на 4, но
не на 100 — кроме годов, кратных 400 (они високосные). Прочитайте год и напечатайте
`YES` или `NO`.

**Формат ввода.** Одно целое число — год.

**Формат вывода.** `YES`, если год високосный, иначе `NO`.

**Пример 1:**
```
Ввод
2000
Вывод
YES
```
**Пример 2:**
```
Ввод
1900
Вывод
NO
```

- **Тренирует:** упаковку непростого логического условия в функцию с говорящим именем.
- **Где пригодится:** календари, даты, финансовые периоды — `isLeapYear` пишут один раз и зовут везде.

> **Как подступиться.** Всё правило умещается в одно выражение с `&&`, `||` и остатками.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# 1900 не високосный, 2000 — да (кратен 400)
2000 => YES
1900 => NO
2024 => YES
2023 => NO
```

```hints
Идея: Правило из трёх частей: «делится на 4», «но не на 100», «кроме кратных 400». Его можно записать одним логическим выражением.
План: Соберите условие из двух веток через `||`: первая — «на 4 и не на 100», вторая — «на 400». Функция просто возвращает это выражение; проверьте на 2000, 1900, 2024.
Ключ: `return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;`
```

## 4.8. Степень рекурсией 🔴

*Степень через саму себя: `base^exp` — это `base`, умноженное на `base^(exp−1)`. Осталось не забыть, где рекурсия остановится.*

Напишите **рекурсивную** функцию `long long power(int base, int exp)`, возвращающую
`base` в степени `exp` (считаем `exp ≥ 0`, а `base^0 = 1`).

**Формат ввода.** Два целых числа: `base` и `exp` (0 ≤ exp ≤ 62) через пробел.

**Формат вывода.** Значение `base` в степени `exp`.

**Пример:**
```
Ввод
2 10
Вывод
1024
```

- **Тренирует:** рекурсию с базовым случаем и уменьшающимся параметром.
- **Где пригодится:** рекурсия — язык деревьев, разбора выражений, «раздели и властвуй».

> **Как подступиться.** Базовый случай `exp == 0` возвращает `1`; иначе `base` умножить на `power(base, exp − 1)`.

> **Бонус.** Сделайте «быстрое возведение»: при чётном `exp` считайте `power(base, exp/2)` один раз и возведите в квадрат — так шагов станет не `exp`, а `log₂(exp)`.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
# степень 0 равна 1; 2^62 у границы long long
2 10 => 1024
5 0 => 1
2 62 => 4611686018427387904
```

```hints
Идея: Степень выражается через степень на единицу меньше: `base^exp = base · base^(exp−1)`. Нужна точка, где рекурсия остановится, и тип, в который влезет `2^62`.
План: Первой строкой — база: `exp == 0` возвращает 1. Иначе умножьте `base` на вызов той же функции с `exp - 1`. Возвращаемый тип — `long long`.
Ключ: `if (exp == 0) return 1; return base * power(base, exp - 1);`
```

> Не выходит и с подсказками? Решение с разбором — [внизу страницы](#решения-с-разбором). Открывай его, только когда правда застрял.

## 4.9. Урон по формуле 🔗🟡

*Первое звено цепочки «Журнал забегов»: формулу урона пишем один раз — дальше она пригодится в темах 5–8.*

Герой бьёт монстра. Базовый урон — `атака − защита`, но не меньше `1`. Бросок кубика `roll`
(от 1 до 20) меняет исход: `20`, `19` или `18` — **крит**, урон удваивается; `1` — **промах**, урон `0`.
Напишите функции `int baseDamage(int atk, int def)`, `bool isCrit(int roll)` и
`int damage(int atk, int def, int roll)`, которая собирает их вместе.

**Формат ввода.** Три целых числа: `atk def roll`.

**Формат вывода.** Итоговый урон.

**Пример:**
```
Ввод
10 3 18
Вывод
14
```

- **Тренирует:** разбиение правила на маленькие функции и их сборку (темы 3–4 вместе).
- **Где пригодится:** игровая логика, скидки и налоги — любое правило «база + модификаторы» пишут функциями, а не одной формулой.

> **Как подступиться.** Сначала `baseDamage` с `std::max`, потом `isCrit`, и только потом `damage`, которая решает про промах и крит.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests

10 3 18 => 14
2 5 20 => 2
10 3 1 => 0
5 5 17 => 1
7 2 19 => 10
```

```hints
Идея: Разложите правило на три вопроса: какой урон без кубика, крит ли это, промах ли это. Каждый вопрос — своя маленькая функция.
План: `baseDamage` возвращает большее из `atk − def` и `1`; `isCrit` — истину для 18..20. `damage`: промах — вернуть 0; иначе база, при крите — вдвое больше.
```

## 4.10. Степень по модулю 🔥

*Челлендж темы: показатель до 10¹⁸ — простая рекурсия из 4.8 не закончится никогда. Нужна быстрая.*

Даны `base`, `exp` и `mod`. Напечатайте остаток от деления `base^exp` на `mod`.
Показатель огромный — до `10^18`, поэтому умножать `exp` раз нельзя.

**Формат ввода.** Три целых числа: `base exp mod` (0 ≤ base ≤ 10^9, 0 ≤ exp ≤ 10^18, 1 ≤ mod ≤ 10^9).

**Формат вывода.** `base^exp mod mod`.

**Пример:**
```
Ввод
2 10 1000
Вывод
24
```

- **Тренирует:** быструю рекурсию «пополам» и контроль переполнения (`long long`, остаток на каждом шаге).
- **Где пригодится:** криптография (RSA), хэши, «номер ячейки по кругу», любые счёты «по модулю» с большими степенями.

> **Как подступиться.** `base^exp = (base^(exp/2))²`, и ещё раз `· base`, если `exp` нечётный. Остаток берите после каждого умножения — тогда числа не вырастут больше `mod²`.

Написал решение — прогони его на этих входах (нажми «копировать», вставь в программу), особенно на краях:

```tests
2 10 1000 => 24
3 1000000000000000000 1000000007 => 246336683
5 0 7 => 1
7 13 1 => 0
10 18 1000000007 => 49
0 0 5 => 1
```

```hints
Идея: Показатель можно делить пополам: степень от `exp` — это квадрат степени от `exp/2` (и ещё один множитель для нечётного). Шагов станет около 60, а не 10¹⁸.
План: База рекурсии: `exp == 0` → `1 % mod`. Иначе посчитайте половину, возведите в квадрат по модулю; если `exp` нечётный — умножьте ещё на `base % mod`. Все произведения — в `long long`.
Ключ: `long long h = powMod(base, exp / 2, mod); long long r = h * h % mod;`
```

<summary>Полное решение 4.1 — Факториал функцией</summary>

Ход мысли по шагам:

1. Выношу подсчёт в отдельную функцию `factorial` — так `main` читается словами.
2. Результат может быть огромным (20! ≈ 2·10¹⁸), поэтому тип — `long long`.
3. Накопитель начинаю с `1` (не с нуля — умножение на ноль всё обнулит). Для `n = 0` цикл не выполнится и вернётся `1` — как и надо (`0! = 1`).

```cpp
#include <iostream>

long long factorial(int n) {
    long long result = 1;
    for (int i = 2; i <= n; ++i)
        result *= i;
    return result;
}

int main() {
    int n = 0;
    std::cin >> n;
    std::cout << factorial(n) << "\n";
    return 0;
}
```


**Другой подход — рекурсия**

```cpp
#include <iostream>

long long factorial(int n) {
    if (n <= 1) return 1;              // база: 0! = 1! = 1
    return n * factorial(n - 1);       // n! = n · (n−1)!
}

int main() {
    int n = 0;
    std::cin >> n;
    std::cout << factorial(n) << "\n";
    return 0;
}
```

> **Сравнение.** Рекурсия повторяет математическое определение `n! = n · (n−1)!` буква в букву. Цикл делает то же без вложенных вызовов — для факториала он проще и не расходует стек. Рекурсию стоит держать в голове для задач, где она естественна: деревья, «раздели и властвуй» (тема 4.4, 4.8).
</details>

<summary>Полное решение 4.2 — Обмен по ссылке</summary>

Ход мысли по шагам:

1. Параметры беру **по ссылке** (`int &a, int &b`) — тогда функция меняет сами переменные, а не копии.
2. Обмен через временную: `t = a; a = b; b = t;`.
3. В `main` вызываю `swapValues(x, y)` — без всяких `&` в месте вызова.

```cpp
#include <iostream>

void swapValues(int &a, int &b) {   // & — работаем с самими переменными
    int t = a;
    a = b;
    b = t;
}

int main() {
    int x = 0, y = 0;
    std::cin >> x >> y;
    swapValues(x, y);
    std::cout << x << " " << y << "\n";
    return 0;
}
```


**Другой подход — `std::swap` из стандартной библиотеки**

```cpp
#include <iostream>
#include <utility>

void swapValues(int &a, int &b) {
    std::swap(a, b);                   // готовый обмен — тоже через ссылки
}

int main() {
    int x = 0, y = 0;
    std::cin >> x >> y;
    swapValues(x, y);
    std::cout << x << " " << y << "\n";
    return 0;
}
```

> **Сравнение.** В реальном коде пишут `std::swap(x, y)` — функция из `<utility>` принимает ссылки ровно как ваша. Своя версия нужна, чтобы увидеть, **почему** без `&` обмен не работает; дальше пользуйтесь готовой: она умеет обменивать и строки, и векторы (быстро, без копирования).
</details>

<summary>Полное решение 4.3 — Минимум и максимум сразу</summary>

Ход мысли по шагам:

1. Читаю числа в `vector`.
2. Ответов два, поэтому возвращаю их через параметры-ссылки `int &mn, int &mx`.
3. Инициализирую `mn` и `mx` **первым** элементом (`v[0]`), а не нулём — иначе на одних отрицательных ошибусь.

```cpp
#include <iostream>
#include <vector>

void minMax(const std::vector<int> &v, int &mn, int &mx) {
    mn = v[0];                 // старт — с первого элемента
    mx = v[0];
    for (int x : v) {
        if (x < mn) mn = x;
        if (x > mx) mx = x;
    }
}

int main() {
    int n = 0;
    std::cin >> n;
    std::vector<int> v;
    for (int i = 0; i < n; ++i) {
        int x = 0;
        std::cin >> x;
        v.push_back(x);
    }

    int mn = 0, mx = 0;
    minMax(v, mn, mx);
    std::cout << mn << " " << mx << "\n";
    return 0;
}
```


**Другой подход — вернуть пару вместо параметров-ссылок**

```cpp
#include <iostream>
#include <utility>
#include <vector>

std::pair<int, int> minMax(const std::vector<int> &v) {
    int mn = v[0], mx = v[0];
    for (int x : v) {
        if (x < mn) mn = x;
        if (x > mx) mx = x;
    }
    return {mn, mx};                   // два значения — одним возвратом
}

int main() {
    int n = 0;
    std::cin >> n;
    std::vector<int> v(n);
    for (int &x : v) std::cin >> x;
    auto [mn, mx] = minMax(v);         // разбираем пару по именам
    std::cout << mn << " " << mx << "\n";
    return 0;
}
```

> **Сравнение.** Возврат пары читается честнее: видно, что функция **выдаёт** результат, а не меняет что-то снаружи. Параметры-ссылки удобны, когда значений много или функция дополняет уже существующие переменные. В современном C++ для 2–3 значений чаще выбирают `pair`/`struct` и «распаковку» `auto [a, b]`.
</details>

<summary>Полное решение 4.4 — НОД рекурсией</summary>

Ход мысли по шагам:

1. Условие остановки — **до** рекурсивного вызова: `if (b == 0) return a;`.
2. Иначе свожу задачу к меньшей: `gcd(b, a % b)`.
3. `b` каждый шаг уменьшается, поэтому рекурсия конечна. Числа до 10⁹ держу в `long long` про запас.

```cpp
#include <iostream>

long long gcd(long long a, long long b) {
    if (b == 0) return a;          // база — до рекурсивного вызова
    return gcd(b, a % b);          // задача сводится к меньшей такой же
}

int main() {
    long long a = 0, b = 0;
    std::cin >> a >> b;
    std::cout << gcd(a, b) << "\n";
    return 0;
}
```


**Другой подход — цикл вместо рекурсии (и `std::gcd`)**

```cpp
#include <iostream>

long long gcd(long long a, long long b) {
    while (b != 0) {                   // та же идея Евклида, но циклом
        long long r = a % b;
        a = b;
        b = r;
    }
    return a;
}

int main() {
    long long a = 0, b = 0;
    std::cin >> a >> b;
    std::cout << gcd(a, b) << "\n";
    return 0;
}
```

> **Сравнение.** Цикл делает ровно те же шаги, что рекурсия, — рекурсия здесь «хвостовая» и легко разворачивается. Цикл не тратит стек и понятен тем, кто рекурсию ещё побаивается; рекурсия короче и ближе к формуле. А в настоящем коде есть готовый `std::gcd(a, b)` из `<numeric>` (C++17).
</details>

<summary>Полное решение 4.5 — Сколько простых в отрезке</summary>

Ход мысли по шагам:

1. Сначала пишу маленькую функцию `bool isPrime(int x)` — проверку простоты.
2. В `main` остаётся простой цикл по `[a, b]` со счётчиком, который её зовёт.
3. Так `main` читается словами: «пройди по отрезку и посчитай простые», а «как проверить» спрятано в функцию.

```cpp
#include <iostream>

bool isPrime(int x) {
    if (x < 2) return false;
    for (int i = 2; i * i <= x; ++i)
        if (x % i == 0) return false;
    return true;
}

int main() {
    int a = 0, b = 0;
    std::cin >> a >> b;

    int count = 0;
    for (int k = a; k <= b; ++k)
        if (isPrime(k)) ++count;

    std::cout << count << "\n";
    return 0;
}
```


**Другой подход — решето Эратосфена**

```cpp
#include <iostream>
#include <vector>

int main() {
    int a = 0, b = 0;
    std::cin >> a >> b;

    std::vector<bool> prime(b + 1, true);    // prime[k] — простое ли k
    prime[0] = false;
    if (b >= 1) prime[1] = false;
    for (int i = 2; i * i <= b; ++i)
        if (prime[i])
            for (int j = i * i; j <= b; j += i)
                prime[j] = false;            // вычёркиваем кратные i

    int count = 0;
    for (int k = a; k <= b; ++k)
        if (prime[k]) ++count;
    std::cout << count << "\n";
    return 0;
}
```

> **Сравнение.** Решето не проверяет каждое число отдельно, а за один раз вычёркивает все составные до `b`. Для отрезка до 100 000 оба способа мгновенны, но на миллионах чисел решето быстрее в десятки раз. Зато `isPrime` проще и работает для одного огромного числа, где решето не поместится в память.
</details>

<summary>Полное решение 4.6 — Совершенное число</summary>

Ход мысли по шагам:

1. Проверку упаковываю в `bool isPerfect(int n)`.
2. Внутри складываю делители от 1 до `n/2` и сравниваю сумму с `n`.
3. Возвращаю `sum == n`. Для единицы сумма делителей — `0`, а `0 != 1`, поэтому она не совершенна.

```cpp
#include <iostream>

bool isPerfect(int n) {
    int sum = 0;
    for (int d = 1; d <= n / 2; ++d)
        if (n % d == 0) sum += d;
    return sum == n;
}

int main() {
    int n = 0;
    std::cin >> n;
    std::cout << (isPerfect(n) ? "YES" : "NO") << "\n";
    return 0;
}
```


**Другой подход — делители парами до √n**

```cpp
#include <iostream>

bool isPerfect(int n) {
    if (n < 2) return false;
    int sum = 1;                             // 1 — делитель любого n > 1
    for (int d = 2; d * d <= n; ++d) {
        if (n % d == 0) {
            sum += d;
            int pair = n / d;                // делители ходят парами: d и n/d
            if (pair != d) sum += pair;
        }
    }
    return sum == n;
}

int main() {
    int n = 0;
    std::cin >> n;
    std::cout << (isPerfect(n) ? "YES" : "NO") << "\n";
    return 0;
}
```

> **Сравнение.** Каждый делитель `d` меньше корня даёт парный `n / d` больше корня — поэтому хватит перебора до `√n`. Для `n = 100000` это ~316 шагов вместо 50 000. Цена — аккуратность: не добавить квадратный корень дважды и не посчитать само `n`. Простой перебор до `n/2` труднее испортить.
</details>

<summary>Полное решение 4.8 — Степень рекурсией</summary>

Ход мысли по шагам:

1. Базовый случай **до** рекурсии: `if (exp == 0) return 1;`.
2. Шаг: `base * power(base, exp − 1)` — `exp` убывает и дойдёт до нуля.
3. Возвращаемый тип `long long`: `2⁶²` в `int` не поместится.

```cpp
#include <iostream>

long long power(int base, int exp) {
    if (exp == 0) return 1;                  // база
    return base * power(base, exp - 1);      // шаг: exp убывает
}

int main() {
    int base = 0, exp = 0;
    std::cin >> base >> exp;
    std::cout << power(base, exp) << "\n";
    return 0;
}
```


**Другой подход — быстрое возведение: половина шагов на каждом уровне**

```cpp
#include <iostream>

long long power(int base, int exp) {
    if (exp == 0) return 1;
    long long half = power(base, exp / 2);   // один вызов на половину степени
    if (exp % 2 == 0) return half * half;
    return half * half * base;
}

int main() {
    int base = 0, exp = 0;
    std::cin >> base >> exp;
    std::cout << power(base, exp) << "\n";
    return 0;
}
```

> **Сравнение.** Простая рекурсия делает `exp` вызовов, быстрая — около `log₂(exp)`: для степени 62 это 6 уровней вместо 62. Здесь разница незаметна, но тот же приём считает степени по модулю для огромных `exp` (см. задачу-челлендж 4.10) — там простой способ не успеет никогда.
</details>

<details>
<summary>Полное решение 4.9 — Урон по формуле</summary>

Правило «база + модификаторы» разбито на функции — каждую легко проверить отдельно, а `damage` читается как само правило.

```cpp
#include <algorithm>
#include <iostream>

int baseDamage(int atk, int def) {
    return std::max(1, atk - def);          // не меньше 1: иначе бой вечный
}

bool isCrit(int roll) {
    return roll >= 18;                      // 18, 19, 20
}

int damage(int atk, int def, int roll) {
    if (roll == 1) return 0;                // промах важнее всего — проверяем первым
    int d = baseDamage(atk, def);
    return isCrit(roll) ? d * 2 : d;
}

int main() {
    int atk = 0, def = 0, roll = 0;
    std::cin >> atk >> def >> roll;
    std::cout << damage(atk, def, roll) << "\n";
    return 0;
}
```

**Другой подход — всё одним выражением**

```cpp
#include <iostream>

int main() {
    int atk = 0, def = 0, roll = 0;
    std::cin >> atk >> def >> roll;
    int base = atk - def > 1 ? atk - def : 1;
    std::cout << (roll == 1 ? 0 : (roll >= 18 ? base * 2 : base)) << "\n";
    return 0;
}
```

> **Сравнение.** Одно выражение короче, но правило в нём уже не прочитать: где крит, где промах, почему `1`. Функции с именами можно проверить по отдельности и переиспользовать — в 5.9 `damage` понадобится снова.
</details>

<details>
<summary>Полное решение 4.10 — Степень по модулю</summary>

Быстрое возведение делает около `log₂(exp)` шагов: для `10^18` — 60. Остаток берём после каждого умножения: оба множителя меньше `10^9`, произведение меньше `10^18` — влезает в `long long`. `1 % mod` в базе нужен для `mod = 1`.

```cpp
#include <iostream>

long long powMod(long long base, long long exp, long long mod) {
    if (exp == 0) return 1 % mod;                  // mod = 1 → ответ 0
    long long half = powMod(base, exp / 2, mod);
    long long r = half * half % mod;               // < 10^9 · 10^9 = 10^18 — влезает
    if (exp % 2 == 1) r = r * (base % mod) % mod;
    return r;
}

int main() {
    long long base = 0, exp = 0, mod = 1;
    std::cin >> base >> exp >> mod;
    std::cout << powMod(base, exp, mod) << "\n";
    return 0;
}
```

**Другой подход — цикл по битам показателя**

```cpp
#include <iostream>

int main() {
    long long base = 0, exp = 0, mod = 1;
    std::cin >> base >> exp >> mod;
    long long result = 1 % mod, b = base % mod;
    while (exp > 0) {
        if (exp & 1) result = result * b % mod;    // бит показателя равен 1 — берём текущую степень
        b = b * b % mod;                           // b, b², b⁴, b⁸…
        exp >>= 1;
    }
    std::cout << result << "\n";
    return 0;
}
```

> **Сравнение.** Цикл делает то же, но идёт по двоичным разрядам показателя и не расходует стек. Рекурсию легче вывести из формулы, цикл — классическая форма, которую вы встретите в библиотеках.
