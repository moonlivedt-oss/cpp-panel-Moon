# Тема 9. Ловим баги

Здесь программы уже написаны, но **работают неправильно**. Задача — найти
ошибку, объяснить её себе и исправить. Это самый полезный навык: чужой (и свой)
код чаще приходится чинить, чем писать с нуля. Каждая ошибка тут — представитель
целого класса багов, которые ты будешь узнавать в лицо всю дальнейшую практику.

> 📖 **Опирается на разделы 11–12 справочника** (`../ref/11-oshibki.md` и `12-lovim-bagi.md`).
> Там метод поиска багов и разбор частых сообщений компилятора.

## Чему ты здесь научишься

- Узнавать в лицо пять классов багов: целочисленное деление, `=` вместо `==`,
  выход за границу массива, неверная инициализация, забытый `break`.
- Не «чинить наугад», а сначала **понять**, почему ломается.
- Проверять гипотезу на минимальном входе.

## Метод: как искать баг (а не гадать)

1. **Прочитай, что программа должна делать**, и найди вход, на котором она врёт.
2. **Сформулируй гипотезу**: «мне кажется, дело вот в этой строке, потому что…».
3. **Проверь гипотезу**: поставь точку останова (`F9`) и посмотри значения в
   панели Variables, либо выведи промежуточное `std::cout << "x = " << x << "\n";`.
4. **Почини и перепроверь** — на том же входе, где ломалось, и на паре соседних.

Не переписывай программу целиком — найди **одну** строку-виновника. Умение сузить
проблему до одной строки важнее, чем умение написать заново.

**Как работать с блоком:** сначала честно найди баг сам (по 10–15 минут на задачу),
запиши свою гипотезу, и только потом открывай подсказку — сверить.

## 9.1. Среднее двух чисел 🟡

Программа должна печатать среднее арифметическое двух целых чисел, но для `3` и `4`
печатает `3` вместо `3.5`.

```cpp
#include <iostream>

int main() {
  int a, b;
  std::cin >> a >> b;
  double avg = (a + b) / 2;
  std::cout << avg << "\n";
}
```

**Пример:** ввод `3 4` — ожидается `3.5`.

**Класс бага:** целочисленное деление. Результат посчитан в `int` **до** того, как попал в `double`.
**Где кусается:** средний балл, средняя цена, проценты — везде, где ждёшь дробь, а получаешь целое.

---

## 9.2. Ноль или нет 🟡

Программа должна печатать `ZERO`, если ввели ноль, и `NOT ZERO` иначе. Но она
**всегда** печатает `NOT ZERO`, даже на вводе `0`.

```cpp
#include <iostream>

int main() {
  int x;
  std::cin >> x;
  if (x = 0) {
    std::cout << "ZERO\n";
  } else {
    std::cout << "NOT ZERO\n";
  }
}
```

**Пример:** ввод `0` — ожидается `ZERO`.

**Класс бага:** `=` (присваивание) вместо `==` (сравнение) — одна из самых частых опечаток.
**Где кусается:** любое условие. Компилятор с `-Wall` обычно предупреждает — научись читать это предупреждение.

## 9.3. Сумма массива 🟡

Программа читает `N` чисел и должна печатать их сумму. Вместо этого она то падает,
то печатает мусор (лишнее «случайное» слагаемое).

```cpp
#include <iostream>
#include <vector>

int main() {
  int n;
  std::cin >> n;
  std::vector<int> v(n);
  for (int i = 0; i < n; ++i) {
    std::cin >> v[i];
  }
  long long sum = 0;
  for (int i = 0; i <= n; ++i) {
    sum += v[i];
  }
  std::cout << sum << "\n";
}
```

**Пример:** ввод `3` и `1 2 3` — ожидается `6`.

**Класс бага:** ошибка «на единицу» (off-by-one) — выход за границу массива.
**Где кусается:** любой цикл по массиву/строке; `<=` вместо `<` — классика. С флагом `-D_GLIBCXX_ASSERTIONS` такой выход ловится сразу.

## 9.4. Максимум 🟡

Программа должна печатать наибольшее из введённых чисел (числа читаются до конца
ввода). На вводе из одних отрицательных чисел она ошибается и печатает `0`.

```cpp
#include <iostream>

int main() {
  int x;
  int best = 0;
  while (std::cin >> x) {
    if (x > best) {
      best = x;
    }
  }
  std::cout << best << "\n";
}
```

**Пример:** ввод `-5 -2 -9` — ожидается `-2`.

**Класс бага:** неверное начальное значение аккумулятора (`best = 0`).
**Где кусается:** поиск min/max, когда данные могут быть все отрицательными или все большими — начинать надо с первого элемента, а не с «удобного» нуля.

## 9.5. День недели 🟡

Программа по номеру дня (1–7) должна печатать `WORKDAY` для 1–5 и `WEEKEND`
для 6–7. Но для `6` она печатает сразу две строки.

```cpp
#include <iostream>

int main() {
  int day;
  std::cin >> day;
  switch (day) {
  case 6:
    std::cout << "WEEKEND\n";
  case 7:
    std::cout << "WEEKEND\n";
  default:
    std::cout << "WORKDAY\n";
  }
}
```

**Пример:** ввод `6` — ожидается ровно одна строка `WEEKEND`.

**Класс бага:** забытый `break` в `switch` — выполнение «проваливается» в следующие `case`.
**Где кусается:** любое меню и разбор кодов на `switch`; провал (fallthrough) иногда нужен намеренно, но здесь он лишний.

## 9.6. Обратный отсчёт 🟡

Программа должна печатать числа от `n` до `1` через пробел. Но она зависает и
бесконечно печатает одно и то же число.

```cpp
#include <iostream>

int main() {
  int n;
  std::cin >> n;
  while (n > 0) {
    std::cout << n << " ";
  }
  std::cout << "\n";
}
```

**Пример:** ввод `5` — ожидается `5 4 3 2 1`.

**Класс бага:** бесконечный цикл — переменная в условии не меняется.
**Где кусается:** любой `while`, где забыли обновить счётчик или условие выхода. Программа «висит» и не реагирует.

## 9.7. Сумма N чисел 🟡

Программа читает `N` чисел и должна печатать их сумму. Иногда ответ верный, а иногда —
явно завышенный (будто прибавилось лишнее случайное число).

```cpp
#include <iostream>

int main() {
  int n;
  std::cin >> n;
  int sum;
  for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;
    sum += x;
  }
  std::cout << sum << "\n";
}
```

**Пример:** ввод `3` и `1 2 3` — ожидается `6`.

**Класс бага:** неинициализированная переменная — внутри «мусор» из памяти.
**Где кусается:** любой накопитель (`sum`, `count`, `product`), заведённый без `= 0`. Коварство в том, что мусор иногда случайно равен нулю, и программа «работает» через раз.

# Подсказки

> 📖 Мало подсказки? Открой теорию темы: [раздел справочника](../ref/11-oshibki.md).

<details>
<summary>9.1 — Среднее двух чисел</summary>

- `(a + b) / 2` — это деление **целого на целое**, дробная часть отбрасывается ещё
  до присваивания в `double`. Для 3 и 4 получается `3`, потом `3.0`.
- Почини делитель: `(a + b) / 2.0`. Тогда деление станет дробным.
</details>

<details>
<summary>9.2 — Ноль или нет</summary>

- В условии стоит `=` (присваивание), а не `==` (сравнение). `x = 0` кладёт в `x` ноль
  и возвращает `0`, то есть «ложь» — поэтому всегда идёт ветка `else`.
- Замени на `if (x == 0)`. Хороший компилятор с `-Wall` ещё и предупреждает про такое.
</details>

<details>
<summary>9.3 — Сумма массива</summary>

- Во втором цикле условие `i <= n`: при `i == n` обращение `v[n]` выходит **за границу**
  вектора (индексы идут только `0..n-1`). Отсюда падение или лишнее «мусорное» число.
- Замени на `i < n`. Классическая ошибка «на единицу» (off-by-one).
</details>

<details>
<summary>9.4 — Максимум</summary>

- `best` начинается с `0`. Если все числа отрицательные, ни одно не окажется больше нуля,
  и напечатается `0` — которого во вводе не было.
- Инициализируй `best` первым прочитанным числом (а не нулём). Например, прочитай первое
  число до цикла, либо заведи флаг «первое число ещё не встречалось».
</details>

<details>
<summary>9.5 — День недели</summary>

- В `switch` после `case 6:` нет `break`, поэтому выполнение «проваливается» в следующие
  `case` — печатаются и `case 7`, и `default`.
- Добавь `break;` в конце каждой ветки. И подумай: для 1–5 сюда вообще не попасть отдельным
  `case`, их ловит `default` — это осознанный выбор или тоже стоит переписать?
</details>

<details>
<summary>9.6 — Обратный отсчёт</summary>

- В теле цикла `n` не меняется, поэтому условие `n > 0` истинно всегда — цикл бесконечен.
- Добавь `--n;` внутрь цикла. Тогда `n` дойдёт до 0, и цикл завершится.
</details>

<details>
<summary>9.7 — Сумма N чисел</summary>

- `int sum;` объявлена без начального значения — внутри случайный «мусор», к которому прибавляются числа.
- Замени на `int sum = 0;`. Правило: любой накопитель инициализируй нулём сразу.
</details>
