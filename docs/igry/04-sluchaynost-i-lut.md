### За 30 секунд

- Генератор `std::mt19937` создают **один раз** на всю игру и передают по ссылке.
- Семя (`seed`) — число, из которого генератор разворачивает всю последовательность. Одно семя — один и тот же мир.
- «С шансом 25 %» — `std::bernoulli_distribution(0.25)`.
- Таблица добычи «60 / 30 / 10» — `std::discrete_distribution<int>({60, 30, 10})`.
- Честный рандом для игрока: **мешок** (`std::shuffle`) и **гарантия** (после N неудач — точно выпадет).

```cpp
std::mt19937 rng(std::random_device{}());                // один раз!
std::bernoulli_distribution crit(0.25);                   // шанс 25 %
std::discrete_distribution<int> loot({60, 30, 10});        // веса
if (crit(rng)) damage *= 2;
int rarity = loot(rng);                                   // 0, 1 или 2
```

## Один генератор на всю игру

```cpp
int rollDice() {
  std::mt19937 rng(std::random_device{}());   // ❌ новый генератор на КАЖДЫЙ бросок
  std::uniform_int_distribution<int> d(1, 6);
  return d(rng);
}
```

Работать будет, но плохо: создание генератора — дорогая операция (у `mt19937` внутри 5 КБ состояния), а `random_device` на некоторых системах медленный или вовсе выдаёт одно и то же. Правильно — **один** генератор, созданный в начале, и передача по ссылке:

```cpp
int rollDice(std::mt19937 &rng) {
  std::uniform_int_distribution<int> d(1, 6);   // распределение — лёгкое, его создавать можно
  return d(rng);
}
```

## Семя мира: повторяемая случайность

Генератор не «случайный» по-настоящему: из одного и того же семени он всегда выдаёт одну и ту же последовательность. Это не недостаток, а **инструмент**:

- **Отладка.** Баг случился на 37-м ходу? Запусти с тем же семенем — он повторится.
- **Общий мир.** Как в Minecraft: друг скажет «семя 2026» — и у тебя сгенерируется точно такая же пещера.
- **Ежедневный вызов.** Семя = сегодняшняя дата → у всех игроков одинаковое подземелье дня.

```cpp
unsigned seed = std::random_device{}();       // случайное семя…
std::cout << "Семя мира: " << seed << "\n";    // …но показываем его игроку
std::mt19937 rng(seed);                       // хочешь повторить — подставь число руками
```

> Важно: одинаковые **числа** из генератора гарантированы стандартом, а вот `uniform_int_distribution` и другие распределения разные компиляторы реализуют по-разному. Мир с семенем 2026 на g++ и на MSVC может отличаться. Для одной сборки игры — всё повторяемо.

## Шанс: bernoulli_distribution

«Выпадет с вероятностью p» — это `std::bernoulli_distribution`: она возвращает `true` с вероятностью `p`.

```cpp
std::bernoulli_distribution dropPotion(0.3);   // 30 %
if (dropPotion(rng)) inventory["зелье"]++;
```

Частая ошибка — ждать, что при шансе 30 % зелье выпадет «примерно каждый третий раз». В среднем — да, но подряд может не выпасть и 5, и 10 раз. Про это — [честный рандом](#честный-рандом-мешок-и-гарантия) ниже.

## Таблица добычи с весами

Сундук: обычный предмет — 60 %, редкий — 30 %, легендарный — 10 %. Как это устроено внутри — по шагам. Бросаем число от 0 до 99 и смотрим, в какой «отрезок» оно попало:

```steps
@id c1tsagtz
# Бросок по таблице 60 / 30 / 10
int roll = dice(rng);             // 0..99
if (roll < 60) return "обычный";
if (roll < 90) return "редкий";
return "легендарный";
---
1 | бросок=№1, roll=73 | Выпало 73.
2 | | 73 < 60? Нет — это не «обычный» (отрезок 0…59).
?3 | выпало=редкий | 73 < 90? Да. Что выпало?
1 | бросок=№2, roll=41, выпало=— | Второй сундук: 41.
2 | выпало=обычный | 41 < 60 — «обычный». На него приходится 60 чисел из 100 — отсюда и 60 %.
1 | бросок=№3, roll=95, выпало=— | Третий: 95.
2 | | Не меньше 60…
3 | | …и не меньше 90.
4 | выпало=легендарный | Остался отрезок 90…99 — всего 10 чисел, отсюда 10 %.
```

Вручную так писать неудобно (добавил предмет — пересчитывай границы). Для этого есть `std::discrete_distribution`: даёшь **веса**, он сам выбирает номер.

```cpp
#include <array>
#include <cstddef>
#include <iostream>
#include <random>
#include <string>

int main() {
  const std::array<std::string, 3> names = {"обычный", "редкий", "легендарный"};
  std::discrete_distribution<int> loot({60, 30, 10});   // веса, не обязательно в сумме 100
  std::mt19937 rng(42);                                  // фиксированное семя — результат повторяем

  std::array<int, 3> count{};
  for (int i = 0; i < 1000; ++i)
    ++count[static_cast<std::size_t>(loot(rng))];       // loot(rng) — номер: 0, 1 или 2

  for (std::size_t k = 0; k < names.size(); ++k)
    std::cout << names[k] << ": " << count[k] << "\n";
  return 0;
}
```

Получится около 600 / 300 / 100 — чуть больше или меньше в каждую сторону. Веса — это **доли**, а не проценты: `{6, 3, 1}` даст то же самое. Добавить «мифический» с весом 1 — просто дописать четвёртое число.

Проверь сам — открой сундуки. Сначала по одному: доли скачут. Потом ×1000 — полоски подтянутся к чертам заявленного шанса. Это и есть закон больших чисел.


## Разброс урона и криты

Урон «ровно 10» каждый удар — скучно. Обычно делают разброс ±20 % и шанс крита:

```cpp
int rollDamage(int base, std::mt19937 &rng) {
  std::uniform_real_distribution<double> spread(0.8, 1.2);   // от 80 % до 120 %
  std::bernoulli_distribution crit(0.15);                    // 15 % — критический удар
  double dmg = base * spread(rng);
  if (crit(rng)) dmg *= 2.0;
  return static_cast<int>(std::lround(dmg));                 // округлить до целого (нужен <cmath>)
}
```

`uniform_real_distribution` — дробные числа в диапазоне, а `std::lround` округляет «по-школьному» и возвращает `long`, поэтому ещё `static_cast<int>`.

## Честный рандом: мешок и гарантия

Настоящая случайность **комковатая**: пять промахов подряд при шансе 70 % — нормальное событие (0,3⁵ ≈ 0,2 %, но игроков тысячи). Игроки это воспринимают как «игра жульничает». Два популярных лекарства:

**Мешок (shuffle bag).** Кладём в «мешок» заранее нужную пропорцию исходов, перемешиваем и тянем по одному. Когда мешок опустел — наполняем заново. За 10 вытягиваний ровно 3 зелья — гарантированно.

```cpp
std::vector<bool> bag;
bool drawFromBag(std::mt19937 &rng) {
  if (bag.empty()) {
    bag = {true, true, true, false, false, false, false, false, false, false};   // 3 из 10
    std::shuffle(bag.begin(), bag.end(), rng);
  }
  bool result = bag.back();
  bag.pop_back();
  return result;
}
```

**Гарантия (pity timer).** Считаем неудачи подряд; после N неудач следующий раз — точно успех (или шанс растёт с каждой неудачей). Так работают сундуки во многих играх.

```cpp
int failsInRow = 0;
bool legendary = legendaryChance(rng) || failsInRow >= 9;   // 10-й сундук подряд — легенда точно
if (legendary) failsInRow = 0; else ++failsInRow;
```

Сравни на деле: открой ×1000 без гарантии и посмотри на «самую длинную серию» без легендарки — десятки сундуков подряд. Включи гарантию, сбрось и открой снова: длиннее 9 серия уже не бывает. Но посмотри на долю легендарок — она заметно выросла (около 15 % вместо 10). Гарантия не бесплатна: её учитывают в балансе и снижают базовый шанс, иначе редкое перестаёт быть редким.

```lootsim
@pity 10
```

## Генерация пещеры: пьяный шахтёр

Простейшая генерация уровня: «шахтёр» стоит посреди сплошной скалы и делает случайные шаги, выкапывая клетки, пока не расчистит 40 % поля. Получаются извилистые пещеры, в которых **все** клетки связаны — дойти можно куда угодно.

```cpp
#include <cstddef>
#include <iostream>
#include <random>
#include <string>
#include <vector>

int main() {
  const int W = 40, H = 12;
  unsigned seed = 2026;                           // поменяй — получишь другую пещеру
  std::mt19937 rng(seed);
  std::uniform_int_distribution<int> dir(0, 3);
  const int DX[4] = {1, -1, 0, 0};
  const int DY[4] = {0, 0, 1, -1};

  std::vector<std::string> map(static_cast<std::size_t>(H), std::string(static_cast<std::size_t>(W), '#'));
  auto cell = [&](int x, int y) -> char & { return map[static_cast<std::size_t>(y)][static_cast<std::size_t>(x)]; };

  int x = W / 2, y = H / 2, dug = 0;
  while (dug < W * H * 4 / 10) {                  // копаем, пока не расчистим 40 %
    if (cell(x, y) == '#') {
      cell(x, y) = '.';
      ++dug;
    }
    int k = dir(rng);
    int nx = x + DX[k], ny = y + DY[k];
    if (nx > 0 && ny > 0 && nx < W - 1 && ny < H - 1) {   // рамку из стен не трогаем
      x = nx;
      y = ny;
    }
  }
  cell(W / 2, H / 2) = '@';                       // герой — там, где начал шахтёр

  std::cout << "Семя: " << seed << "\n";
  for (const std::string &row : map) std::cout << row << '\n';
  return 0;
}
```

Поиграй с параметрами: 25 % — узкие ходы, 60 % — широкие залы. А если запустить **нескольких** шахтёров из разных точек — получится сеть пещер. Монеты и монстров расставляют потом на случайные клетки `.` — и все они гарантированно достижимы.

> 🎮 **В настоящих играх.** Tetris по стандарту Tetris Guideline выдаёт фигуры «мешком из семи»: все 7 фигур перемешиваются и выдаются по одной — ровно shuffle bag, поэтому палку не приходится ждать вечно. В Hearthstone легендарная карта гарантирована хотя бы раз за 40 наборов — таймер гарантии. А миры Minecraft растут из семени: одинаковое семя — одинаковый мир.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| Новый `mt19937` в каждой функции | медленно, а на части систем — одинаковые числа | один генератор, по ссылке |
| `rand() % 6` | устаревший и перекошенный способ | `uniform_int_distribution` |
| `std::mt19937 rng;` без семени | каждый запуск — одна и та же игра | семя из `random_device` (и показать его) |
| Шанс «1 из 3» как `dist(rng) == 3` при `dist(1, 3)` | работает, но непонятно; легко ошибиться границей | `bernoulli_distribution(1.0 / 3)` |
| Ставить монстра в случайную клетку без проверки | монстр в стене | выбирать только из клеток `.` |

## Проверь себя

```quiz
В: Игрок говорит: «Шанс 50 %, а у меня 6 промахов подряд — игра сломана». Что ответить?
+ Для настоящей случайности это редко, но возможно (1/64); если это мешает игре — нужен мешок или гарантия
- Генератор сломан, нужно пересоздавать его каждый бросок
- Шанс 50 % означает строго через раз
= Честная случайность бывает «комковатой». Мешок (shuffle bag) и гарантия (pity timer) делают её приятнее для игрока.

В: Что даст `std::discrete_distribution<int>({6, 3, 1})`?
+ Номера 0, 1, 2 с вероятностями 60 %, 30 % и 10 %
- Числа 6, 3 и 1 поровну
- Ошибку: сумма весов не 100
= Веса — доли. Сумма может быть любой.

В: Зачем показывать игроку семя мира?
+ Чтобы можно было повторить тот же мир — для отладки, чтобы поделиться с другом, для «задания дня»
- Для красоты
- Без этого генератор не работает
= Одно семя — одна и та же последовательность чисел, а значит, и тот же мир (в одной сборке игры).
```

```cards
В: Как получить `true` с вероятностью 20 %?
О: `std::bernoulli_distribution chance(0.2); if (chance(rng)) …`

В: Что такое «мешок» (shuffle bag)?
О: Заранее набранные исходы в нужной пропорции, перемешанные `std::shuffle` и вытягиваемые по одному. Пропорция соблюдается точно.

В: Чем «пьяный шахтёр» хорош для генерации пещер?
О: Все выкопанные клетки связаны между собой — любую точку можно достичь.

Q: Почему `rand() % 6` хуже `std::uniform_int_distribution`?
A: У `rand` слабая случайность, а остаток от деления даёт перекос. `<random>` с `std::mt19937` — качественный генератор и честное распределение.

Q: Как выбрать лут с весами: обычный 70, редкий 25, легендарный 5?
A: `std::discrete_distribution<int> d({70, 25, 5});` — вызов `d(rng)` вернёт индекс с нужной вероятностью.

Q: Зачем задавать зерно (seed) вручную?
A: Одно зерно — одна и та же последовательность: удобно воспроизводить баги и делиться «сидом» карты.
H: Подумай о повторном запуске с теми же числами.

Q: Что такое «гарант» (pity timer) в луте?
A: Счётчик неудач: если редкий предмет не выпал N раз подряд, следующий гарантирован. Это защита от невезения.
```

## Закрепление прошлых тем

Три вопроса из тем, на которых стоит случайность:

```quiz

+ Да, обе границы включены
- Нет, правая граница не входит
- Только если генератор `mt19937`
= У целочисленного распределения диапазон закрытый: `[1, 6]`. У дробного `uniform_real_distribution` правая граница не входит.

В: Тема 7. Что нужно передать в `std::shuffle`, кроме диапазона?
+ Генератор: `std::shuffle(v.begin(), v.end(), rng)`
```
