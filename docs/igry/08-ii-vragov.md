### За 30 секунд

- ИИ врага — это **машина состояний**: `Patrol` (патруль), `Chase` (погоня), `Attack` (атака), `Flee` (бегство).
- Каждый ход — две функции: `think()` выбирает состояние по ситуации, `act()` делает то, что велит состояние.
- `think()` — цепочка правил **по приоритету**: мало здоровья → бежать; рядом → бить; видит → гнаться; иначе — патруль.
- Расстояние на сетке — «манхэттенское»: `|dx| + |dy|`. Для погони в обход стен — волна BFS из [темы про карту](03-karta-i-put.md).
- Разные «характеры» — это не новый код, а **разные числа**: радиус зрения, порог бегства, скорость.

## ИИ в играх: не умный, а интересный

Игровой ИИ не должен побеждать игрока — он должен быть **понятным** и **интересным** противником. Враг, который всегда стреляет в голову с другого конца карты, раздражает. Враг, который патрулирует, замечает, кричит, гонится и убегает, когда ранен, — оживляет игру, хотя устроен очень просто.

Поэтому почти во всех играх ИИ — это не нейросеть, а набор правил: машина состояний (как в [теме про состояния](02-sostoyaniya.md)), только **у каждого врага своя**.

## У каждого врага — своё состояние

```cpp
enum class Mode { Patrol, Chase, Attack, Flee };

struct Enemy {
  Pos pos;
  int hp = 10;
  Mode mode = Mode::Patrol;
  std::vector<Pos> route;   // точки патруля: ходит между ними по кругу
  std::size_t next = 0;     // к какой точке идёт сейчас
};
```

Пять гоблинов — пять объектов `Enemy`, и у каждого своё `mode`: один патрулирует, второй уже гонится, третий убегает. Общий только код, который ими управляет.

## Думать и действовать: две разные функции

Полезно разделить «принять решение» и «выполнить его»:

```cpp
Mode think(const Enemy &e, Pos hero);   // только решает — ничего не меняет (const!)
void act(Enemy &e, Pos hero);           // делает шаг, бьёт, убегает — по e.mode
```

Зачем разделять:

- `think` легко проверить: подставил ситуацию — посмотрел, что враг **решил**. Без экрана и без случайностей.
- Решения всех врагов можно принять **сначала**, а выполнить **потом** — тогда враг, походивший первым, не влияет на решение второго в тот же ход.
- Отладка: печатаешь `mode` над врагом — и сразу видно, почему он стоит (он «думает», что патрулирует).

## Порядок правил решает всё

`think` — это цепочка `if`, и **порядок** в ней — это приоритеты врага:

```cpp
Mode think(const Enemy &e, Pos hero) {
  int d = dist(e.pos, hero);
  if (e.hp <= 3) return Mode::Flee;     // 1. жизнь дороже всего
  if (d <= 1) return Mode::Attack;      // 2. герой рядом — бить
  if (d <= 5) return Mode::Chase;       // 3. видит героя — гнаться
  return Mode::Patrol;                  // 4. иначе — обычные дела
}
```

Посмотри, как раненый враг принимает решение, хотя герой стоит вплотную:

```steps
@id c1su29sh
# Раненый враг рядом с героем: что он выберет?
int d = dist(e.pos, hero);
if (e.hp <= 3) return Mode::Flee;
if (d <= 1) return Mode::Attack;
if (d <= 5) return Mode::Chase;
return Mode::Patrol;
---
1 | e.hp=3, d=1 | Враг ранен (3 HP), герой — на соседней клетке.
?2 | решение=Flee | Первое правило: `hp <= 3`. Что выберет враг?
2 | | Условие истинно — `return` сразу, остальные правила **даже не проверяются**. Враг убегает, хотя мог бы ударить.
1 | e.hp=10, d=1, решение=— | А теперь здоровый враг на том же месте.
2 | | 10 <= 3 — ложь, идём дальше.
3 | решение=Attack | Рядом — атака.
1 | d=4, решение=— | Герой отошёл на 4 клетки.
3 | | 4 <= 1 — ложь.
4 | решение=Chase | Видит — гонится. Поменяй правила 1 и 2 местами — и получишь «берсерка», который дерётся до последнего.
```

## Всё вместе: один враг, четыре поведения

Враг патрулирует между двумя точками, герой подходит всё ближе — враг его замечает, догоняет, атакует, а раненый — убегает. Программа печатает, что он решил на каждом ходу:

```cpp
#include <cstddef>
#include <cstdlib>
#include <iostream>
#include <string>
#include <vector>

enum class Mode { Patrol, Chase, Attack, Flee };

std::string modeName(Mode m) {
  switch (m) {
    case Mode::Patrol: return "патруль";
    case Mode::Chase: return "погоня";
    case Mode::Attack: return "атака";
    case Mode::Flee: return "бегство";
  }
  return "?";
}

struct Pos {
  int x = 0;
  int y = 0;
};

int dist(Pos a, Pos b) { return std::abs(a.x - b.x) + std::abs(a.y - b.y); }

// Шаг на одну клетку к цели (dir = +1) или от неё (dir = -1) по «длинной» оси.
Pos stepToward(Pos from, Pos to, int dir) {
  Pos p = from;
  if (std::abs(to.x - from.x) >= std::abs(to.y - from.y)) p.x += dir * (to.x > from.x ? 1 : -1);
  else p.y += dir * (to.y > from.y ? 1 : -1);
  return p;
}

struct Enemy {
  Pos pos;
  int hp = 10;
  Mode mode = Mode::Patrol;
  std::vector<Pos> route;
  std::size_t next = 0;
};

Mode think(const Enemy &e, Pos hero) {
  int d = dist(e.pos, hero);
  if (e.hp <= 3) return Mode::Flee;
  if (d <= 1) return Mode::Attack;
  if (d <= 5) return Mode::Chase;
  return Mode::Patrol;
}

void act(Enemy &e, Pos hero) {
  switch (e.mode) {
    case Mode::Patrol: {
      Pos target = e.route[e.next];
      if (dist(e.pos, target) == 0) e.next = (e.next + 1) % e.route.size();   // дошёл — к следующей точке
      else e.pos = stepToward(e.pos, target, +1);
      break;
    }
    case Mode::Chase: e.pos = stepToward(e.pos, hero, +1); break;
    case Mode::Attack: std::cout << "    враг бьёт героя!\n"; break;
    case Mode::Flee: e.pos = stepToward(e.pos, hero, -1); break;
  }
}

int main() {
  Enemy e;
  e.pos = {10, 0};
  e.route = {{10, 0}, {14, 0}};
  const std::vector<int> heroX = {0, 3, 6, 8, 9, 10, 10, 10};   // герой идёт вправо и останавливается

  for (std::size_t turn = 0; turn < heroX.size(); ++turn) {
    Pos hero{heroX[turn], 0};
    if (turn == 6) e.hp = 3;                                     // герой ранил врага
    e.mode = think(e, hero);
    std::cout << "Ход " << turn + 1 << ": герой " << hero.x << ", враг " << e.pos.x
              << ", расстояние " << dist(e.pos, hero) << " -> " << modeName(e.mode) << "\n";
    act(e, hero);
  }
  return 0;
}
```

```console
Ход 1: герой 0, враг 10, расстояние 10 -> патруль
Ход 2: герой 3, враг 10, расстояние 7 -> патруль
Ход 3: герой 6, враг 11, расстояние 5 -> погоня
Ход 4: герой 8, враг 10, расстояние 2 -> погоня
Ход 5: герой 9, враг 9, расстояние 0 -> атака
    враг бьёт героя!
Ход 6: герой 10, враг 9, расстояние 1 -> атака
    враг бьёт героя!
Ход 7: герой 10, враг 9, расстояние 1 -> бегство
Ход 8: герой 10, враг 8, расстояние 2 -> бегство
```

Здесь враг идёт к цели по прямой — на открытом поле этого хватает. В лабиринте замени `stepToward` на шаг по волне BFS от героя ([как враг идёт по волне](03-karta-i-put.md#как-враг-идёт-по-волне)) — и погоня будет огибать стены.

## Характеры: одно поведение, разные числа

Трус, берсерк и снайпер — не три разных класса, а три набора чисел:

```cpp
struct Personality {
  int sight = 5;       // радиус зрения
  int fleeAt = 3;      // при каком HP убегает (0 — никогда)
  int attackRange = 1; // с какого расстояния бьёт
};

const Personality coward{8, 7, 1};    // видит далеко, убегает рано
const Personality berserk{4, 0, 1};   // близорукий, но не отступает никогда
const Personality archer{7, 3, 4};    // бьёт издалека
```

`think` читает числа из характера вместо констант — и в игре сразу три разных противника. Новому врагу не нужен новый код, только новая строчка.

## Выбор по очкам: когда правил становится много

Когда у врага 8–10 действий (лечиться, звать подмогу, прятаться за укрытием…), цепочка `if` становится запутанной. Тогда используют **выбор по очкам** (utility AI): каждое действие получает оценку «насколько оно сейчас полезно», и враг выбирает действие с наибольшей.

```cpp
int scoreFlee  = (e.hp < 4) ? 90 : 0;
int scoreHeal  = (e.hp < 6 && e.potions > 0) ? 70 : 0;
int scoreAttack = (d <= 1) ? 60 : 0;
int scoreChase = (d <= e.sight) ? 40 : 0;
// выбрать действие с максимальной оценкой
```

Преимущество — правила не мешают друг другу, их легко добавлять и настраивать числами. Для консольной игры обычно хватает цепочки `if`, но полезно знать, куда расти.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| Враг и решает, и двигается в одной функции | трудно отлаживать, враги влияют на решения друг друга | `think` + `act` |
| Правила в «неправильном» порядке | раненый враг не убегает, а бьёт | порядок `if` = приоритеты |
| Нет «гистерезиса» у погони | на границе зрения враг дёргается: погоня-патруль-погоня | терять цель на 2–3 клетки дальше, чем замечать |
| Погоня по прямой в лабиринте | враг упирается в стену | шаг по волне BFS |
| Все враги одинаковые | скучно | характеры — разные числа |

## Проверь себя

```quiz
В: Почему `think` удобно делать `const`-функцией, которая только возвращает решение?
+ Её легко проверять и отлаживать, а решения всех врагов можно принять до того, как кто-то походит
- Так быстрее компилируется
- `const`-функции нельзя вызывать в цикле
= Разделение «решить» и «сделать» — простой способ держать ИИ предсказуемым.

В: Враг замечает героя на расстоянии 5 и теряет на расстоянии 5. Герой стоит ровно на границе и шагает туда-сюда. Что увидит игрок?
+ Враг дёргается: погоня, патруль, погоня…
- Враг плавно преследует
- Ничего особенного
= Лечится «гистерезисом»: заметил на 5 — теряет только на 8.

- Скопировать `think` и переписать
- Никак
= Поведение в коде общее, характер — в данных.
```

```cards
В: Из каких двух функций удобно собирать ИИ врага?
О: `think()` — выбрать состояние по ситуации; `act()` — выполнить то, что велит состояние.

В: Что такое гистерезис в ИИ?
О: Разные пороги для входа и выхода из состояния (заметил на 5, потерял на 8) — чтобы враг не дёргался на границе.

Q: Какие состояния бывают у простого ИИ врага?
A: Например: патруль → преследование (увидел игрока) → атака (подошёл вплотную) → бегство (мало здоровья).

Q: Как враг «видит» игрока в простейшей версии?
A: По расстоянию: `dx * dx + dy * dy <= r * r` — без корня. По желанию ещё проверяют, нет ли стены на линии взгляда.
H: Зачем здесь нет `sqrt`?

Q: Зачем врагу реакция с задержкой?
A: Мгновенная реакция кажется нечестной. Небольшая пауза делает ИИ живым и даёт игроку шанс.

Q: Как сделать врагов разными без нового кода?
A: Вынести параметры в данные: радиус обзора, скорость, порог бегства. Один ИИ — разные числа.
```

## Закрепление прошлых тем

Три вопроса из прошлых тем раздела:

```quiz
В: Игры, тема 2. Почему состояние хранят в `enum class`, а не в нескольких `bool`?
+ Состояние одно в каждый момент — не бывает «в меню и в бою сразу»
- `bool` занимает больше памяти
- `enum class` работает быстрее
= С четырьмя `bool` возможны 16 сочетаний, и большинство из них — баги.

В: Игры, тема 3. Почему в `inside` сначала проверяют `y`, а потом берут `map[y]`?
+ Иначе обращение за границу вектора случится раньше проверки
- Так быстрее
- Порядок не важен
= `&&` вычисляется слева направо и останавливается на первом `false`.
```
