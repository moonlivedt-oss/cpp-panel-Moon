### За 30 секунд

- Терминал понимает **escape-последовательности** — строки, начинающиеся с `\x1b[`: цвет, позиция курсора, очистка.
- В Windows их нужно один раз **включить**: `SetConsoleMode(..., ENABLE_VIRTUAL_TERMINAL_PROCESSING)`.
- Кадр собирают **в одну строку** и печатают разом, начиная с `\x1b[H` (курсор в угол), — тогда нет мерцания.
- `_kbhit()` — «нажата ли клавиша?» (не ждёт), `_getch()` — прочитать её без Enter. Оба из `<conio.h>`, только Windows.
- Стрелки приходят **двумя** кодами: сначала `0` или `224`, потом код стрелки (72 ↑, 80 ↓, 75 ←, 77 →).

## Escape-последовательности: команды терминалу

Если напечатать особую строку, терминал её не покажет, а **выполнит**. Все они начинаются с символа ESC (`\x1b`) и `[`:

| Строка | Что делает |
|---|---|
| `\x1b[2J` | очистить экран |
| `\x1b[H` | курсор в левый верхний угол |
| `\x1b[5;10H` | курсор в строку 5, столбец 10 (считаются с 1) |
| `\x1b[31m` … `\x1b[37m` | цвет текста: красный, зелёный, жёлтый, синий, пурпурный, голубой, белый |
| `\x1b[1m` | жирный (часто — ярче) |
| `\x1b[0m` | сбросить цвет и стиль |
| `\x1b[?25l` / `\x1b[?25h` | спрятать / показать курсор |

```cpp
std::cout << "\x1b[31m" << "Огонь!" << "\x1b[0m" << "\n";   // «Огонь!» красным, дальше — обычный цвет
```

Никогда не забывай `\x1b[0m` после цветного куска — иначе в этот цвет окрасится всё, что напечатается дальше, включая твою командную строку после выхода из игры.

## Включить цвета в Windows

Windows Terminal и консоль VS Code понимают эти коды сразу, а старая консоль (`conhost`) — только после включения режима. Включают один раз при старте:

```cpp
#include <windows.h>

void enableAnsi() {
  HANDLE out = GetStdHandle(STD_OUTPUT_HANDLE);
  DWORD mode = 0;
  if (GetConsoleMode(out, &mode))                                    // узнать текущий режим
    SetConsoleMode(out, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);  // добавить «понимать escape-коды»
  SetConsoleOutputCP(CP_UTF8);                                       // и заодно — русский текст
}
```

## Кадр целиком: рисуем без мерцания

Первая идея — каждый кадр очищать экран (`system("cls")` или `\x1b[2J`) и печатать поле строчка за строчкой. Экран будет **мигать**: какое-то мгновение он пустой, и глаз это замечает. К тому же `system("cls")` запускает отдельную программу — это очень медленно.

Правильно:

1. Собрать **весь** кадр в одну `std::string`.
2. Начать её с `\x1b[H` — «курсор в угол», **без** очистки.
3. Напечатать одним `std::cout << frame << std::flush;`.

Новый кадр ложится поверх старого символ в символ — пустого мгновения нет. Чистить экран нужно только один раз при старте (`\x1b[2J`) и если размер поля изменился.

## Клавиши без Enter: _kbhit и _getch

`std::cin` ждёт Enter — для игры в реальном времени не годится. В Windows есть две функции из `<conio.h>`:

- `_kbhit()` — **не ждёт**: возвращает не ноль, если в буфере есть нажатая клавиша.
- `_getch()` — забирает одну клавишу из буфера, **без** Enter и без показа на экране.

```cpp
while (_kbhit()) {          // пока есть непрочитанные нажатия (за кадр их может быть несколько)
  int key = _getch();
  if (key == 'd') ++x;
  if (key == 'q') running = false;
}
// дальше — обновление и рисование кадра, цикл не останавливается
```

Почему `while`, а не `if`: пока шёл кадр, игрок мог нажать две клавиши. С `if` вторая останется в буфере и сработает кадром позже — управление станет «ватным».

> `<conio.h>` — не часть стандарта C++, это расширение Windows-компиляторов (MinGW и MSVC). Для обычного ввода по-прежнему бери `std::cin` — см. [справку](../ref/09-spravka.md). А в Linux/macOS для того же используют библиотеки вроде `ncurses`.

## Стрелки: две половинки одной клавиши

Буквы приходят одним кодом, а стрелки и `F1…F12` — **двумя**: сначала «префикс» `0` или `224`, потом код самой клавиши.

```cpp
int key = _getch();
if (key == 0 || key == 224) {   // это «особая» клавиша — читаем вторую половинку
  int code = _getch();
  if (code == 72) --y;          // ↑
  if (code == 80) ++y;          // ↓
  if (code == 75) --x;          // ←
  if (code == 77) ++x;          // →
}
```

```steps

2 | | 224 — значит, это особая клавиша, будет вторая половинка.
?3 | code=72 | `_getch()` ещё раз — какой код у стрелки вверх?
4 | y=4 | 72 — это ↑. Двигаемся вверх.
1 | нажато=W, key=119, code=— | Теперь буква `w`: код 119 приходит **одним** числом.
2 | | 119 — не 0 и не 224, вторую половинку не читаем.
5 | | Сравниваем с `'w'` — совпало.
6 | y=3 | Тоже вверх. Если бы мы прочитали `_getch()` ещё раз «на всякий случай», программа бы остановилась и ждала новую клавишу.
```

## Всё вместе: живое поле

Герой `@` ходит на `WASD`, собирает монеты `$`, кадры идут 30 раз в секунду независимо от того, жмёшь ли ты что-то. Выход — `Q`.

```cpp
#include <conio.h>     // _kbhit, _getch — только Windows
#include <windows.h>   // SetConsoleMode, SetConsoleOutputCP

#include <chrono>
#include <iostream>
#include <string>
#include <thread>

void enableAnsi() {
  HANDLE out = GetStdHandle(STD_OUTPUT_HANDLE);
  DWORD mode = 0;
  if (GetConsoleMode(out, &mode))
    SetConsoleMode(out, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);
  SetConsoleOutputCP(CP_UTF8);
}

int main() {
  enableAnsi();
  const int W = 30, H = 10;
  int px = W / 2, py = H / 2;     // герой
  int cx = 3, cy = 2;             // монета
  int coins = 0;

  std::cout << "\x1b[2J\x1b[?25l";   // очистить экран один раз и спрятать курсор
  bool running = true;
  while (running) {
    while (_kbhit()) {               // все нажатия, накопившиеся за кадр
      int key = _getch();
      if (key == 'w' && py > 0) --py;
      if (key == 's' && py < H - 1) ++py;
      if (key == 'a' && px > 0) --px;
      if (key == 'd' && px < W - 1) ++px;
      if (key == 'q') running = false;
    }

    if (px == cx && py == cy) {      // подобрали монету — переносим её
      ++coins;
      cx = (cx * 7 + 5) % W;
      cy = (cy * 3 + 1) % H;
    }

    std::string frame = "\x1b[H";    // курсор в угол: рисуем ПОВЕРХ прошлого кадра
    for (int y = 0; y < H; ++y) {
      for (int x = 0; x < W; ++x) {
        if (x == px && y == py) frame += "\x1b[33m@\x1b[0m";        // жёлтый герой
        else if (x == cx && y == cy) frame += "\x1b[32m$\x1b[0m";   // зелёная монета
        else frame += '.';
      }
      frame += '\n';
    }
    frame += "Монеты: " + std::to_string(coins) + "   WASD — ход, Q — выход\n";
    std::cout << frame << std::flush;                               // один вывод на кадр

    std::this_thread::sleep_for(std::chrono::milliseconds(33));     // ~30 кадров в секунду
  }
  std::cout << "\x1b[?25h";          // вернуть курсор
  return 0;
}
```

Запускай из внешнего терминала или встроенного терминала VS Code: вкладка «Output» у некоторых раннеров не передаёт нажатия клавиш программе.

Монета здесь переезжает по формуле, а не случайно, — чтобы код был короче. Замени формулу на `<random>` из [темы про случайность](04-sluchaynost-i-lut.md), и получится настоящая мини-игра.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| `system("cls")` каждый кадр | мерцание и тормоза | `\x1b[H` + кадр одной строкой |
| Нет `\x1b[0m` после цвета | окрашивается всё до конца, даже после выхода | сбрасывать цвет после каждого цветного куска |
| `if (_kbhit())` вместо `while` | «ватное» управление, нажатия опаздывают | `while (_kbhit())` |
| Стрелка читается одним `_getch()` | в игру прилетает «224», а стрелка — кадром позже | при `0`/`224` читать вторую половинку |
| Курсор не вернули | после игры курсор в терминале пропал | `\x1b[?25h` перед выходом |

## Проверь себя

```quiz
В: Почему кадр лучше печатать одной строкой, начиная с `\x1b[H`, а не очищать экран?
+ Новый кадр рисуется поверх старого без пустого мгновения — нет мерцания
- Так меньше памяти
- `\x1b[2J` не работает в Windows
= Очистка оставляет на мгновение пустой экран, и глаз видит мигание. Перезапись поверх — нет.

В: Что вернёт `_kbhit()`, если игрок ничего не нажимал?
+ 0 — и программа сразу пойдёт дальше, не дожидаясь нажатия
- Будет ждать нажатия
- Код последней нажатой клавиши
= В этом весь смысл: цикл кадров не останавливается, пока игрок думает.

В: `_getch()` вернул 224. Что это значит?
+ Нажата особая клавиша (стрелка, F-клавиша) — её код придёт следующим `_getch()`
- Нажата буква «а»
- Ошибка чтения
= Стрелки приходят парой: префикс 0/224 и код клавиши.
```

```cards
В: Как в консоли вывести текст красным и вернуть обычный цвет?
О: `std::cout << "\x1b[31m" << текст << "\x1b[0m";`

В: Какие две функции нужны для управления без Enter в Windows?
О: `_kbhit()` — есть ли нажатие (не ждёт), `_getch()` — прочитать клавишу. Заголовок `<conio.h>`.

Q: Почему экран мерцает, если каждый кадр вызывать `system("cls")`?
A: Очистка и перерисовка видны глазу. Лучше вернуть курсор в начало (`"\x1b[H"`) и перезаписать кадр целиком.

Q: Зачем собирать кадр в одну `std::string` перед выводом?
A: Один большой вывод быстрее сотни мелких `std::cout <<` и не рвёт кадр посередине.

Q: Как спрятать мигающий курсор в консоли?
A: Последовательностью `"\x1b[?25l"`, а вернуть — `"\x1b[?25h"`. Возвращать нужно обязательно, перед выходом из игры.
H: `l` — спрятать, `h` — показать.

Q: Что делает `_kbhit()`?
A: Проверяет, нажата ли клавиша, не останавливая программу. Саму клавишу потом читают через `_getch()` (Windows, `<conio.h>`).
```

> **Бонус к «Подземелью»** (к [квесту 11](../proekt/04-glava-3-klassy-i-karta.md#квест-11-карта-подземелья)): герой ходит без Enter, стены серые, монстры красные, золото жёлтое, а над картой — строка статуса с HP.

## Закрепление прошлых тем

Три вопроса из тем, на которых стоит экран:

```quiz
В: Тема 5. Что лежит в `std::string row(5, '.');`?
+ `"....."`
- `"5."`
- `"."`
= Конструктор «сколько раз, какой символ» — удобный способ сделать пустую строку поля.

В: Тема 2. Почему в цикле кадров пишут `"\n"`, а не `std::endl`?
+ `std::endl` ещё и сбрасывает буфер — на каждой строке кадра это медленно
- `std::endl` не работает в Windows
- Разницы нет
= Кадр собирают целиком и сбрасывают один раз: `std::cout << frame << std::flush;`.

В: Игры, тема 1. Чем `sleep_until(next)` лучше `sleep_for(33ms)` в игровом цикле?
+ Спит до нужного момента — время самого кадра не сдвигает ритм
- Спит точнее на Windows
- Ничем, это синонимы
= С `sleep_for` кадр длится «работа + 33 мс», и FPS уплывает.
```
