### За 30 секунд

- Игра всегда находится **ровно в одном** состоянии: меню, игра, пауза, конец.
- Состояния перечисляют в `enum class State { Menu, Playing, Paused, GameOver };`.
- Главный цикл делает `switch (state)` и зовёт функцию этого состояния.
- Функция состояния **возвращает следующее состояние** — так все переходы видны в одном месте.
- Пауза и инвентарь «поверх» игры — это **стек** состояний: положили сверху, сняли — вернулись.

```cpp
enum class State { Menu, Playing, GameOver, Quit };

State state = State::Menu;
while (state != State::Quit) {
  switch (state) {
    case State::Menu:     state = menu();     break;
    case State::Playing:  state = play();     break;
    case State::GameOver: state = gameOver(); break;
    case State::Quit:     break;
  }
}
```

## Проблема: каша из флагов

Первая версия игры обычно обрастает флагами:

```cpp
bool inMenu = true;
bool isPaused = false;
bool gameOver = false;
bool inSettings = false;

if (inMenu && !inSettings) { /* меню */ }
else if (!inMenu && !isPaused && !gameOver) { /* игра */ }
else if (isPaused && !gameOver) { /* пауза */ }
// а что, если inMenu и gameOver оба true? Такого быть не должно — но код это позволяет
```

Четыре флага — это 16 комбинаций, из которых осмысленных всего четыре. Остальные 12 — готовые баги: забыл сбросить `gameOver` при новой игре, и меню показывается поверх экрана поражения.

## Машина состояний

Вместо флагов — **одна** переменная, которая может принимать только допустимые значения:

```cpp
enum class State { Menu, Playing, Paused, GameOver, Quit };
State state = State::Menu;    // «в меню и одновременно в игре» — просто невозможно записать
```

Каждому состоянию — своя функция, которая делает свою работу и **решает, куда дальше**:

```cpp
State menu() {
  std::cout << "1 — играть, 0 — выход\n> ";
  int choice = readInt();
  if (choice == 1) return State::Playing;   // переход
  return State::Quit;
}
```

Так все переходы видны в одном месте — в `return` функции состояния. Не нужно искать по всему коду, кто и где выставил `gameOver = true`.

## Таблица переходов

Прежде чем писать код, полезно нарисовать таблицу: из какого состояния, по какому событию, куда.

| Сейчас | Событие | Дальше |
|---|---|---|
| Menu | «Играть» | Playing |
| Menu | «Выход» | Quit |
| Playing | угадал число | GameOver |
| Playing | «пауза» | Paused |
| Paused | «продолжить» | Playing |
| GameOver | «ещё раз» | Playing |
| GameOver | «в меню» | Menu |

Если какого-то перехода нет в таблице — его нет и в игре. Это отличная проверка на «а что будет, если…».

Пройди по шагам — игрок выбирает «играть», угадывает, возвращается в меню и выходит:

```steps
@id c5xtrb4
# Как state меняется от событий игрока
State state = State::Menu;
while (state != State::Quit) {
    switch (state) {
        case State::Menu:     state = menu();     break;
        case State::Playing:  state = play();     break;
        case State::GameOver: state = gameOver(); break;
    }
}
---
1 | state=Menu | Игра начинается с меню.
2 | | Menu ≠ Quit — крутим цикл.
4 | ввёл=1, state=Playing | `menu()` спросил, игрок ввёл 1 («играть») — функция вернула `Playing`.
2 | | Снова проверка — не Quit.
5 | ввёл=угадал число | `play()` отработала всю партию…
?5 | state=GameOver | …и вернула следующее состояние. Какое?
6 | ввёл=2 (в меню), state=Menu | На экране конца игрок выбрал «в меню».
4 | ввёл=0, state=Quit | В меню — «выход».
2 | | Quit — цикл закончен, игра завершается. Заметь: ни одного флага.
```

## Всё вместе: угадайка с меню

Полная программа: меню → игра → экран итогов → снова игра или меню.

```cpp
#include <iostream>
#include <limits>
#include <random>

enum class State { Menu, Playing, GameOver, Quit };

// Надёжное чтение числа: на буквах не зацикливается, на конце ввода вернёт 0.
int readInt() {
  int v = 0;
  while (!(std::cin >> v)) {
    if (std::cin.eof()) return 0;
    std::cin.clear();
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    std::cout << "Нужно число: ";
  }
  return v;
}

State menu() {
  std::cout << "\n=== УГАДАЙКА ===\n1 — играть\n0 — выход\n> ";
  return readInt() == 1 ? State::Playing : State::Quit;
}

State play(std::mt19937 &rng, int &lastTries) {
  std::uniform_int_distribution<int> dist(1, 50);
  int secret = dist(rng);
  int tries = 0;
  std::cout << "Я загадал число от 1 до 50.\n";
  while (true) {
    std::cout << "Твой вариант: ";
    int guess = readInt();
    if (std::cin.eof()) return State::Quit;   // ввод закончился — выходим
    ++tries;
    if (guess == secret) break;
    std::cout << (guess < secret ? "Больше!\n" : "Меньше!\n");
  }
  lastTries = tries;
  return State::GameOver;
}

State gameOver(int tries) {
  std::cout << "Угадал за " << tries << " попыток!\n1 — ещё раз, 2 — в меню, 0 — выход\n> ";
  switch (readInt()) {
    case 1: return State::Playing;
    case 2: return State::Menu;
    default: return State::Quit;
  }
}

int main() {
  std::mt19937 rng(std::random_device{}());
  State state = State::Menu;
  int lastTries = 0;
  while (state != State::Quit) {
    switch (state) {
      case State::Menu:     state = menu(); break;
      case State::Playing:  state = play(rng, lastTries); break;
      case State::GameOver: state = gameOver(lastTries); break;
      case State::Quit:     break;
    }
  }
  std::cout << "Пока!\n";
  return 0;
}
```

Обрати внимание:

- `main` совсем короткий — он только **переключает** состояния.
- Данные, которые нужны нескольким состояниям (`rng`, `lastTries`), живут в `main` и передаются по ссылке.
- В `switch` перечислены **все** значения `enum class`, даже `Quit`. Если добавишь новое состояние и забудешь его здесь, g++ предупредит: `enumeration value 'Paused' not handled in switch` (флаг `-Wall`). Это бесплатная проверка — не глуши её `default:`.

## Пауза поверх игры: стек состояний

Пауза, инвентарь, диалог — это состояния, которые открываются **поверх** игры, а закрываясь, возвращают **туда же**. Обычная переменная `state` тут неудобна: после паузы надо помнить, куда возвращаться. Помогает стек — `std::vector<State>`, где верхний элемент — текущее состояние:

```cpp
std::vector<State> stack = {State::Playing};

stack.push_back(State::Paused);     // открыли паузу поверх игры
// ... текущее — stack.back() == Paused
stack.pop_back();                   // закрыли — снова Playing, всё как было

stack.push_back(State::Inventory);  // инвентарь
stack.push_back(State::Dialog);     // из инвентаря открыли диалог «выбросить?»
stack.pop_back();                   // закрыли диалог — вернулись в инвентарь, а не в игру
```

Правило простое: **открыть окно** — `push_back`, **закрыть** — `pop_back`, **сменить сцену целиком** (из игры в меню) — очистить стек и положить новое.

```steps
@id c1tnnbb7
# Стек состояний: пауза и инвентарь
std::vector<State> stack = {State::Playing};
stack.push_back(State::Paused);
stack.pop_back();
stack.push_back(State::Inventory);
stack.push_back(State::Dialog);
stack.pop_back();
stack.pop_back();
---
1 | стек=[Playing], сейчас=Playing | Идёт игра.
2 | стек=[Playing, Paused], сейчас=Paused | Нажали паузу — она легла **сверху**. Игра под ней не пропала, просто не обновляется.
3 | стек=[Playing], сейчас=Playing | Сняли паузу — вернулись ровно туда, где были.
4 | стек=[Playing, Inventory], сейчас=Inventory | Открыли инвентарь.
5 | стек=[Playing, Inventory, Dialog], сейчас=Dialog | Из инвентаря — диалог «выбросить меч?».
6 | стек=[Playing, Inventory], сейчас=Inventory | Закрыли диалог — вернулись в инвентарь, а не в игру.
7 | стек=[Playing], сейчас=Playing | Закрыли инвентарь — снова игра.
```

> 🎮 **В настоящих играх.** В исходниках Doom (1993) есть перечисление `gamestate_t` со значениями `GS_LEVEL`, `GS_INTERMISSION`, `GS_FINALE`, `GS_DEMOSCREEN` — та же машина состояний, что в этой теме. Призраки Pac-Man по таймеру переключаются между режимами «погоня», «разбегание» и «испуг» — тоже конечный автомат.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| Несколько `bool` вместо состояния | невозможные комбинации, «меню поверх поражения» | один `enum class` |
| Забыли `break` в `case` | выполнится и следующее состояние | `break` в каждом `case` (или `return`) |
| `default:` в `switch` по своему `enum` | компилятор перестанет предупреждать о забытом состоянии | перечислять все значения явно |
| Меняют `state` в середине обработки кадра | часть кадра — по старому состоянию, часть — по новому | функция состояния **возвращает** новое, меняем в одном месте |
| Новая игра не сбрасывает данные | вторая партия начинается с HP и счётом первой | сброс — в момент перехода в `Playing` |

## Проверь себя

```quiz
В: Почему `enum class State` лучше четырёх флагов `bool`?
+ Переменная может быть только в одном допустимом состоянии — невозможные комбинации не записать
- Он быстрее работает
- Флаги нельзя использовать в `if`
= Четыре флага дают 16 комбинаций, а осмысленных — 4. `enum class` оставляет только допустимые.

В: Игрок открыл паузу, а из неё — настройки. Закрыл настройки. Куда он должен попасть?
+ Обратно в паузу
- Сразу в игру
- В главное меню
= Это поведение стека: закрытие снимает верхнее состояние и возвращает предыдущее.

В: Что делает флаг `-Wall` со `switch` по `enum class` без `default`?
+ Предупреждает, если какое-то значение перечисления не обработано
- Ничего
- Запрещает компиляцию
= Предупреждение `-Wswitch` — бесплатная защита: добавил новое состояние — компилятор покажет все места, где его забыли.
```

```cards
В: Что возвращает функция состояния в машине состояний?
О: Следующее состояние. Так все переходы собраны в `return` и видны в одном месте.

В: Как открыть паузу поверх игры и вернуться обратно?
О: Стек состояний: `stack.push_back(State::Paused)` — открыть, `stack.pop_back()` — вернуться.

Q: Чем машина состояний лучше набора флагов `bool`?
A: В каждый момент ровно одно состояние, недопустимые сочетания невозможны, а все переходы видны в одном `switch`.

Q: Почему для состояний берут `enum class`, а не просто `enum`?
A: Имена не утекают в окружающую область и не превращаются неявно в `int` — меньше случайных ошибок.

Q: Что делает стек состояний, когда нажали «Пауза»?
A: Кладёт `Pause` поверх `Playing` — игра не сбрасывается. Снятие паузы — `pop`, и снова активна игра.
H: Верхнее состояние стека — то, что сейчас на экране.

Q: Как компилятор помогает не забыть состояние в `switch`?
A: С `-Wall` он предупреждает (`-Wswitch`), если в `switch` по `enum class` обработаны не все значения и нет `default`.
```

## Закрепление прошлых тем

Три вопроса из тем, на которых стоят состояния:

```quiz
В: Тема 3. Что будет, если в `case` забыть `break`?
+ Выполнение «провалится» в следующий `case`
- Ошибка компиляции
- Выполнится только этот `case`
= Иногда это делают нарочно, но чаще это баг. `-Wextra` предупредит о проваливании; нарочное помечают `[[fallthrough]];`.

В: Тема 3. `enum class State { Menu, Play };` и `int s = State::Menu;` — что будет?
+ Ошибка компиляции — `enum class` сам в `int` не превращается
- `s` станет `0`
- `s` станет `1`
= Нужно явно: `static_cast<int>(State::Menu)`. Строгость — плюс: `State` не перепутать с числом.

В: Игры, тема 1. Почему для игры берут `steady_clock`, а не `system_clock`?
+ `steady_clock` никогда не идёт назад
- `steady_clock` точнее показывает дату
- `system_clock` нельзя вычитать
= `system_clock` может перевести пользователь или синхронизация, и тогда кадр получится отрицательным.
```
