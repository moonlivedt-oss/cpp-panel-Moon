### За 30 секунд

- Всех участников хранят в `std::vector<Unit>`; обновление мира — цикл по вектору.
- Урон считают **одной функцией**: `std::max(1, atk - def)` — минимум 1, чтобы бой не зависал.
- Эффект — структура со счётчиком ходов; каждый ход — применить и уменьшить счётчик, закончившиеся убрать.
- Павших убирают **после** обхода: `std::erase_if(v, [](const Unit &u) { return u.hp <= 0; });` (C++20).
- Журнал — `std::deque<std::string>`: новые сообщения в конец, старые — долой с начала.

## Сущность: одна структура на всех

Герой, гоблин и слизень отличаются **числами**, а не устройством. Поэтому — одна структура:

```cpp
struct Unit {
  std::string name;
  int hp = 0;
  int atk = 0;       // атака
  int def = 0;       // защита
  bool alive() const { return hp > 0; }
};

std::vector<Unit> enemies = {
    {"Гоблин", 10, 4, 1},
    {"Скелет", 14, 5, 3},
};
```

Когда поведение **действительно** разное (дракон дышит огнём, лучник стреляет издалека) — пригодится [наследование](../ref/20-nasledovanie.md) или поле-«тип». Но начинать стоит с одной структуры: удивительно много игр на этом и заканчиваются.

## Формула урона

```cpp
int damage(const Unit &attacker, const Unit &target) {
  return std::max(1, attacker.atk - target.def);   // хотя бы 1: иначе при def >= atk бой вечный
}
```

Почему функция, а не `hp -= atk - def` прямо в месте удара: формула обязательно усложнится (криты, стихии, броня), и менять её лучше **в одном месте**. Пара популярных вариантов:

| Формула | Как ведёт себя |
|---|---|
| `max(1, atk - def)` | просто и понятно; защита «съедает» урон целиком |
| `atk * 100 / (100 + def)` | защита снижает урон процентом и никогда не обнуляет его |
| `atk * atk / (atk + def)` | при высокой атаке защита почти не мешает |

## Эффекты с таймером: яд и щит

Эффект — это «что делать каждый ход» + «сколько ходов осталось»:

```cpp
struct Effect {
  std::string name;
  int perTurn = 0;      // урон за ход (отрицательный — лечение)
  int turnsLeft = 0;
};
```

У сущности — вектор эффектов. Каждый ход: применить все, уменьшить счётчики, закончившиеся убрать:

```steps
@id csextbl
# Яд на 3 хода
for (Effect &e : unit.effects) {
    unit.hp -= e.perTurn;
    --e.turnsLeft;
}
std::erase_if(unit.effects, [](const Effect &e) { return e.turnsLeft <= 0; });
---
1 | hp=10, яд (осталось ходов)=3 | Гоблина отравили: 2 урона за ход, 3 хода.
2 | hp=8 | Ход 1: яд жжёт.
3 | яд (осталось ходов)=2 | 
5 | | Эффект ещё не закончился — остаётся.
2 | hp=6 | Ход 2.
3 | яд (осталось ходов)=1 | 
2 | hp=4 | Ход 3.
?3 | яд (осталось ходов)=0 | Сколько ходов яда осталось?
5 | яд (осталось ходов)=— | `erase_if` убрал закончившийся эффект. На следующем ходу яд уже не действует.
```

Щит — тот же механизм: эффект с `perTurn = 0`, а в формуле урона проверяем, есть ли у цели «щит», и делим урон пополам. Новый эффект — это новая **строчка данных**, а не новый кусок кода.

## Убрать павших: ловушка erase в цикле

Хочется удалять мёртвых прямо при обходе:

```cpp
for (std::size_t i = 0; i < enemies.size(); ++i)
  if (enemies[i].hp <= 0)
    enemies.erase(enemies.begin() + i);    // ⚠️ пропускает соседа
```

Посмотри, что происходит, когда двое мёртвых стоят подряд:

```steps
@id c1kjbax
# Почему erase в цикле пропускает элементы
for (std::size_t i = 0; i < v.size(); ++i)
    if (v[i].hp <= 0)
        v.erase(v.begin() + i);
---
1 | v=[Гоблин 0, Скелет 0, Слизень 5], i=0 | Двое мёртвых подряд, слизень жив.
2 | | `v[0]` — гоблин, hp 0 — мёртв.
3 | v=[Скелет 0, Слизень 5] | Удалили. Все, кто был правее, **сдвинулись влево**: скелет теперь на месте 0.
?1 | i=1 | `++i` — какой теперь индекс?
2 | | `v[1]` — это уже **слизень**. Скелет на месте 0 так и не проверен!
1 | i=2 | 2 < 2 — ложь, цикл окончен.
1 | итог=мёртвый скелет остался в бою | Мёртвый скелет будет атаковать дальше. Классический баг.
```

Правильный способ — **сначала** обойти всех, **потом** одним вызовом убрать павших:

```cpp
std::erase_if(enemies, [](const Unit &u) { return !u.alive(); });   // C++20, <vector>
```

`std::erase_if` сам делает всё аккуратно и за один проход. (До C++20 писали связку `v.erase(std::remove_if(...), v.end())` — встретишь в старом коде.)

## Журнал боя

Сообщения «Гоблин бьёт героя на 3» копятся быстро, а на экране нужны последние 5. `std::deque` умеет быстро добавлять в конец и убирать с начала:

```cpp
std::deque<std::string> log;

void say(std::deque<std::string> &log, const std::string &msg) {
  log.push_back(msg);
  if (log.size() > 5) log.pop_front();   // храним только 5 последних
}
```

## Всё вместе: бой с волной врагов

Герой бьёт первого врага в списке, эффекты тикают, живые враги отвечают, павшие убираются. Всё, что выше, — в одной программе:

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Effect {
  std::string name;
  int perTurn = 0;
  int turnsLeft = 0;
};

struct Unit {
  std::string name;
  int hp = 0;
  int atk = 0;
  int def = 0;
  std::vector<Effect> effects;
  bool alive() const { return hp > 0; }
};

int damage(const Unit &attacker, const Unit &target) {
  return std::max(1, attacker.atk - target.def);
}

void tickEffects(Unit &u) {
  for (Effect &e : u.effects) {
    u.hp -= e.perTurn;
    --e.turnsLeft;
    std::cout << "  " << u.name << ": " << e.name << " -" << e.perTurn << "\n";
  }
  std::erase_if(u.effects, [](const Effect &e) { return e.turnsLeft <= 0; });
}

int main() {
  Unit hero{"Герой", 30, 7, 2, {}};
  std::vector<Unit> enemies = {
      {"Гоблин", 10, 4, 1, {}},
      {"Скелет", 14, 5, 3, {}},
      {"Слизень", 6, 2, 0, {}},
  };
  enemies[0].effects.push_back({"яд", 2, 3});   // гоблина отравили ещё до боя

  int turn = 1;
  while (hero.alive() && !enemies.empty()) {
    std::cout << "Ход " << turn++ << "\n";

    Unit &target = enemies.front();            // бьём первого в списке
    int d = damage(hero, target);
    target.hp -= d;
    std::cout << "  Герой бьёт: " << target.name << " -" << d << "\n";

    for (Unit &e : enemies) tickEffects(e);    // эффекты у всех

    for (const Unit &e : enemies) {            // живые отвечают
      if (!e.alive()) continue;
      int hit = damage(e, hero);
      hero.hp -= hit;
      std::cout << "  " << e.name << " бьёт героя: -" << hit << "\n";
    }

    std::erase_if(enemies, [](const Unit &u) { return !u.alive(); });   // павших — после обхода
    std::cout << "  HP героя: " << hero.hp << ", врагов: " << enemies.size() << "\n";
  }
  std::cout << (hero.alive() ? "Победа!\n" : "Поражение...\n");
  return 0;
}
```

Поменяй числа — например, дай скелету `def = 7` (герой будет наносить ему минимум 1) — и посмотри, как меняется исход. Это и есть **балансировка**: игровые дизайнеры часами крутят именно такие числа.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| `erase` внутри цикла по индексу | мёртвые пропускаются и продолжают бить | `std::erase_if` после обхода |
| `erase` внутри range-for | неопределённое поведение (итератор сломан) | то же — `erase_if` после |
| Ссылка на элемент вектора, потом `push_back` | ссылка «висит» после переезда вектора | брать ссылку заново после изменения размера |
| Урон может быть 0 | бой никогда не кончается | `std::max(1, …)` |
| Формула урона скопирована в 5 мест | правка баланса = охота на копии | одна функция `damage` |

## Проверь себя

```quiz
В: Почему павших врагов убирают после обхода, а не во время?
+ Удаление сдвигает элементы, и цикл пропускает соседа (а в range-for — ломает итератор)
- Так быстрее компилируется
- `erase` нельзя вызывать для структур
= `std::erase_if` после обхода убирает всех подходящих за один проход и без пропусков.

В: У героя атака 5, у голема защита 9. Что вернёт `std::max(1, 5 - 9)`?
+ 1
- -4
- 0
= `max` выбирает большее из 1 и −4. Минимальный урон не даёт бою зависнуть.

В: Зачем эффекту поле `turnsLeft`?
+ Чтобы эффект действовал заданное число ходов и потом сам исчезал
- Для красоты вывода
- Чтобы считать урон
= Каждый ход счётчик уменьшается; когда он дошёл до нуля, эффект удаляется `erase_if`.
```

```cards
В: Как в C++20 удалить из вектора все элементы по условию?
О: `std::erase_if(v, условие);` — например, `[](const Unit &u) { return u.hp <= 0; }`.

В: Зачем журналу боя `std::deque`, а не `vector`?
О: `deque` быстро убирает элементы с начала (`pop_front`) — удобно хранить только последние N сообщений.

Q: Как хранить врагов разного типа в одном векторе без наследования?
A: Одна `struct Entity` с полем вида (`enum class Kind`) и общими характеристиками — простой и быстрый путь для небольшой игры.

Q: Почему мёртвых врагов не удаляют прямо в цикле по индексу?
A: Индексы сдвигаются, и следующий элемент пропускается. Сначала бой, потом удаление всех разом: `std::erase_if(enemies, [](const Entity &e) { return e.hp <= 0; });`

Q: Как посчитать урон с учётом брони, чтобы он не ушёл в минус?
A: `int dmg = std::max(0, attack - armor);` — или с минимальным уроном: `std::max(1, attack - armor)`.

Q: Что такое инициатива в пошаговом бою?
A: Порядок ходов: участников сортируют по скорости (`std::sort` с компаратором) и ходят по очереди.
H: Кто быстрее, тот и первый.
```
