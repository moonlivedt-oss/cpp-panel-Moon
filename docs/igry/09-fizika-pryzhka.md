### За 30 секунд

- У героя есть **позиция** `y`, **скорость** `vy` и постоянное **ускорение** — гравитация `g`.
- Каждый шаг физики: сначала `vy -= g * dt`, потом `y += vy * dt`. Именно в таком порядке.
- Прыжок — это не «поднять на 5 клеток», а **дать скорость вверх**: `vy = jumpSpeed`. Дальше гравитация всё сделает сама.
- Приземлился (`y <= земля`) — поставить на землю, обнулить скорость, `onGround = true`. Прыгать можно только с земли.
- Высоту прыжка считают формулой: `h = v² / (2g)`. Хочешь прыжок на 3 клетки — вычисли нужную скорость.

## Позиция, скорость, ускорение

Три величины, каждая меняет следующую:

| Величина | Что это | Пример | Кто её меняет |
|---|---|---|---|
| `y` | где герой | 2.5 клетки над землёй | скорость |
| `vy` | как быстро и куда движется | +8 клеток/с — вверх | ускорение, прыжок |
| `g` | как быстро меняется скорость | 30 клеток/с² — вниз | никто, константа мира |

В жизни так и есть: мяч, подброшенный вверх, сначала летит быстро, замедляется, на миг зависает и падает, всё ускоряясь. Гравитация не двигает мяч напрямую — она **меняет его скорость**.

> **Про направление оси.** Здесь `y` — высота над землёй: вверх — плюс. На экране (в консоли и в большинстве движков 2D) строки считаются **сверху вниз**, и там всё наоборот: прыжок — отрицательная скорость, гравитация — положительная. Выбери одно правило на всю игру и подпиши его комментарием.

## Один шаг физики

Каждый фиксированный шаг (`dt`) делаем два действия:

```cpp
vy -= g * dt;   // 1. гравитация меняет скорость
y  += vy * dt;  // 2. скорость меняет позицию
```

Это называется **полунеявный метод Эйлера**. Если поменять строки местами (сначала позиция по **старой** скорости), прыжок будет чуть неточным и, что хуже, будет зависеть от `dt`. С фиксированным шагом из [темы про время](01-vremya-i-cikl.md#фиксированный-шаг-обновления) физика ведёт себя одинаково на любом компьютере.

Пройди несколько шагов с простыми числами: `dt = 0.1`, `g = 10`, прыжок со скоростью 5:

```steps
@id c117enb1
# Шаги физики: взлёт и вершина
vy -= g * dt;
y += vy * dt;
---
1 | шаг=1, vy=4 | Прыгнули со скоростью 5. Гравитация сразу отняла 10 × 0.1 = 1.
2 | y=0.4 | Сдвиг: 4 × 0.1 = 0.4 клетки вверх.
1 | шаг=2, vy=3 | Скорость падает на 1 каждый шаг.
2 | y=0.7 | 
1 | шаг=3, vy=2 | 
?2 | y=0.9 | Какая будет высота? (0.7 + 2 × 0.1)
1 | шаг=4, vy=1 | Подъём замедляется.
2 | y=1 | 
1 | шаг=5, vy=0 | Скорость ноль — это **вершина** прыжка.
2 | | Высота не изменилась: мы «зависли» на миг, как мяч в верхней точке.
1 | шаг=6, vy=-1 | Скорость стала отрицательной — пошли вниз.
2 | y=0.9 | Падение — зеркало взлёта.
```

## Земля: приземлиться и не провалиться

За один шаг герой может пролететь **ниже** земли (был на высоте 0.3, скорость −8, шаг 0.05 → высота −0.1). Поэтому после шага проверяем и «выталкиваем» обратно:

```cpp
if (y <= 0.0) {        // пересекли землю
  y = 0.0;             // поставить ровно на неё
  vy = 0.0;            // остановить падение
  onGround = true;
} else {
  onGround = false;    // в воздухе
}

if (jumpPressed && onGround) vy = jumpSpeed;   // прыгать можно только с земли
```

Без проверки `onGround` игрок жмёт прыжок в воздухе — и улетает в небо «лестницей». (Если **нужен** двойной прыжок — заведи счётчик прыжков и сбрасывай его при приземлении.)

## Прыжок глазами игрока

Прежде чем считать — посмотри, как прыжок выглядит на экране. Нажми «Играть»: каждый кадр — одно обновление мира. Заметь, что наверху герой **замедляется**, а вниз летит **всё быстрее** — это и есть гравитация, которая каждый шаг уменьшает скорость `vy`.

## Всё вместе: график прыжка

Программа моделирует один прыжок с фиксированным шагом и рисует высоту «графиком»: чем выше герой, тем правее `@`.

```cpp
#include <cmath>
#include <cstddef>
#include <iomanip>
#include <iostream>
#include <string>

int main() {
  const double g = 40.0;          // гравитация, клеток/с²
  const double jumpSpeed = 20.0;  // скорость отрыва, клеток/с
  const double dt = 0.05;         // фиксированный шаг: 20 обновлений в секунду

  double y = 0.0;                 // высота над землёй (вверх — плюс)
  double vy = jumpSpeed;          // прыгнули!
  double t = 0.0;
  bool onGround = false;

  std::cout << std::fixed << std::setprecision(2);
  while (!onGround) {
    vy -= g * dt;                 // 1. гравитация меняет скорость
    y += vy * dt;                 // 2. скорость меняет высоту
    t += dt;
    if (y <= 0.0) {               // приземлились
      y = 0.0;
      vy = 0.0;
      onGround = true;
    }
    int col = static_cast<int>(std::lround(y * 4));   // 1 клетка высоты = 4 символа
    std::cout << "t=" << t << "  y=" << std::setw(4) << y << " |"
              << std::string(static_cast<std::size_t>(col), ' ') << "@\n";
  }
  return 0;
}
```

Запусти — увидишь симметричную «горку»: быстро вверх, замедление, вершина на половине секунды, такое же падение.

```console
t=0.05  y=0.90 |    @
t=0.10  y=1.70 |       @
t=0.15  y=2.40 |          @
t=0.20  y=3.00 |            @
t=0.25  y=3.50 |              @
t=0.30  y=3.90 |                @
t=0.35  y=4.20 |                 @
t=0.40  y=4.40 |                  @
t=0.45  y=4.50 |                  @
t=0.50  y=4.50 |                  @
t=0.55  y=4.40 |                  @
...
```

Формула ниже обещает вершину ровно 5 клеток, а вышло 4.5: шаг 0.05 с довольно крупный, и дискретная модель чуть «срезает» дугу. Уменьши `dt` до 0.01 — вершина станет 4.9. Для игры это не страшно: важно, что прыжок **одинаковый** при любом FPS. Поменяй `g` на 80 — прыжок станет низким и резким, на 20 — высоким и «лунным».

## Прыжок нужной высоты: считаем, а не подбираем

Новички подбирают `jumpSpeed` и `g` наугад часами. Дизайнеры поступают наоборот: решают, **какой** должен быть прыжок, и вычисляют числа.

| Хочу | Формула |
|---|---|
| по `v` и `g` узнать высоту прыжка | `h = v² / (2g)` |
| по `v` и `g` узнать время до вершины | `t = v / g` |
| прыжок высотой `h` за время `t` до вершины | `v = 2h / t`,  `g = 2h / t²` |

Пример: прыжок на 3 клетки, до вершины 0.4 с. Тогда `v = 2·3 / 0.4 = 15`, `g = 2·3 / 0.16 = 37.5`. Подставил — и прыжок ровно такой, как задумано.

```cpp
const double jumpHeight = 3.0;    // клетки — то, что видит игрок
const double timeToApex = 0.4;    // секунды — «лёгкость» прыжка
const double g = 2 * jumpHeight / (timeToApex * timeToApex);
const double jumpSpeed = 2 * jumpHeight / timeToApex;
```

Теперь «поднять прыжок на клетку» — это поменять одно понятное число, а не две магические константы.

Подбери свой прыжок: высота и «лёгкость» — ползунками, числа для кода и траектория по шагам `dt = 0.05` — сразу:

```live
@H = 3 [1..6 step 0.5]
@T = 0.4 [0.2..0.8 step 0.05]
---
const double jumpHeight = {H};    // клетки
const double timeToApex = {T};    // секунды
const double g = {2*H/(T*T)};         // = 2h / t²
const double jumpSpeed = {2*H/T};  // = 2h / t
---
g = {2*H/(T*T)}, скорость прыжка = {2*H/T}
{for i=0..8} через {i*0.05} с высота {(2*H/T)*(i*0.05) - (2*H/(T*T))*(i*0.05)*(i*0.05)/2}
```

## Приятное управление: три хитрости

Честная физика часто ощущается **нечестной**. Игрок уверен, что нажал прыжок вовремя, — а персонаж уже на два кадра сорвался с края. Почти все платформеры тихо помогают игроку:

**1. Время койота (coyote time).** Как койот из мультфильма, который ещё секунду висит над пропастью: прыгнуть можно в течение ~0.1 с **после** того, как герой сошёл с края.

```cpp
if (onGround) coyote = 0.1;       // на земле — «запас» полный
else coyote -= dt;                // в воздухе — тает
if (jumpPressed && coyote > 0) { vy = jumpSpeed; coyote = 0; }
```

**2. Буфер прыжка (jump buffering).** Игрок нажал прыжок **чуть раньше** приземления — не теряем нажатие, а помним его ~0.1 с:

```cpp
if (jumpPressed) buffer = 0.1;    // запомнили нажатие
else buffer -= dt;
if (buffer > 0 && onGround) { vy = jumpSpeed; buffer = 0; }
```

**3. Прыжок разной высоты.** Отпустил кнопку рано — прыжок ниже: срезаем скорость подъёма.

```cpp
if (jumpReleased && vy > 0) vy *= 0.5;   // коротко нажал — низкий прыжок
```

Плюс ограничение скорости падения (`vy = std::max(vy, -maxFall);`), чтобы с большой высоты герой не разгонялся до невидимости. Все четыре — по две-три строки, а разница в ощущении огромная.

## Платформы на сетке: оси по очереди

Когда герой движется и вбок, и по вертикали, столкновения со стенами и платформами проверяют **по одной оси за раз**:

1. Сдвинули по `x` — если попали в стену, вернули `x` обратно (упёрлись в стену).
2. Потом сдвинули по `y` — если попали в блок: при падении — это приземление (`onGround = true`), при взлёте — удар головой (`vy = 0`).

Если двигать сразу по обеим осям, герой, прыгнувший в угол, не поймёт, во что врезался — в стену или в пол, и будет «залипать» или проваливаться сквозь угол.

> 🎮 **В настоящих играх.** Celeste прощает промахи ровно теми хитростями, что в этой теме: прыжок срабатывает ещё несколько кадров после схода с края (coyote time), а нажатие чуть раньше приземления запоминается (буфер прыжка). В Super Mario Bros. высота прыжка зависит от того, сколько держишь кнопку.

## Типовые ошибки

| Ошибка | Что будет | Как надо |
|---|---|---|
| Прыжок как «телепорт» `y += 5` | рывок без дуги, неестественно | `vy = jumpSpeed`, дальше — гравитация |
| Сначала `y += vy*dt`, потом `vy -= g*dt` | прыжок неточный и зависит от FPS | сначала скорость, потом позиция |
| Переменный `dt` в физике | на слабом компьютере прыжок другой высоты | фиксированный шаг |
| Нет проверки `onGround` | бесконечные прыжки в воздухе | прыжок только с земли (или счётчик) |
| `y` в `int` | при скорости 0.7 клетки/шаг герой стоит на месте | `double`, округлять только при рисовании |
