## 42. Отладчик по-взрослому

### За 30 секунд

- Запуск отладки текущего файла — `Ctrl+Alt+D` (C/C++ Runner) или «Debug File» у кнопки запуска. Отладчик — gdb 17.1 из MSYS2.
- **Условная** точка (правый клик по точке → Edit Breakpoint → Expression): остановка только когда `i == 997`, а не на каждом витке.
- **Точка-журнал** (Logpoint): печатает `hp = {hp}` в Debug Console и не останавливает программу. `std::cout` добавлять и потом вычищать не нужно.
- **Watch** — выражение, которое пересчитывается на каждом шаге: `v.size()`, `hp <= 0`, `x * 2 + 1`.
- Упала — окно **Call Stack** показывает цепочку вызовов; клик по строке — переход к ней со всеми переменными того момента.

### План: от симптома к строке

1. **Повтори баг.** Найди самый короткий ввод, на котором ответ неверный (метод — в [«Как ловить баги»](12-lovim-bagi.md)).
2. **Поставь точку до подозрительного места**, а не на нём: смотри, какие данные туда **приходят**.
3. **Сформулируй ожидание** до шага: «после этой строки `sum` должна стать 15». Шагни `F10` и сравни.
4. Первая строка, где ожидание не совпало, — и есть баг. Дальше не шагай: читай эту строку.

Главное — ожидание **до** шага. Без него отладка превращается в разглядывание чисел.

### Условная точка останова

Цикл на 10 000 витков врёт на последних. Нажимать `F5` тысячи раз не надо.

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v(10000);
    for (int i = 0; i < 10000; ++i) v[static_cast<std::size_t>(i)] = i % 7;
    long long sum = 0;
    for (int i = 0; i < 10000; ++i) {
        sum += v[static_cast<std::size_t>(i)];   // точка здесь, условие: i == 9998
    }
    std::cout << sum << "\n";
}
```

Правый клик по красной точке → **Edit Breakpoint…** → **Expression** → `i == 9998`. Программа пробежит 9998 витков сама и остановится ровно там. Вариант **Hit Count** — «остановиться на N-м проходе».

### Точка-журнал вместо `std::cout`

Правый клик по полю номеров строк → **Add Logpoint…** → текст `шаг {step}, HP {hp}`. Фигурные скобки — выражения. Программа не останавливается, а строки появляются в **Debug Console**.

Чем это лучше `std::cout`:
- не надо пересобирать программу и потом вычищать отладочную печать;
- вывод отладки не смешивается с выводом программы (тесты не ломаются);
- точку можно выключить галочкой в панели **Breakpoints**.

### Watch: следить за выражением

Панель **Watch** → `+` → любое выражение из переменных, видимых в этой точке: `hp`, `inventory.size()`, `hp > maxHp`, `static_cast<double>(sum) / n`. После каждого шага значение пересчитывается; изменившееся подсвечивается.

Удобно держать там **инвариант** — то, что всегда должно быть правдой: `hp >= 0 && hp <= maxHp`. Стало `false` — нарушение произошло на последнем шаге.

Вызов функций с побочными эффектами в Watch не пиши (`v.push_back(1)`): отладчик выполнит его по-настоящему.

### Программа упала: стек вызовов

Запусти падающую программу под отладчиком (`Ctrl+Alt+D`), а не обычным запуском. При падении gdb остановится **на строке падения** и покажет **Call Stack**.

```cpp
#include <iostream>
#include <vector>

int lastPositive(const std::vector<int> &v) {
    int i = static_cast<int>(v.size()) - 1;
    while (v[static_cast<std::size_t>(i)] <= 0) --i;   // нет положительных — i уходит в минус
    return v[static_cast<std::size_t>(i)];
}

int main() {
    std::vector<int> data = {-3, -1, -7};
    std::cout << lastPositive(data) << "\n";
}
```

Что делать при остановке:
1. **Call Stack**: верхняя строка — где упало (часто внутри библиотеки: `std::vector::operator[]`). Иди вниз по стеку до **первой своей** функции — клик по ней.
2. **Variables** в этом кадре: `i = -1`, `v.size() = 3`. Причина видна сразу: индекс ушёл за левый край.
3. Исправь условие: `while (i >= 0 && v[...] <= 0)`, а «не нашли» верни отдельно (например, через [`std::optional`](26-variant.md)).

Код выхода `0xC0000005` при обычном запуске — это то же падение; разбор кодов — в [«Ошибках компилятора»](11-oshibki.md).

### Рекурсия: кто кого вызвал

В рекурсии Call Stack — это буквально стопка вызовов: сверху самый глубокий. Клик по любому кадру показывает **его** `n` и **его** локальные переменные.

```cpp
#include <iostream>

long long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // точка здесь, условие n == 2
}

int main() { std::cout << fib(6) << "\n"; }
```

Остановитесь с условием `n == 2` и посмотрите в Call Stack: `fib(2) ← fib(3) ← fib(4) ← fib(5) ← fib(6) ← main`. Видно, что `fib(2)` будет вызвана ещё не раз — так выглядит лишняя работа, которую лечит запоминание.

Переполнение стека (`0xC00000FD`) под отладчиком видно так же: стек из тысяч одинаковых кадров — значит, у рекурсии нет выхода или он недостижим.

### Выход за границы — поймать на месте

`v[i]` за концом вектора не падает сразу — портит память, и упасть может совсем в другом месте. Два способа заставить ошибку проявиться там, где она случилась:

- писать `v.at(i)` вместо `v[i]` в подозрительном месте: выход за границы бросит `std::out_of_range`, отладчик остановится на исключении;
- собирать с `-D_GLIBCXX_ASSERTIONS`: `operator[]` сам проверяет индекс и останавливает программу с сообщением. Это замена санитайзерам, которые в MSYS2 не собираются.

### Программа ждёт ввода

Под отладчиком ввод идёт в терминал программы (вкладка **Terminal**), а не в Debug Console. Если программа «зависла» на старте — скорее всего, она ждёт `std::cin`: переключись в терминал и введи данные.

Для длинного ввода удобнее сразу читать из файла: на время отладки в начале `main` добавь `std::ifstream in("input.txt");` и читай из `in`, а не из `std::cin`.

### Типовые ловушки

| Что видишь | Почему | Как чинить |
|---|---|---|
| переменная `<optimized out>`, шаги прыгают | собрано с оптимизацией | отлаживать сборку без `-O2`, с `-g` (Debug File делает это сам) |
| точка не срабатывает, кружок серый | файл не пересобран или точка на пустой строке | пересобрать и запустить заново; ставить точку на строку с кодом |
| `F11` уходит внутрь `std::vector` | шаг внутрь заходит и в библиотеку | `Shift+F11` — выйти обратно; внутрь своих функций, а не чужих |
| в Debug Console не работает `v[2]` | ограничение gdb (см. [«Основы»](01-osnovy.md#отладчик-увидеть-что-происходит-внутри)) | раскрыть `v` в Variables или `*(v._M_impl._M_start+2)` |
| отладка «ничего не показывает» и сразу закончилась | программа не упала и не остановилась ни на одной точке | поставить точку в начале `main` |

```findbug
int sumTo(int n) {
    int sum = 0;
    for (int i = 1; i < n; ++i)   // точка здесь, Watch: sum
        sum += i;
    return sum;
}
// sumTo(5) должна вернуть 15, а возвращает 10
---
Условие `i < n` не доходит до самого `n`: последний виток пропущен. В Watch видно, что после `i = 4` цикл заканчивается, а `sum` = 10. Нужно `i <= n`.
```

## Рецепты: хочу X → вот код

Ищешь не функцию, а решение задачи — начни отсюда.

- **Остановиться только на нужном витке цикла** — условная точка: Expression `i == 997`. → [условная точка](#условная-точка-останова)
- **Печатать значения, не меняя код** — точка-журнал (Logpoint) `hp = {hp}`. → [точка-журнал](#точка-журнал-вместо-stdcout)
- **Поймать момент, когда значение стало неправильным** — Watch с инвариантом `hp >= 0 && hp <= maxHp`. → [Watch](#watch-следить-за-выражением)
- **Программа упала — где и почему** — запуск под отладчиком и Call Stack. → [стек вызовов](#программа-упала-стек-вызовов)
- **Выход за границы проявляется «где-то потом»** — `v.at(i)` или `-D_GLIBCXX_ASSERTIONS`. → [границы](#выход-за-границы--поймать-на-месте)
- **Отладка зависла на старте** — программа ждёт ввода в терминале. → [ввод](#программа-ждёт-ввода)

## Проверь себя

```cards
Q: Как остановиться в цикле только на 5000-м витке?
A: Условная точка останова: Edit Breakpoint → Expression `i == 4999` (или Hit Count).

Q: Чем точка-журнал (Logpoint) лучше `std::cout` для отладки?
A: Не надо пересобирать и вычищать печать; вывод идёт в Debug Console и не смешивается с выводом программы; выключается галочкой.

Q: Программа упала внутри `std::vector::operator[]`. Что смотреть?
A: Call Stack: спуститься до первой своей функции и в её Variables посмотреть индекс и размер.

Q: Что держать в Watch, чтобы поймать момент поломки?
A: Инвариант — условие, которое всегда должно быть истинно, например `hp >= 0 && hp <= maxHp`.

Q: Почему переменная показывается как `<optimized out>`?
A: Программа собрана с оптимизацией; для отладки нужна сборка с `-g` без `-O2`.

Q: Чем `F10` отличается от `F11`?
A: `F10` выполняет строку целиком (функции внутри — не заходя), `F11` заходит внутрь вызываемой функции.

Q: Что показывает окно Call Stack при остановке в функции?
A: Цепочку вызовов: кто вызвал эту функцию, кто вызвал того — до `main`. Клик по кадру — его переменные.

Q: Как не нажимать `F5` тысячу раз в цикле?
A: Условная точка (Expression `i == 999`) или Hit Count.
```

## Закрепление прошлых тем

Три вопроса из прошлых тем — всё это видно в отладчике:

```quiz
В: Тема 3. Цикл `for (int i = 0; i <= n; ++i)` по вектору из `n` элементов. Что не так?
+ Последний виток выходит за конец вектора
- Первый элемент пропускается
- Всё верно
= `<=` даёт `n + 1` витков; последний индекс — `n - 1`.

В: Тема 4. Функция вызывает сама себя без базы. Что увидишь в Call Stack перед падением?
+ Тысячи одинаковых кадров этой функции
- Один кадр
- Пустой стек
= Рекурсия без выхода растит стек, пока он не кончится.

В: Тема 22. Что происходит при `*p`, где `p == nullptr`?
+ Программа падает (обращение к нулевому адресу)
- Получается 0
- Компилятор не соберёт
= Разыменовывать можно только указатель, который на что-то указывает.
```
