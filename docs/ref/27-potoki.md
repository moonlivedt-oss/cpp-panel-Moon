## 41. Потоки

### За 30 секунд

- Поток — ещё одна «линия выполнения» внутри программы. `main` — первый поток.
- `std::thread t(функция);` запускает, `t.join();` ждёт конца. Забыл `join` — программа аварийно завершится.
- `std::jthread` (C++20) делает `join` сам в деструкторе — начинай с него.
- Два потока меняют одну переменную без защиты — **гонка данных**, неопределённое поведение. Защита: `std::mutex` + `std::lock_guard` или `std::atomic`.
- Нужен результат — `std::async` вернёт `std::future`, `get()` дождётся и отдаст значение.
- Заголовки: `<thread>`, `<mutex>`, `<atomic>`, `<future>`.

### Первый поток и `join`

```cpp
#include <iostream>
#include <thread>

void countTo(int n) {
    long long sum = 0;
    for (int i = 1; i <= n; ++i) sum += i;
    std::cout << "сумма до " << n << " = " << sum << "\n";
}

int main() {
    std::thread worker(countTo, 1000000);   // функция и её аргументы
    std::cout << "main работает дальше\n";
    worker.join();                           // ждём, пока поток закончит
}
```

Порядок двух строк вывода не гарантирован: потоки идут одновременно, кто напечатает первым — решает планировщик.

`std::thread`, у которого не вызвали `join` (или `detach`), при уничтожении завершает всю программу через `std::terminate`. Это частая первая ошибка.

### `std::jthread`: сам дождётся

`std::jthread` — тот же поток, но в деструкторе сам делает `join`. Выйти из функции и «забыть» поток уже нельзя.

```cpp
#include <iostream>
#include <thread>
#include <vector>

int main() {
    std::vector<int> results(4);
    {
        std::vector<std::jthread> pool;
        for (int k = 0; k < 4; ++k) {
            pool.emplace_back([&results, k] {   // каждый поток пишет только в свою ячейку
                int s = 0;
                for (int i = 0; i < 1000; ++i) s += k;
                results[static_cast<std::size_t>(k)] = s;
            });
        }
    }   // здесь все четыре потока дождались сами
    for (int r : results) std::cout << r << " ";
    std::cout << "\n";   // 0 1000 2000 3000
}
```

Здесь общих данных нет: каждый поток пишет в свою ячейку `results[k]`. Это безопасно.

### Гонка данных

Два потока делают `++counter` для одной переменной. `++` — это «прочитать, прибавить, записать». Если потоки сделают это одновременно, одно прибавление потеряется.

```cpp
#include <iostream>
#include <thread>

int main() {
    int counter = 0;
    auto work = [&counter] { for (int i = 0; i < 100000; ++i) ++counter; };   // гонка!
    std::jthread a(work), b(work);
    a.join();
    b.join();
    std::cout << counter << "\n";   // часто меньше 200000, каждый запуск — по-разному
}
```

Это неопределённое поведение: в отладке «работает», в релизе — теряет значения, на другой машине — ещё что-то. Гонку не видно в коде глазами, поэтому правило простое: **общие изменяемые данные — только под защитой**.

### `std::mutex` и `std::lock_guard`

Мьютекс — «замок»: пока один поток его держит, другой ждёт. `std::lock_guard` берёт замок в конструкторе и отпускает в деструкторе — даже если внутри бросили исключение.

```cpp
#include <iostream>
#include <mutex>
#include <string>
#include <thread>
#include <vector>

int main() {
    std::vector<std::string> log;
    std::mutex logMutex;
    auto work = [&](const std::string &who) {
        for (int i = 0; i < 3; ++i) {
            std::lock_guard<std::mutex> lock(logMutex);   // до конца блока — только этот поток
            log.push_back(who + " " + std::to_string(i));
        }
    };
    {
        std::jthread a(work, "A"), b(work, "B");
    }
    std::cout << log.size() << "\n";   // всегда 6
}
```

Держи замок как можно меньше: вычисляй без замка, под замком — только запись в общее.

### `std::atomic` для счётчиков

Для одного числа мьютекс — избыточно. `std::atomic<int>` делает `++` неделимым.

```cpp
#include <atomic>
#include <iostream>
#include <thread>

int main() {
    std::atomic<int> counter{0};
    auto work = [&counter] { for (int i = 0; i < 100000; ++i) ++counter; };
    {
        std::jthread a(work), b(work);
    }
    std::cout << counter << "\n";   // всегда 200000
}
```

### Результат из потока: `std::async`

Когда нужен ответ, а не побочный эффект, — `std::async`. Он возвращает `std::future`; `get()` ждёт и отдаёт значение (или пробрасывает исключение из потока).

```cpp
#include <future>
#include <iostream>
#include <numeric>
#include <vector>

long long sumRange(const std::vector<int> &v, std::size_t from, std::size_t to) {
    return std::accumulate(v.begin() + static_cast<std::ptrdiff_t>(from), v.begin() + static_cast<std::ptrdiff_t>(to), 0LL);
}

int main() {
    std::vector<int> data(1000000, 1);
    std::size_t half = data.size() / 2;
    auto left = std::async(std::launch::async, sumRange, std::cref(data), 0, half);
    long long right = sumRange(data, half, data.size());   // вторую половину — сами
    std::cout << left.get() + right << "\n";                // 1000000
}
```

`std::cref(data)` — передать по константной ссылке: иначе `async` скопировал бы весь вектор.

### Когда потоки не нужны

- Программа ждёт ввода с клавиатуры — поток не ускорит человека.
- Работы мало: запуск потока стоит дороже, чем сложить тысячу чисел.
- Всё упирается в диск или сеть, а не в процессор.
- Код ещё не работает правильно в одном потоке — сначала он, потом скорость.

Измеряй: `std::chrono::steady_clock::now()` до и после — и сравни с одним потоком.

### Типовые ошибки

| Что видишь | Почему | Как чинить |
|---|---|---|
| `terminate called without an active exception` | `std::thread` уничтожен без `join` | `join` перед выходом из области или `std::jthread` |
| результат «плавает» от запуска к запуску | гонка данных | `std::mutex` + `lock_guard` или `std::atomic` |
| программа зависла навсегда | два потока ждут замки друг друга (deadlock) | брать несколько замков одним `std::scoped_lock(m1, m2)` |
| лямбда в потоке видит мусор | захватили по ссылке локальную переменную, которая уже умерла | захватывать по значению или гарантировать, что поток закончится раньше |
| `std::async` не ускорил | без `std::launch::async` задача может выполниться лениво в том же потоке | указать `std::launch::async` |

```findbug
void run() {
    std::thread worker([] { std::cout << "работаю\n"; });
    // функция закончилась
}
---
`std::thread` уничтожается без `join()` — программа аварийно завершится через `std::terminate`. Нужно `worker.join();` перед выходом или `std::jthread`, который дождётся сам.
```

## Рецепты: хочу X → вот код

Ищешь не функцию, а решение задачи — начни отсюда.

- **Запустить работу параллельно и дождаться** — `std::jthread t(f);` — дождётся сам в конце блока. → [jthread](#stdjthread-сам-дождётся)
- **Два потока меняют один счётчик** — `std::atomic<int>`. → [atomic](#stdatomic-для-счётчиков)
- **Два потока пишут в один вектор** — `std::mutex` + `std::lock_guard`. → [mutex](#stdmutex-и-stdlock_guard)
- **Получить результат из другого потока** — `std::async(std::launch::async, f)` и `.get()`. → [async](#результат-из-потока-stdasync)
- **Понять, стоит ли вообще** — сначала замерь, работы должно быть много. → [когда не нужны](#когда-потоки-не-нужны)

## Проверь себя

```cards
Q: Что произойдёт, если `std::thread` уничтожится без `join()`?
A: Программа аварийно завершится через `std::terminate`.

Q: Чем `std::jthread` удобнее `std::thread`?
A: Делает `join` сам в деструкторе — забыть дождаться поток нельзя.

Q: Что такое гонка данных?
A: Два потока одновременно обращаются к одной переменной, и хотя бы один её меняет, без синхронизации. Это неопределённое поведение.
H: Пример — `++counter` из двух потоков.

Q: Зачем `std::lock_guard`, если у мьютекса есть `lock()`/`unlock()`?
A: Он отпустит замок в деструкторе — даже при раннем `return` или исключении.

Q: Как получить значение, посчитанное в другом потоке?
A: `std::async(std::launch::async, f, …)` вернёт `std::future`; `get()` дождётся и отдаст результат.

Q: Почему общий `std::mt19937` нельзя вызывать из нескольких потоков?
A: Генератор меняет своё состояние при каждом вызове — это гонка данных. У каждого потока — свой генератор.

Q: Что такое deadlock?
A: Два потока держат по замку и ждут замок друг друга — оба ждут вечно. Лечится захватом обоих замков сразу: `std::scoped_lock(m1, m2)`.

Q: Как передать в поток большой вектор без копии?
A: По ссылке через `std::cref(v)` / `std::ref(v)` — и следить, чтобы вектор жил дольше потока.
```
