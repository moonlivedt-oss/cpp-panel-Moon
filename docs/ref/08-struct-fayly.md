### За 30 секунд

- `struct` — свой тип из нескольких полей: `struct Point { int x = 0; int y = 0; };` — точка с запятой после `}` обязательна.
- Поле — через точку: `p.x`. Вектор структур — самая частая форма данных в задачах.
- Функции принимают структуру по `const Point &` — без копии.
- Файлы: `std::ifstream in("a.txt")` — читать, `std::ofstream out("b.txt")` — писать; открылся ли — `is_open()`.
- Математика — `<cmath>`: `std::sqrt`, `std::pow`, `std::abs`, `std::round`.

```cpp
struct Student { std::string name; int score = 0; };
std::vector<Student> group = {{"Аня", 90}, {"Борис", 75}};

std::ofstream out("out.txt");
if (!out.is_open()) { /* не удалось открыть */ }
for (const auto &s : group) out << s.name << " " << s.score << "\n";
```

> Здесь три **независимые** мини-темы — `struct`, математика и файлы. Читать можно в любом порядке: друг от друга они не зависят.

Если совсем с нуля: `struct` — это **свой тип** из нескольких полей (точка = x + y, студент = имя + балл). А **файлы** дают программе сохранять результат и читать данные с диска, а не только из консоли.

## 19. `struct`

Когда несколько переменных описывают один объект, их складывают вместе.

```cpp
struct Point {         // struct описывает ТИП, а не переменную
  int x = 0;           // поля со значениями по умолчанию —
  int y = 0;           // чтобы не бывало неинициализированного мусора
};                     // ⚠️ точка с запятой после закрывающей скобки!

int main() {
  Point p;                       // создали переменную типа Point → x = 0, y = 0
  p.x = 3;                       // доступ к полю через точку
  p.y = 4;

  Point q{10, 20};               // сразу со значениями: x = 10, y = 20
  std::cout << q.x << "," << q.y;   // → 10,20
}
```

<details>
<summary>Разбор: что за команды при работе со struct</summary>

- **`struct Point { int x = 0; int y = 0; };`** — описываем новый **тип** `Point`: «объект с двумя полями `x` и `y`». Это ещё не переменная, а чертёж. `= 0` — значения полей по умолчанию. **Точка с запятой** после `}` обязательна.
- **`Point p;`** — создаём переменную типа `Point`; поля получат значения по умолчанию (`0, 0`).
- **`p.x = 3;`** — доступ к полю через точку: `имя_переменной.имя_поля`.
- **`Point q{10, 20};`** — создать и сразу заполнить поля по порядку: `x = 10`, `y = 20`.

</details>

<details>
<summary>Копнуть глубже: как `struct` лежит в памяти</summary>

`struct` не добавляет никакой «обёртки» и не хранит имена полей — это способ сказать компилятору: «положи эти переменные в памяти **подряд**, одним куском». `Point{10, 20}` — это буквально два `int` (по 4 байта) друг за другом, всего 8 байт; `p.x` компилятор превращает в «возьми по адресу `p`», а `p.y` — «по адресу `p` плюс 4 байта». Никакого поиска по имени во время работы нет: смещения всех полей известны ещё при компиляции. И сама переменная типа `Point` — обычная **значимая** переменная, как `int`: она целиком лежит там же, где объявлена (для локальной — на стеке), а при `Point b = a;` копируются оба поля.

Одна тонкость — **выравнивание** (alignment). Процессор быстрее читает данные с «круглых» адресов, поэтому компилятор иногда вставляет между полями невидимые байты-заполнители. Из-за этого `sizeof` структуры бывает **больше** суммы размеров полей: `struct { char c; int n; };` занимает не 5 байт, а 8 — после однобайтового `char` добавляются 3 пустых байта, чтобы `int` начинался с адреса, кратного 4. На учебных задачах это не мешает, но объясняет, почему размер структуры порой «неожиданный».

</details>

### Структуры и функции

```cpp
double dist(const Point &a, const Point &b) {      // const & — не копируем и не меняем
  int dx = a.x - b.x;
  int dy = a.y - b.y;
  return std::sqrt(1.0 * dx * dx + 1.0 * dy * dy);   // 1.0 * — чтобы считать в double
}

void movePoint(Point &p, int dx, int dy) {         // & — меняем оригинал
  p.x += dx;
  p.y += dy;
}

Point makePoint(int x, int y) {                    // возврат по значению — нормально
  Point p;
  p.x = x;
  p.y = y;
  return p;
}

Point a{0, 0};
Point b{3, 4};
std::cout << dist(a, b) << "\n";     // → 5
movePoint(a, 1, 1);
std::cout << a.x << "," << a.y;      // → 1,1
```

struct Pos { int x = 0; int y = 0; };
int steps(Pos a, Pos b) { return std::abs(a.x - b.x) + std::abs(a.y - b.y); }   // по клеткам, без диагоналей

Pos exitCell{9, 4}, hero{1, 1}, monster{7, 3};
std::cout << (steps(hero, exitCell) < steps(monster, exitCell) ? "герой" : "монстр") << "\n";
```

```

### Методы — функции внутри структуры

```cpp
struct Rectangle {
  double width = 0;
  double height = 0;

  double area() const {              // const = «этот метод ничего не меняет»
    return width * height;           // поля видны без всякого префикса
  }

  double perimeter() const {
    return 2 * (width + height);
  }

  void scale(double k) {             // без const — потому что меняет поля
    width *= k;
    height *= k;
  }
};

Rectangle r{3.0, 4.0};
std::cout << r.area() << "\n";       // → 12
r.scale(2.0);
std::cout << r.area() << "\n";       // → 48
```

<details>
<summary>Разбор: методы и загадочное `const`</summary>

- **`double area() const { … }`** — **метод**: функция, живущая внутри структуры. Поля (`width`, `height`) видны ей напрямую, без префикса.
- **`const` после скобок** — обещание «этот метод ничего в объекте не меняет, только читает». `area` и `perimeter` лишь считают — поэтому `const`.
- **`void scale(double k)`** — без `const`, потому что меняет поля (`width *= k`). Ставить `const` на такой метод нельзя.
- **`r.area()`, `r.scale(2.0)`** — вызов метода через точку у переменной, как обращение к полю, но со скобками.

Правило: метод только читает — помечай `const`; метод меняет объект — без `const`.

</details>

Как только у структуры появляются методы — ты уже пишешь классы, просто с открытыми полями.

### Сравнение и печать структуры

Две частые задачи со своим типом: **сравнить** два объекта и **напечатать** объект через `<<`, как встроенное число. И то и другое пишется коротко.

```cpp
#include <iostream>

struct Point {
  int x = 0;
  int y = 0;
  bool operator==(const Point &) const = default;   // C++20: сравнение по ВСЕМ полям — само
};

// Печать своего типа: свободная функция operator<< с потоком слева.
std::ostream &operator<<(std::ostream &os, const Point &p) {
  return os << "(" << p.x << ", " << p.y << ")";
}

int main() {
  Point a{1, 2};
  Point b{1, 2};
  Point c{3, 4};

  std::cout << (a == b) << "\n";        // → 1   все поля совпали
  std::cout << (a == c) << "\n";        // → 0
  std::cout << a << " " << c << "\n";   // → (1, 2) (3, 4)   сработал наш operator<<
  return 0;
}
```

`= default` у `operator==` (C++20) говорит компилятору «сравнивай по всем полям сам» — не надо перечислять их руками. А `operator<<` один раз описывает, как тип выглядит на экране, — дальше его можно печатать где угодно, включая контейнеры. Сравнение `==` заодно позволяет искать структуру через `std::find`; для ключа `map` нужен `operator<` — см. [свой struct как ключ](06-konteynery.md#свой-struct-как-ключ).

### Вектор структур: полный рабочий пример

```cpp
struct Student {
  std::string name;
  int score = 0;
};

std::vector<Student> group;

// Заполнение
group.push_back({"Аня", 95});
group.push_back({"Борис", 70});
group.push_back({"Вика", 88});

// Средний балл
int sum = 0;
for (const auto &s : group)
  sum += s.score;
double avg = static_cast<double>(sum) / static_cast<double>(group.size());
std::cout << "Средний: " << avg << "\n";              // → Средний: 84.3333

// Кто выше среднего
std::cout << "Выше среднего: ";
for (const auto &s : group)
  if (s.score > avg)
    std::cout << s.name << " ";                       // → Аня Вика
std::cout << "\n";

// Сортировка по убыванию балла
std::sort(group.begin(), group.end(),
          [](const Student &a, const Student &b) { return a.score > b.score; });

// Вывод таблицей
for (const auto &s : group)
  std::cout << std::setw(10) << s.name << std::setw(5) << s.score << "\n";
// →        Аня   95
// →       Вика   88
// →      Борис   70
```

> **Что запомнить.** `struct` собирает связанные поля в один тип. Значения по умолчанию задавай прямо в полях, метод, который только читает, помечай `const`, в функции передавай по `const &`.

## 20. Математика

```cpp
#include <cmath>              // для дробных
#include <cstdlib>            // для целых

std::cout << std::sqrt(16.0) << "\n";     // → 4      корень
std::cout << std::pow(2.0, 10) << "\n";   // → 1024   степень
std::cout << std::abs(-2.5) << "\n";      // → 2.5    модуль (double, из <cmath>)
std::cout << std::abs(-5) << "\n";        // → 5      модуль (int, из <cstdlib>)

std::cout << std::round(3.6) << "\n";     // → 4   к ближайшему
std::cout << std::floor(3.6) << "\n";     // → 3   вниз
std::cout << std::ceil(3.2) << "\n";      // → 4   вверх
std::cout << std::trunc(3.9) << "\n";     // → 3   отбросить дробную часть
```

> `abs` живёт в двух заголовках: для `int` — в `<cstdlib>`, для `double` — в `<cmath>`. Подключи оба и не думай об этом.

### Формулы, которые нужны постоянно

```cpp
// Сумма чисел от 1 до n
long long sum = 1LL * n * (n + 1) / 2;               // 1LL — от переполнения

// Високосный год
bool leap = (y % 400 == 0) || (y % 4 == 0 && y % 100 != 0);

bool even = (n % 2 == 0);

int withoutLast = n / 10;                // число без последней цифры

// Проценты
double part = 100.0 * count / total;     // 100.0 — чтобы не было целочисленного деления

// Среднее
double avg = static_cast<double>(sum) / count;

// Расстояние между точками
double d = std::sqrt(1.0 * dx * dx + 1.0 * dy * dy);

// Наибольший общий делитель — уже есть в стандартной библиотеке (C++17, <numeric>)
std::cout << std::gcd(12, 18) << "\n";   // → 6    наибольший общий делитель
std::cout << std::lcm(4, 6) << "\n";     // → 12   наименьшее общее кратное

// Как он устроен внутри — алгоритм Евклида. Написать один раз полезно, дальше бери std::gcd
int myGcd(int a, int b) {
  while (b != 0) {
    int t = a % b;      // остаток от деления
    a = b;              // сдвигаем пару: делитель становится делимым,
    b = t;              // остаток — новым делителем
  }
  return a;             // когда остаток стал нулём, ответ в a
}
std::cout << myGcd(12, 18);              // → 6

// Загнать значение в границы — std::clamp(x, lo, hi) из <algorithm>
std::cout << std::clamp(15, 1, 10) << "\n";   // → 10   (подробно — раздел 5)
```

### Мин/макс, `hypot` и ловушка `pow`

**Максимум и минимум из нескольких значений** — через фигурные скобки, не вкладывая `max` в `max`:

```cpp
#include <algorithm>

int a = 3, b = 9, c = 5;
std::cout << std::max({a, b, c}) << "\n";   // → 9   вместо max(a, max(b, c))
std::cout << std::min({a, b, c}) << "\n";   // → 3
```

**Расстояние между точками — `std::hypot`** вместо `sqrt(dx*dx + dy*dy)`: короче и не переполняется по дороге на больших числах:

```cpp
double dx = 3.0, dy = 4.0;
std::cout << std::hypot(dx, dy) << "\n";    // → 5
```

**Ловушка `std::pow` для целых степеней.** `pow` считает в `double` и иногда возвращает не ровно `100`, а `99.9999…` — после `static_cast<int>` это превращается в `99`:

```cpp
int wrong = static_cast<int>(std::pow(10, 2));   // ⚠️ иногда 99, а не 100
int right = 10 * 10;                             // ✅ целую степень — умножением
long long p = 1;                                 // ✅ или циклом для любой степени
for (int i = 0; i < 5; ++i)
  p *= 10;                                       // p == 100000, точно
```

`std::pow` — для **дробных** степеней и вещественных расчётов. Возводишь целое в целую степень и ждёшь точный `int` — умножай сам.

### Случайные числа

```cpp
#include <random>

std::random_device rd;                          // источник настоящей случайности
std::mt19937 gen(rd());                         // генератор, засеянный от него
std::uniform_int_distribution<int> dist(1, 6);  // равномерно от 1 до 6 включительно

for (int i = 0; i < 5; ++i)
  std::cout << dist(gen) << " ";                // → 3 6 1 4 4   (каждый запуск свои)
```

```cpp alt: Бросок кубика d20 для атаки
std::mt19937 rng(std::random_device{}());
std::uniform_int_distribution<int> d20(1, 20);
int roll = d20(rng);
std::cout << (roll == 20 ? "Критический удар!" : roll >= 10 ? "Попадание" : "Промах") << " (" << roll << ")\n";
```

```cpp alt: Случайный вопрос для самопроверки
std::vector<std::string> questions = {"Что такое ссылка?", "Чем vector лучше массива?", "Зачем const &?"};
std::mt19937 rng(std::random_device{}());
std::uniform_int_distribution<std::size_t> pick(0, questions.size() - 1);
std::cout << questions[pick(rng)] << "\n";
```

Старый `rand()` из `<cstdlib>` работает, но распределение у него хуже. Для учебных задач разницы нет, для чего-то серьёзного бери `<random>`.

### Перемешать колоду и вероятности

Тем же генератором делают ещё две частые в играх вещи: случайный дробный (для «событий с вероятностью») и **перемешивание** вектора — `std::shuffle` из `<algorithm>`:

```cpp
#include <algorithm>          // std::shuffle
#include <iostream>
#include <random>
#include <vector>

int main() {
  std::mt19937 gen(std::random_device{}());          // генератор создаём ОДИН раз
  std::uniform_real_distribution<double> chance(0.0, 1.0);

  std::cout << (chance(gen) < 0.3) << "\n";          // событие с шансом 30% → 1 или 0

  std::vector<int> deck = {1, 2, 3, 4, 5, 6};
  std::shuffle(deck.begin(), deck.end(), gen);       // перемешать «колоду»
  for (int card : deck)
    std::cout << card << " ";                        // → случайный порядок
  std::cout << "\n";
  return 0;
}
```

> Генератор (`gen`) создавай **один раз** — в `main` или как `static` внутри функции, — а не на каждый вызов. Если пересоздавать его в цикле, засев может совпасть, и «случайные» числа пойдут одинаковыми. `std::shuffle` берёт тот же `gen` третьим аргументом (устаревший `std::random_shuffle` из старых учебников удалён в C++17).

> **Что запомнить.** Математика — из `<cmath>`: `std::sqrt`, `std::pow`, `std::abs`. Дробные сравнивай с допуском, корень из отрицательного числа даёт `nan`.

## 21. Файлы

Файл — тот же поток, что `cin` и `cout`, только привязанный к диску. Всё, что ты знаешь про `>>` и `getline`, работает и здесь.

### Сначала — главная ловушка на твоей сборке

> **Как надо.** Открылся ли файл — проверяй через `is_open()`: `if (!in.is_open()) { std::cout << "Файл не найден\n"; return 1; }`.

Почти во всех учебниках проверка открытия файла записана так:

```cpp
std::ifstream in("input.txt");
if (!in) {                        // ❌ на твоём g++ (MSYS2 UCRT64) это НЕ СРАБОТАЕТ
  std::cout << "Файл не найден\n";
  return 1;
}
```

Проверено на твоём компиляторе: для **несуществующего** файла поток даёт `is_open() = 0`, но при этом `fail() = 0`, и `if (!in)` считает, что всё хорошо. Программа спокойно идёт дальше, ничего не читает и выдаёт «0 строк» вместо честного «файла нет».

```cpp
std::ifstream in("input.txt");
if (!in.is_open()) {              // ✅ так работает всегда
  std::cout << "Файл не найден\n";
  return 1;
}
```

**Правило: проверяй открытие через `is_open()`.** То же самое для записи — `if (!out.is_open())`. Это единственное место в справочнике, где совет расходится с большинством учебников, и расходится намеренно: `is_open()` верен и там, и здесь.

```badgood

                  // не записаться
---
#include <fstream>

out << score << "\n";
// закроется сам в конце блока —
// забыть нельзя
```

### Запись

```cpp
#include <fstream>

std::ofstream out("output.txt");        // o = output, открыли на запись
                                        // ⚠️ если файл был — его содержимое СТИРАЕТСЯ

if (!out.is_open()) {                   // проверка обязательна: путь может быть недоступен
  std::cout << "Не удалось открыть файл на запись\n";
  return 1;
}

out << "Результат: " << 42 << "\n";     // пишем ровно как в cout
out << "Вторая строка\n";
// файл закроется сам при выходе из области видимости
```

<details>
<summary>Разбор: что за команды при работе с файлом</summary>

- **`#include <fstream>`** — подключает файловые потоки (`ifstream`, `ofstream`).
- **`std::ofstream out("output.txt");`** — открыть файл **на запись**. `ofstream` = *output* stream, буква **o** — «пишем». Файла не было — создастся; был — **старое содержимое стирается**. Дальше `out` работает точно как `std::cout`.
- **`if (!out.is_open())`** — проверка, что файл правда открылся (путь мог быть недоступен). Для файлов проверяй именно `is_open()` — почему, см. ловушку выше.
- **`out << "Результат: " << 42 << "\n";`** — пишем в файл тем же `<<`, что и в консоль.
- **Закрывать вручную не нужно** — файл закроется сам, когда `out` выйдет из области видимости (это RAII). Для чтения всё зеркально: `std::ifstream in(…)`, буква **i** — *input*, и читаем через `>>` / `getline`, как из `std::cin`.

</details>

### Чтение

```cpp
std::ifstream in("input.txt");          // i = input, открыли на чтение

if (!in.is_open()) {
  std::cout << "Файл не найден\n";
  return 1;
}

// Вариант 1: числа по одному
int x = 0;
int sum = 0;
while (in >> x)                         // цикл кончится на конце файла или на нечисле
  sum += x;
std::cout << "Сумма: " << sum << "\n";

// Вариант 2: строки целиком
std::string line;
int number = 1;
while (std::getline(in, line)) {        // читаем, пока строки есть
  std::cout << number << ": " << line << "\n";
  ++number;
}
```

Как `while (in >> x)` читает файл и почему цикл сам останавливается — по шагам. Пусть в `input.txt` лежит `5 7 abc 3`:

```steps
@id cvg0kmb
# Чтение чисел до конца (или до мусора)
std::ifstream in("input.txt");
int x = 0, sum = 0;
while (in >> x)
    sum += x;
std::cout << "Сумма: " << sum;
---
1 | файл=▸5 7 abc 3, in=открыт | Файл открыт, «курсор чтения» (▸) — в самом начале.
2 | x=0, sum=0 |
3 | x=5, файл=5 ▸7 abc 3 | `in >> x` прочитал 5 и сдвинул курсор. Чтение удалось — условие истинно.
4 | sum=5 |
3 | x=7, файл=5 7 ▸abc 3 | Прочитали следующее число.
?4 | sum=12 |
3 | in=сломан (fail) | `abc` — не число! Чтение не удалось, поток «сломался», условие **ложно**. Число 3 после мусора так и не прочитано.
5 | | Печатаем то, что успели сложить. | Сумма: 12
```

Мораль: цикл `while (in >> x)` останавливается и на конце файла, и на первом «не числе». Если в файле может быть мусор — после цикла проверяйте `in.eof()`: `false` значит «остановились не на конце».

### Полный пример: посчитать статистику файла

```cpp
#include <fstream>
#include <iostream>
#include <string>

int main() {
  std::ifstream in("data.txt");
  if (!in.is_open()) {
    std::cout << "Файл не открылся\n";
    return 1;
  }

  int lines = 0;
  int words = 0;
  std::string line;

  while (std::getline(in, line)) {        // построчно
    ++lines;
    bool inWord = false;                  // флаг «мы внутри слова»
    for (char c : line) {
      if (c == ' ' || c == '\t') {
        inWord = false;                   // пробел — слово кончилось
      } else if (!inWord) {
        inWord = true;                    // начался новый непробельный участок
        ++words;                          // считаем его один раз
      }
    }
  }

  std::cout << "Строк: " << lines << ", слов: " << words << "\n";
  return 0;
}
```

### Папки и файлы: `std::filesystem`

`<fstream>` читает и пишет **содержимое** файла. А узнать, есть ли файл, создать папку для сохранений или перечислить все сохранения — это `std::filesystem` (C++17).

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>

namespace fs = std::filesystem;   // короткое имя вместо длинного

int main() {
  fs::path dir = "saves";
  fs::create_directories(dir);                         // создать папку (если её нет)
  std::ofstream(dir / "slot1.txt") << "hp 30\n";       // «/» склеивает части пути

  if (fs::exists(dir / "slot1.txt"))
    std::cout << "Размер: " << fs::file_size(dir / "slot1.txt") << " байт\n";

  for (const auto &entry : fs::directory_iterator(dir))   // все файлы папки
    if (entry.path().extension() == ".txt")
      std::cout << entry.path().filename().string() << "\n";
}
```

| Нужно | Как |
|---|---|
| есть ли файл | `fs::exists(p)` |
| создать папку со всеми родителями | `fs::create_directories(p)` |
| размер | `fs::file_size(p)` |
| удалить | `fs::remove(p)` |
| все файлы папки | `fs::directory_iterator(dir)` |
| имя без пути, расширение | `p.filename()`, `p.extension()` |

Операции над диском бросают `fs::filesystem_error`, если что-то пошло не так (нет прав, диска). Для проверок «спросить, а не падать» у функций есть вариант с `std::error_code` последним аргументом.

Программа ищет `input.txt` в **рабочей директории**, а это не всегда папка с `.exe`. В VS Code с `C/C++ Runner` рабочая директория — папка проекта. Если файл «не находится»:

> Файлы закрываются сами при выходе из области видимости — это RAII, главная идея C++. Явный `in.close()` нужен редко: например, если хочешь тут же открыть тот же файл на запись.

> **Что запомнить.** `std::ifstream` читает, `std::ofstream` пишет и стирает старое содержимое (`std::ios::app` — дописывает). Сразу после открытия проверь `is_open()`. Читай в условии цикла — `while (std::getline(in, line))`, а не `while (!in.eof())`. Файл закроется сам.

## Мини-проект: таблица результатов в файле

`struct`, вектор структур, сортировка и файлы — вместе. Программа помнит результаты между запусками: читает таблицу из `results.txt`, добавляет нового игрока, сортирует по очкам и записывает обратно.

```cpp {43-48}
#include <windows.h>
#include <algorithm>
#include <format>
#include <fstream>
#include <iostream>
#include <string>
#include <vector>

struct Result {
  std::string name;
  int points = 0;
};

// Записать таблицу в файл: имя и очки через пробел, по строке на игрока.
bool saveResults(const std::string &path, const std::vector<Result> &rows) {
  std::ofstream out(path);
  if (!out.is_open()) return false;
  for (const auto &r : rows) out << r.name << " " << r.points << "\n";
  return true;
}

// Прочитать обратно. Файла нет — пустая таблица.
std::vector<Result> loadResults(const std::string &path) {
  std::vector<Result> rows;
  std::ifstream in(path);
  Result r;
  while (in >> r.name >> r.points) rows.push_back(r);
  return rows;
}

int main() {
  SetConsoleCP(CP_UTF8);
  SetConsoleOutputCP(CP_UTF8);

  const std::string path = "results.txt";
  std::vector<Result> table = loadResults(path);
  std::cout << "В файле было записей: " << table.size() << "\n";

  Result fresh;
  std::cout << "Имя и очки нового игрока: ";
  if (std::cin >> fresh.name >> fresh.points) table.push_back(fresh);

  std::sort(table.begin(), table.end(),
            [](const Result &a, const Result &b) { return a.points > b.points; });

  std::cout << "\n  # | Игрок      | Очки\n";
  for (std::size_t i = 0; i < table.size(); ++i)   // format считает буквы, а не байты — столбцы ровные
    std::cout << std::format("{:>3} | {:<10} | {:>4}\n", i + 1, table[i].name, table[i].points);

  if (!saveResults(path, table)) std::cout << "Не удалось записать " << path << "\n";
  return 0;
}
```

Что здесь из темы: **свой тип** `Result`; **функции, которые принимают и возвращают вектор структур**; проверка **`is_open()`** при записи (на твоей сборке `if (!out)` отсутствие файла не ловит — см. [файлы](#21-файлы)); чтение «пока читается» — `while (in >> …)`: нет файла — цикл просто не выполнится, и таблица пустая; сортировка по полю лямбдой; ровные столбцы через `std::format` — он, в отличие от `setw`, считает русские буквы правильно ([почему](02-vvod-vyvod.md#почему-это-важно-именно-для-русских-таблиц)).
