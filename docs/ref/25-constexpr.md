## 39. constexpr

> **Коротко это уже было:** `constexpr`-константа — в [«Основах»](01-osnovy.md#constexpr-константа-времени-компиляции), `constexpr`-функция — в [«Функциях»](04-funkcii.md#constexpr-функции-вычисления-на-этапе-компиляции). Здесь — всё целиком.

### За 30 секунд

- `constexpr` у переменной: значение **обязано** быть известно при сборке. Не получилось — ошибка компиляции, а не сюрприз при запуске.
- `constexpr` у функции: её **можно** вызвать при сборке (если аргументы известны), а можно и обычным образом.
- `consteval` — функцию **нужно** вызвать при сборке; с данными из `std::cin` её не вызвать.
- `static_assert(условие, "текст")` — проверка, которая роняет сборку, если условие ложно.
- `if constexpr` — ветка шаблона выбирается при сборке, ненужная даже не компилируется.

### `const` и `constexpr` — не одно и то же

`const` значит «после инициализации не меняется». Значение при этом может прийти откуда угодно — хоть с клавиатуры. `constexpr` строже: значение должно быть посчитано **до запуска**.

```cpp
#include <iostream>

int main() {
    int n = 0;
    std::cin >> n;
    const int a = n * 2;        // можно: const, но значение станет известно только при запуске
    constexpr int b = 60 * 60;  // можно: 3600 известно при сборке
    // constexpr int c = n * 2; // ошибка: n не известно при сборке
    std::cout << a + b << "\n";
}
```

Где это важно: размер `std::array`, аргумент шаблона, метка `case` — там нужно число, известное при сборке.

```cpp
#include <array>
#include <iostream>

constexpr int kRows = 3;
constexpr int kCols = 4;

int main() {
    std::array<int, kRows * kCols> cells{};   // размер — выражение из constexpr
    std::cout << cells.size() << "\n";        // 12
}
```

### `constexpr`-функция

Обычная функция с пометкой `constexpr`. Если все аргументы известны при сборке и результат нужен как константа — компилятор посчитает его сам. Иначе функция работает как обычная.

```cpp
#include <iostream>

constexpr int square(int x) { return x * x; }

int main() {
    constexpr int area = square(12);   // посчитано при сборке: в программе уже лежит 144
    int side = 0;
    std::cin >> side;
    std::cout << area << " " << square(side) << "\n";   // square(side) — при запуске
}
```

В `constexpr`-функции можно почти всё, что в обычной: циклы, `if`, локальные переменные. Нельзя то, что при сборке не сделать: ввод-вывод, `new` без парного `delete`, статические переменные.

```cpp
#include <iostream>

constexpr long long factorial(int n) {
    long long r = 1;
    for (int i = 2; i <= n; ++i) r *= i;
    return r;
}

int main() {
    constexpr long long f10 = factorial(10);
    std::cout << f10 << "\n";   // 3628800
}
```

### `static_assert`: проверка при сборке

`static_assert` — как `assert`, но срабатывает **до запуска**. Им фиксируют договорённости, которые код молча предполагает.

```cpp
#include <cstdint>

constexpr int kMaxLevel = 20;
constexpr int kHpPerLevel = 5;

static_assert(kMaxLevel * kHpPerLevel <= 200, "максимальное HP не влезет в полосу здоровья");
static_assert(sizeof(std::int32_t) == 4, "нужен 32-битный int32_t");

int main() {}
```

Поменял `kMaxLevel` на 50 — программа не соберётся, и текст ошибки скажет почему. Ошибка при сборке дешевле ошибки у игрока.

### `consteval`: только при сборке

`consteval` (C++20) — «немедленная» функция: каждый её вызов обязан посчитаться при сборке. Удобно для значений, которые **нельзя** случайно начать считать при запуске.

```cpp
#include <iostream>

consteval int kilobytes(int n) { return n * 1024; }

int main() {
    constexpr int buffer = kilobytes(64);
    std::cout << buffer << "\n";   // 65536
    // int n = 0; std::cin >> n; kilobytes(n);   // ошибка: n не известно при сборке
}
```

### `if constexpr` в шаблонах

В шаблоне обычный `if` компилирует **обе** ветки для любого `T`. Если одна ветка для этого типа не имеет смысла — ошибка. `if constexpr` выбрасывает ненужную ветку ещё при сборке.

```cpp
#include <iostream>
#include <string>
#include <type_traits>

template <typename T>
std::string describe(const T &value) {
    if constexpr (std::is_integral_v<T>) {
        return "целое: " + std::to_string(value);
    } else if constexpr (std::is_same_v<T, std::string>) {
        return "строка длины " + std::to_string(value.size());
    } else {
        return "что-то другое";
    }
}

int main() {
    std::cout << describe(42) << "\n" << describe(std::string("abc")) << "\n" << describe(3.5) << "\n";
}
```

С обычным `if` вызов `describe(3.5)` не собрался бы: `std::to_string` пришлось бы компилировать и для ветки со строкой, где у `double` нет `.size()`.

### Таблица, посчитанная заранее

`constexpr`-функция может вернуть целый `std::array`. Таблица ляжет в программу готовой — при запуске её не надо строить.

```cpp
#include <array>
#include <iostream>

// Опыт до следующего уровня: 100, 150, 225, … (каждый раз в полтора раза больше)
constexpr std::array<int, 10> makeXpTable() {
    std::array<int, 10> t{};
    int need = 100;
    for (int &x : t) {
        x = need;
        need = need * 3 / 2;
    }
    return t;
}

constexpr auto kXp = makeXpTable();
static_assert(kXp[0] == 100 && kXp[1] == 150, "таблица опыта посчитана неверно");

int main() {
    for (int x : kXp) std::cout << x << " ";
    std::cout << "\n";
}
```

### Типовые ошибки

| Что видишь | Почему | Как чинить |
|---|---|---|
| `the value of 'n' is not usable in a constant expression` | `constexpr`-переменной дали значение, известное только при запуске | нужна константа — сделай источник `constexpr`; не нужна — пиши `const` |
| `call to consteval function ... is not a constant expression` | `consteval` вызвана с данными из ввода | используй `constexpr`-функцию: её можно звать и при запуске |
| `static assertion failed` | правило в `static_assert` нарушено | это и есть смысл проверки: прочитай текст и поправь константу |
| `if constexpr` не помогает вне шаблона | ветка всё равно компилируется | отбрасывание веток работает только в шаблонах |

## Рецепты: хочу X → вот код

Ищешь не функцию, а решение задачи — начни отсюда.

- **Размер массива из формулы** — `constexpr int kCells = kRows * kCols; std::array<int, kCells> a{};`. → [const и constexpr](#const-и-constexpr--не-одно-и-то-же)
- **Посчитать значение при сборке** — `constexpr`-функция и `constexpr`-переменная с её результатом. → [constexpr-функция](#constexpr-функция)
- **Запретить сборку, если нарушено правило** — `static_assert(условие, "текст");`. → [static_assert](#static_assert-проверка-при-сборке)
- **Гарантировать расчёт только при сборке** — `consteval`. → [consteval](#consteval-только-при-сборке)
- **Разное поведение шаблона для разных типов** — `if constexpr (std::is_integral_v<T>)`. → [if constexpr](#if-constexpr-в-шаблонах)
- **Таблица опыта или урона без расчёта при запуске** — `constexpr`-функция возвращает `std::array`. → [таблица](#таблица-посчитанная-заранее)

## Проверь себя

```cards
Q: Чем `constexpr int x = …;` отличается от `const int x = …;`?
A: `const` — только «не меняется после инициализации», значение может прийти при запуске. `constexpr` — значение обязано быть известно при сборке.

Q: Можно ли вызвать `constexpr`-функцию с числом из `std::cin`?
A: Да. Тогда она просто выполнится при запуске, как обычная. При сборке она считается, только если аргументы известны заранее.

Q: Что делает `static_assert`?
A: Проверяет условие при сборке. Ложно — программа не соберётся, в ошибке будет твой текст.

Q: Зачем `consteval`, если есть `constexpr`?
A: `consteval` гарантирует, что вызов посчитан при сборке: случайно начать считать это при запуске не получится.

Q: Почему в шаблоне нужен `if constexpr`, а не `if`?
A: Обычный `if` компилирует обе ветки для каждого типа. `if constexpr` отбрасывает ненужную ветку, и код, бессмысленный для этого типа, не компилируется.
H: Пример: `.size()` у `double` не существует.

Q: Можно ли внутри `constexpr`-функции читать `std::cin`?
A: Нет: при сборке ввода нет. `constexpr`-функцию с вводом не вызвать при сборке — компилятор откажет.

Q: Где обязательно нужна константа времени компиляции?
A: Размер `std::array`, аргумент шаблона, метка `case`, условие `static_assert`.

Q: Чем `if constexpr` отличается от обычного `if` вне шаблона?
A: Вне шаблона — почти ничем: обе ветки всё равно компилируются. Отбрасывание веток работает в шаблонах.
```

```quiz
В: Какая строка НЕ соберётся, если `n` прочитано из `std::cin`?
- `const int a = n + 1;`
+ `constexpr int b = n + 1;`
- `int c = n + 1;`
= `constexpr` требует значение, известное при сборке, а `n` известно только при запуске.

В: Где обязательно нужно число, известное при сборке?
+ размер `std::array<int, N>`
- размер `std::vector<int> v(n)`
- аргумент обычной функции
= Размер `std::array` — часть типа, его выбирает компилятор. Размер `vector` задаётся при запуске.

В: Что случится, если `static_assert(sizeof(int) == 8, "...")` ложно?
- программа упадёт при запуске
+ программа не соберётся
- условие будет проигнорировано
= `static_assert` проверяется компилятором, до запуска.

В: Что будет, если `constexpr`-функцию вызвать с числом из `std::cin`?
+ Она выполнится при запуске, как обычная
- Ошибка компиляции
- Вернёт 0
= `constexpr` значит «можно при сборке», а не «только при сборке». Только — это `consteval`.

В: Какой вызов `consteval int twice(int x)` соберётся?
+ `constexpr int a = twice(21);`
- `int n; std::cin >> n; twice(n);`
- оба
= Аргумент `consteval`-функции обязан быть известен при сборке.

В: Зачем `static_assert` у таблицы баланса игры?
+ Чтобы неверная формула не дала собрать программу
- Чтобы таблица считалась быстрее
- Чтобы проверка шла при каждом запуске
= Ошибка при сборке находится раньше, чем ошибка у игрока.
```

## Закрепление прошлых тем

Три вопроса из прошлых тем — они встретятся в `constexpr`-коде:

```quiz
В: Тема 1. Чем `const int x = n * 2;` (где `n` прочитано с клавиатуры) отличается от `int x = n * 2;`?
+ `x` нельзя изменить после инициализации
- Значение посчитается при сборке
- Ничем
= `const` — только «не меняется». Посчитать при сборке значение, которое известно лишь при запуске, нельзя.

В: Тема 6. Чем `std::array<int, 5>` отличается от `std::vector<int>`?
+ Размер `array` известен при сборке и не меняется
- `array` умеет `push_back`
- `array` всегда в куче
= Размер `std::array` — часть типа, поэтому его задают константой.

В: Тема 17. Что делает компилятор с `template <typename T> T maxOf(T a, T b)` при вызове `maxOf(2, 5)`?
+ Создаёт версию функции для `int`
- Проверяет типы при запуске
- Превращает `T` в `auto`
= Это инстанцирование: для каждого типа — своя копия функции.
```
