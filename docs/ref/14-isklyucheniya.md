## 29. Исключения

Бывают два разных «нет ответа». Первое — когда пусто **по-нормальному**: искали и не нашли. Для него есть [`std::optional`](04-funkcii.md#stdoptional--когда-ответа-может-не-быть). Второе — когда **что-то пошло не так** и продолжать здесь нельзя: попросили превратить `"abc"` в число, обратились за границу вектора. Для этого — **исключения**.

### Ты их уже встречал: где библиотека бросает

Стандартная библиотека сама бросает исключения в таких местах:

```cpp
std::vector<int> v = {1, 2, 3};
v.at(10);                          // бросает std::out_of_range

std::stoi("abc");                  // бросает std::invalid_argument
std::stoi("99999999999");          // бросает std::out_of_range (не влезло в int)

std::map<std::string, int> m;
m.at("нет");                       // бросает std::out_of_range

std::optional<int> o;
o.value();                         // бросает std::bad_optional_access
```

Если исключение **не поймать**, программа немедленно завершается с сообщением:

```
terminate called after throwing an instance of 'std::out_of_range'
  what():  vector::_M_range_check: __n (which is 10) >= this->size() (which is 3)
```

Это уже лучше, чем молчаливая порча памяти у `v[10]`: видно тип ошибки и причину. Но падать необязательно — исключение можно **поймать**.

### `try` / `catch` — поймать и не упасть

Опасный код кладут в `try`, а обработку — в `catch`:

```cpp
#include <iostream>
#include <string>
#include <stdexcept>

int main() {
  std::string input = "abc";
  try {
    int n = std::stoi(input);            // если бросит — прыгаем в catch
    std::cout << "Число: " << n << "\n"; // сюда попадём только при успехе
  } catch (const std::invalid_argument &e) {
    std::cout << "Это не число: " << e.what() << "\n";
  }
  return 0;
}
// input = "abc"  →  Это не число: stoi
```

Как это читается:

- **`try { … }`** — «попробуй выполнить». Если внутри бросили — остаток блока **пропускается**, управление сразу прыгает в `catch`.
- **`catch (const std::invalid_argument &e)`** — «поймай ошибку вот такого типа». Ловим **по `const &`** (не по значению — см. ловушки ниже).
- **`e.what()`** — текстовое описание, которое положил тот, кто бросил.

Ловить можно несколько типов подряд — сработает первый подходящий:

```cpp
try {
  int n = std::stoi(input);
  std::cout << n;
} catch (const std::invalid_argument &e) {
  std::cout << "не число\n";
} catch (const std::out_of_range &e) {
  std::cout << "число слишком большое\n";
}
```

### Бросить своё исключение

Бросают через `throw`. Готовые типы — в `<stdexcept>`; чаще всего берут `std::runtime_error` и передают ему сообщение:

```cpp
#include <stdexcept>

int checkAge(int value) {
  if (value < 0 || value > 150)
    throw std::runtime_error("возраст вне диапазона");   // дальше эта функция не идёт
  return value;
}
```

`throw` работает как мгновенный выход: он **прерывает функцию** и «пробивается» вверх по стеку вызовов, пока не встретит подходящий `catch`. Если не встретит нигде — программа завершится.

Смысл в разделении обязанностей: функция, которая **обнаружила** проблему, не обязана знать, что с ней делать. Она бросает; решает тот, кто вызвал:

```cpp
try {
  int age = checkAge(userInput);
  std::cout << "Возраст принят: " << age << "\n";
} catch (const std::exception &e) {
  std::cout << "Отклонено: " << e.what() << "\n";
}
```

### Поймать любое стандартное — `std::exception`

Все стандартные исключения происходят от одного базового типа — `std::exception`. Поэтому `catch (const std::exception &e)` ловит **любое** из них, а `e.what()` работает для всех:

```cpp
try {
  риск();                              // что бы внутри ни бросили из стандартных
} catch (const std::exception &e) {
  std::cout << "Ошибка: " << e.what() << "\n";
}
```

Это удобно как «сеть на всякий случай» на верхнем уровне программы. Но если ты умеешь обработать конкретный случай по-особому — лови его отдельным `catch` выше, а `std::exception` оставляй последним, общим.

### Безопасный разбор числа: `stoi` в `optional`

Вот как соединяются два инструмента. `std::stoi` бросает на мусоре (об этом предупреждал [раздел 10](05-stroki.md#преобразования-числа-и-строки)), а вызывающему удобнее получить «либо число, либо пусто». Оборачиваем бросок в `try/catch` и отдаём наружу [`std::optional`](04-funkcii.md#stdoptional--когда-ответа-может-не-быть):

```cpp
#include <iostream>
#include <optional>
#include <stdexcept>
#include <string>

std::optional<int> parseInt(const std::string &s) {
  try {
    return std::stoi(s);               // получилось — число само ляжет в optional
  } catch (const std::exception &) {   // не число или не влезло — вернём «пусто»
    return std::nullopt;
  }
}

int main() {
  if (auto n = parseInt("42"))
    std::cout << "ok: " << *n << "\n";   // → ok: 42
  if (!parseInt("abc"))
    std::cout << "не число\n";           // → не число
  return 0;
}
```

Получилось лучшее из двух миров: исключение ловится **на границе** (там, где оно возникло), а наружу торчит спокойный `optional`, который вызывающий проверяет обычным `if` — без своего `try/catch`. Это типовой приём: «исключительное» от библиотеки превратить в «нормальное пусто» для остальной программы.

### Исключение, `optional` или код возврата — что когда

Три инструмента на «что-то не получилось», и путать их не нужно:

| Инструмент | Когда | Пример |
|---|---|---|
| [`std::optional`](04-funkcii.md#stdoptional--когда-ответа-может-не-быть) | пусто — это **нормальный** исход, случается часто | «найти элемент» (может не найтись) |
| `return false` / код возврата | вызывающий **каждый раз** проверяет результат | `withdraw` вернул `false` — денег не хватило |
| **исключение** | ошибка **редкая и исключительная**, продолжать нельзя | файл не открылся, ввод не разобрать, вышли за границу |

Правило: если «нет результата» — обычное дело и его проверяют на каждом шагу, бери `optional` или `bool`. Исключения — для того, что **не должно** случаться в норме и что глупо проверять после каждого вызова.

### Почему исключения безопасны: RAII

Когда `throw` «пробивается» вверх и функции по дороге завершаются, их локальные объекты **корректно уничтожаются** — файлы закрываются, память `vector` освобождается. Это тот же [RAII](10-slovar.md), по которому ресурсы освобождаются на выходе из области видимости:

```cpp
void process() {
  std::ifstream in("data.txt");        // открыли файл
  int n = std::stoi(readLine(in));     // ⚠️ бросит на плохой строке
  // ...
}                                      // ✅ даже при throw файл закроется сам — RAII
```

Именно поэтому в современном C++ не пишут `try { ... } finally { закрыть_вручную }` — закрывать вручную нечего, всё закрывается само. Это ещё один довод против `new`/`delete`: сырая память при `throw` **утекла бы**, а `vector` — нет.

### Типовые ошибки

```cpp
// 1. Поймали по значению вместо const & — лишняя копия и риск «срезки» типа
try { ... } catch (std::exception e) { }        // ⚠️ по значению
try { ... } catch (const std::exception &e) { } // ✅ по const &

// 2. Проглотили исключение молча — беда исчезла из виду
try {
  risky();
} catch (const std::exception &) {
  // ❌ пусто: ошибка случилась, но никто о ней не узнал
}

// 3. Ловят слишком широко там, где хотели один случай
try {
  int n = std::stoi(s);
} catch (...) {              // ⚠️ «поймать вообще всё» — прячет и те ошибки, что не ждали
  std::cout << "не число";  //    catch (const std::invalid_argument &) — честнее
}
```

> Исключения — не замена обычным проверкам. `if (d != 0)` перед делением проще и понятнее, чем `try/catch`. Бросай там, где проверка вызывающего была бы навязчивой, а сама ошибка — редкой и по-настоящему исключительной. Что дальше по темам — [раздел 26](09-spravka.md#26-что-учить-дальше).

## Проверь себя

Небольшой разбор по теме. Нажми вариант — сразу увидишь, верно или нет; можно и просто «Показать ответ».

```quiz
В: Что будет, если исключение не поймать ни одним `catch`?
+ Программа аварийно завершится (`std::terminate`)
- Исключение тихо проигнорируется
- Функция вернёт `0`
= Непойманное исключение поднимается по стеку вызовов до самого верха и обрывает программу.

В: Какой `catch` поймает и `std::out_of_range` от `.at()`, и `std::invalid_argument` от `stoi`?
+ `catch (const std::exception &e)`
- `catch (int e)`
- `catch (const std::string &e)`
= Все стандартные исключения — наследники `std::exception`. Текст ошибки — `e.what()`.

В: Когда лучше вернуть `std::optional`, а не бросать исключение?
+ Когда «нет результата» — нормальная ситуация: пользователь ввёл не число, элемент не найден
- Всегда — исключения запрещены
- Никогда — `optional` устарел
= Исключение — для настоящих сбоев, которые нельзя обработать на месте. Ожидаемое «не получилось» честнее выразить `optional`.

В: Почему ловить стоит по `const &`: `catch (const std::exception &e)`?
+ Без копии и без «срезки»: сохраняется настоящий тип исключения
- Иначе не компилируется
- Так быстрее бросать
= Ловля по значению копирует объект и обрезает его до базового `std::exception` — теряется точное сообщение наследника.
```

Найди ошибку:

```findbug
std::string input = "abc";
int n = 0;
try {
    n = std::stoi(input);
} catch (const std::out_of_range &e) {
    std::cout << "слишком большое число\n";
}
std::cout << n;            // программа всё равно падает
---
Для строки `"abc"` `stoi` бросает **`std::invalid_argument`**, а ловится только `std::out_of_range` — исключение пролетает мимо и обрывает программу.

**Исправление:** добавить `catch (const std::invalid_argument &e)` или ловить общее `catch (const std::exception &e)`.
```
