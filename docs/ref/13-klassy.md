## 22. Классы

В [разделе 19](08-struct-fayly.md#19-struct) уже сказано: как только у `struct` появляются методы, ты фактически пишешь класс — просто с открытыми полями. Класс добавляет к этому одну важную вещь: возможность **спрятать** данные, чтобы снаружи их нельзя было испортить.

> 📖 **Определение.** **Класс** — свой тип, который держит вместе данные (**поля**) и действия над ними (**методы**). **Объект** — конкретный экземпляр класса, созданный по этому «чертежу»: `Account acc;` — `acc` это объект. Термины собраны в [словаре](10-slovar.md#про-классы-ооп).

### За 30 секунд

- `class` — это `struct`, у которого всё по умолчанию **закрыто** (`private`). Открытое — после `public:`.
- Поля прячут, наружу дают **действия**: `takeDamage(5)` вместо `hp -= 5`. Так объект не сломать снаружи.
- **Конструктор** задаёт стартовое состояние: `Hero h("Торин", 30);` — объекта без нужных данных не бывает.
- Метод, который только читает, помечают `const`: `int hp() const { return hp_; }`.
- **Деструктор** (`~Hero()`) срабатывает сам, когда объект уходит из области видимости, — на этом держится RAII.

```cpp
class Hero {
 public:
  Hero(std::string name, int maxHp) : name_(std::move(name)), hp_(maxHp), maxHp_(maxHp) {}
  void takeDamage(int d) { hp_ = std::max(0, hp_ - d); }   // здоровье никогда не уйдёт в минус
  bool isAlive() const { return hp_ > 0; }
 private:
  std::string name_;
  int hp_, maxHp_;
};
```

### От `struct` к `class`: одно отличие

Технически `struct` и `class` в C++ — почти одно и то же. Разница ровно одна: **что открыто по умолчанию.**

```cpp
struct Point {     // в struct всё public — открыто по умолчанию
  int x = 0;
  int y = 0;
};

class Secret {     // в class всё private — закрыто по умолчанию
  int hidden = 0;  // снаружи не достать
};
```

Само по себе это мелочь. Смысл появляется, когда данные нужно **защитить правилом**.

### Инкапсуляция: спрятать данные, открыть действия

Представь счёт в банке. Баланс не должен становиться отрицательным. Со `struct` эту гарантию дать нельзя — поле открыто, и кто угодно испортит:

```cpp
struct Account {
  long long balance = 0;
};

Account acc;
acc.balance = -1000;      // ❌ ничто не мешает: инвариант «баланс >= 0» нарушен молча
```

Класс прячет поле (`private`) и разрешает менять его **только через свои методы** (`public`), которые следят за правилом:

```cpp
class Account {
 public:                       // ← отсюда и ниже — доступно снаружи
  void deposit(long long sum) {
    if (sum > 0)
      balance += sum;          // класс сам решает, как менять баланс
  }

 private:                      // ← отсюда и ниже — только внутри класса
  long long balance = 0;       // снаружи balance не увидеть и не присвоить
};

Account acc;
acc.deposit(100);              // ✅ так можно
acc.balance = -1000;           // ❌ error: 'balance' is private — правило не обойти
```

```cpp alt: В игре: здоровье, которое не уйдёт в минус
class Health {
 public:
  explicit Health(int max) : hp_(max), max_(max) {}
  void damage(int d) { hp_ = std::max(0, hp_ - std::max(0, d)); }
  void heal(int h) { hp_ = std::min(max_, hp_ + std::max(0, h)); }
  int value() const { return hp_; }
 private:
  int hp_, max_;
};

Health h(30);
h.damage(50);                  // hp не станет -20
std::cout << h.value() << "\n";   // 0
```

```cpp alt: Таймер: время не бывает отрицательным
class Timer {
 public:
  void add(int seconds) { if (seconds > 0) total_ += seconds; }
  int minutes() const { return total_ / 60; }
 private:
  int total_ = 0;              // снаружи не выставить -100
};

Timer t;
t.add(125);
t.add(-999);                   // проигнорировано правилом класса
std::cout << t.minutes() << "\n";   // 2
```

Это и есть **инкапсуляция**: данные спрятаны, наружу торчат только безопасные действия. Правило «баланс не бывает отрицательным» держится в одном месте, а не размазано по всей программе.

- **`private`** — видно только методам самого класса. Сюда прячут поля-данные.
- **`public`** — видно всем снаружи. Сюда выносят методы, через которые с объектом работают.

### Конструктор — как объект рождается

У `struct` поля задают при создании фигурными скобками: `Point p{3, 4}`. У класса с приватными полями так нельзя — они закрыты. Их задаёт **конструктор**: специальный метод с именем класса, который выполняется при создании объекта.

```cpp
class Account {
 public:
  Account(long long start) : balance(start) {}   // конструктор: имя класса, без типа возврата
  //      ↑ параметр        ↑ список инициализации: balance получает значение start

 private:
  long long balance = 0;
};

Account acc(500);        // конструктор вызвался, balance стал 500
```

Часть после двоеточия — **список инициализации**: поля получают значения ещё до входа в тело `{}`. Именно так и надо задавать поля — не присваиванием в теле:

```cpp
Account(long long start) : balance(start) {}   // ✅ инициализация — поле сразу правильное
Account(long long start) { balance = start; }  // ⚠️ работает, но поле сначала создаётся, потом присваивается
```

Для простых типов разница невелика, но привычка правильная: **инициализируй в списке, а не присваивай в теле.**

Конструкторов может быть несколько (перегрузка) — например, «с начальным балансом» и «с нуля»:

```cpp
class Account {
 public:
  Account() : balance(0) {}                      // без аргументов — пустой счёт
  Account(long long start) : balance(start) {}   // с начальным балансом

 private:
  long long balance = 0;
};

Account empty;         // вызвался Account()
Account rich(1000);    // вызвался Account(long long)
```

### `const`-методы — что только читает

Как и у [методов struct](08-struct-fayly.md#методы--функции-внутри-структуры), метод, который ничего не меняет, помечают `const`. Это позволяет звать его у `const`-объектов и защищает от случайной правки полей:

```cpp
class Account {
 public:
  long long getBalance() const {    // const: обещает не менять поля
    return balance;
    // balance += 1;                 // ❌ error: внутри const-метода поля менять нельзя
  }

 private:
  long long balance = 0;
};
```

Правило простое: **читающий метод — `const`, меняющий — без `const`.** Геттеры (методы «дай значение») почти всегда `const`.

### Деструктор и RAII

У конструктора есть пара — **деструктор**: метод `~ИмяКласса()`, который вызывается **сам**, когда объект выходит из области видимости. Это тот самый механизм, по которому закрываются файлы и освобождается память в `vector` — [RAII](10-slovar.md#про-типы-и-память).

```cpp
#include <iostream>
#include <string>
#include <utility>

class Scope {
 public:
  Scope(std::string name) : name_(std::move(name)) {
    std::cout << "+ " << name_ << "\n";   // конструктор — объект родился
  }
  ~Scope() {                              // ДЕСТРУКТОР — вызовется сам на выходе из области
    std::cout << "- " << name_ << "\n";
  }

 private:
  std::string name_;
};

int main() {
  Scope outer("main");
  {
    Scope inner("block");   // родится здесь
  }                         // и умрёт здесь — деструктор на закрывающей }
  std::cout << "работаем\n";
  return 0;
}                           // outer умрёт здесь
```

```
+ main
+ block
- block
работаем
- main
```

Порядок обратный рождению (`block` создан позже — уничтожен раньше), и деструктор срабатывает **на любом выходе** из блока: обычном, по `return`, даже при исключении. Поэтому в C++ ресурс освобождают **в деструкторе**, а не «не забыть в конце» — забыть невозможно.

Пройдите по шагам — следите, **на какой строке** срабатывает деструктор. Её никто не вызывает явно — это делает закрывающая `}`:

```steps
@id c1a7vnyb
# Кто когда рождается и умирает
int main() {
    Scope outer("main");
    {
        Scope inner("block");
    }
    std::cout << "работаем\n";
    return 0;
}
---
2 | outer=жив | Конструктор `outer` — печать «+ main». | + main\n
4 | inner=жив | Внутренний блок `{`: рождается `inner`. | + block\n
5 | inner=— | Закрывающая `}` блока — `inner` выходит из области, деструктор вызывается **сам**. | - block\n
6 | | Обычная работа. `inner` уже нет, а `outer` жив. | работаем\n
7 | | `return 0;` — выходим из `main`...
8 | outer=— | ...и на `}` функции умирает `outer`. Последним родился — первым умер: `block` раньше `main`. | - main\n
```

> На практике свой деструктор нужен редко: готовые RAII-типы (`vector`, `string`, потоки, [умные указатели](18-umnye-ukazateli.md)) уже освобождают всё сами. Пиши деструктор, только когда класс владеет чем-то, что стандартная библиотека не закрывает за тебя. И помни: как только у класса появляется свой деструктор, стоит подумать и о копировании — это «правило трёх/пяти», тема на вырост.

### Пример целиком: класс `Account`

Всё вместе — маленький работающий класс с защищённым инвариантом:

```cpp
#include <iostream>

class Account {
 public:
  explicit Account(long long start)              // счёт с начальным балансом
      : balance(start > 0 ? start : 0) {}        // отрицательный старт не пустим: будет 0

  void deposit(long long sum) {
    if (sum > 0)
      balance += sum;
  }

  bool withdraw(long long sum) {          // вернёт false, если денег не хватает
    if (sum <= 0 || sum > balance)
      return false;
    balance -= sum;
    return true;
  }

  long long getBalance() const {          // только читает — значит const
    return balance;
  }

 private:
  long long balance = 0;                  // спрятано: снаружи не испортить
};

int main() {
  Account acc(100);
  acc.deposit(50);
  std::cout << acc.getBalance() << "\n";              // → 150

  bool ok = acc.withdraw(500);                        // денег не хватает
  std::cout << ok << " " << acc.getBalance() << "\n"; // → 0 150   отказ, баланс цел

  Account bad(-500);                                  // попытка начать с минуса
  std::cout << bad.getBalance() << "\n";              // → 0   конструктор не пустил

  // balance напрямую не тронуть — он private, инвариант «баланс >= 0» защищён
  return 0;
}
```

Обрати внимание: снаружи невозможно привести счёт в неверное состояние. Тронуть баланс можно ровно в трёх местах — конструктор, `deposit` и `withdraw`, — и **каждое** из них следит за правилом. Забыть проверку в конструкторе — частая дыра: методы защищены, а объект «рождается» уже сломанным.

> **`explicit` перед конструктором** запрещает незаметное превращение числа в объект. Без него сработало бы `Account acc = 500;` и, хуже, вызов `print(500)` у функции `void print(const Account &)` — компилятор молча собрал бы счёт из числа. Правило: конструктор с **одним** параметром помечай `explicit`, если такое превращение не задумано специально.

### `this` — указатель на себя

Внутри метода есть скрытый параметр `this` — [указатель](22-ukazateli.md#указатель-t--переменная-в-которой-лежит-адрес) на тот объект, у которого метод вызвали. Когда пишешь в методе просто `balance`, компилятор читает это как `this->balance`.

Явно `this` нужен в двух случаях. Первый — **имя параметра совпало с именем поля**:

```cpp
void setName(const std::string &name) {
  this->name = name;     // слева поле объекта, справа параметр
}
```

Без `this->` было бы `name = name;` — параметр присвоился бы сам себе, а поле не изменилось. Флаг `-Wshadow` предупреждает о таком совпадении имён, поэтому надёжнее назвать параметр иначе (`newName`) — тогда и `this` не понадобится.

Второй — **вернуть сам объект**, чтобы вызовы шли цепочкой:

```cpp
#include <iostream>
#include <string>

class Player {
 public:
  explicit Player(const std::string &startName) : name(startName) {}

  Player &addScore(int points) {
    score += points;
    return *this;               // this — указатель, *this — сам объект
  }

  void print() const { std::cout << name << ": " << score << "\n"; }

 private:
  std::string name;
  int score = 0;
};

int main() {
  Player p("Аня");
  p.addScore(10).addScore(5);   // цепочка: оба вызова — для одного p
  p.print();                    // → Аня: 15
  return 0;
}
```

`addScore` возвращает ссылку на тот же объект, поэтому следующий `.addScore(5)` идёт к тому же игроку. Так устроен и `std::cout << a << b`: каждый `<<` возвращает сам поток.

В `const`-методе `this` указывает на `const`-объект — поэтому такой метод и не может менять поля.

### `static`-поля — одно на всех

Обычное поле у каждого объекта своё. Поле с `static` — **одно на весь класс**, общее для всех объектов. Типичное применение — счётчик созданных объектов или выдача номеров:

```cpp
#include <iostream>
#include <string>

class Ticket {
 public:
  explicit Ticket(const std::string &who) : owner(who), number(++issued) {}

  int getNumber() const { return number; }
  static int count() { return issued; }       // static-метод: вызывается без объекта

 private:
  std::string owner;
  int number = 0;
  static inline int issued = 0;               // одно на весь класс (C++17: inline — задать прямо здесь)
};

int main() {
  Ticket a("Аня"), b("Борис"), c("Вера");
  std::cout << b.getNumber() << "\n";         // → 2
  std::cout << Ticket::count() << "\n";       // → 3 — через имя класса, не через объект
  return 0;
}
```

```cpp alt: Сколько монстров сейчас живо
class Monster {
 public:
  Monster() { ++alive_; }
  ~Monster() { --alive_; }
  static int alive() { return alive_; }
 private:
  static inline int alive_ = 0;          // один счётчик на всех монстров
};

{
  Monster a, b;
  std::cout << Monster::alive() << "\n";   // 2
}
std::cout << Monster::alive() << "\n";     // 0 — вышли из блока, деструкторы уменьшили счётчик
```

```cpp alt: Общая настройка для всех объектов
class Enemy {
 public:
  int damage(int base) const { return base * difficulty; }
  static inline int difficulty = 1;      // одна «сложность» на всю игру
};

Enemy::difficulty = 3;                   // меняем для всех врагов сразу
Enemy goblin;
std::cout << goblin.damage(4) << "\n";  // 12
```

- `static inline int issued = 0;` — объявить и сразу задать значение (с C++17). В старом коде поле объявляют в классе, а значение задают отдельной строкой в `.cpp`: `int Ticket::issued = 0;`.
- `static`-метод не привязан к объекту: у него нет `this`, поэтому он видит только `static`-поля. Вызывают его через имя класса: `Ticket::count()`.

> **Не путать с `static` у локальной переменной.** `static int calls = 0;` внутри функции — переменная, которая переживает выход из функции и хранит значение между вызовами. Слово то же, смысл другой.

### `operator<<` — печатать объект через `cout`

`std::cout << acc;` сам по себе не соберётся: `cout` не знает, как печатать твой тип (ошибка [`no match for 'operator<<'`](11-oshibki.md#no-match-for-operator--const-stdstring)). Научить его — значит написать **свободную функцию** `operator<<`:

```cpp
#include <iostream>
#include <string>

struct Point {
  int x = 0;
  int y = 0;
};

// Принимает поток и объект, пишет в поток, возвращает тот же поток.
std::ostream &operator<<(std::ostream &out, const Point &p) {
  out << "(" << p.x << ", " << p.y << ")";
  return out;                  // вернуть поток — чтобы работали цепочки << … <<
}

int main() {
  Point a{3, 4};
  Point b{-1, 2};
  std::cout << "a = " << a << ", b = " << b << "\n";   // → a = (3, 4), b = (-1, 2)
  return 0;
}
```

Разбор сигнатуры: `std::ostream &out` — поток по ссылке (`cout`, файл — любой); `const Point &p` — объект только для чтения, без копии; возвращаем `out`, иначе `std::cout << a << b` не сработает — второй `<<` не к чему было бы прицепить.

Если печатать нужно `private`-поля класса, есть два пути: печатать через открытые методы (`acc.getBalance()`) — это проще — или объявить функцию «другом» класса: `friend std::ostream &operator<<(std::ostream &, const Account &);` внутри класса. Друг видит `private`.

### Свои операторы: `+`, `==`, `<=>`, `[]`

Оператор — это функция с особым именем. Свой тип можно научить складываться, сравниваться и индексироваться — тогда код с ним читается как с числами.

```cpp
#include <compare>
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

struct Money {
  long long kopecks = 0;

  Money operator+(const Money &other) const { return {kopecks + other.kopecks}; }
  // C++20: одна строка даёт ==, !=, <, >, <=, >= — сравнение по полям по порядку
  auto operator<=>(const Money &) const = default;
};

class Inventory {
 public:
  void add(const std::string &item) { items_.push_back(item); }
  // [] только для чтения, с проверкой границ
  const std::string &operator[](std::size_t i) const {
    if (i >= items_.size()) throw std::out_of_range("нет такого слота");
    return items_[i];
  }

 private:
  std::vector<std::string> items_;
};

int main() {
  Money a{1050}, b{250};
  Money sum = a + b;                                  // вызывается a.operator+(b)
  std::cout << sum.kopecks << " " << (a > b) << "\n"; // 1300 1

  Inventory bag;
  bag.add("зелье");
  std::cout << bag[0] << "\n";                        // зелье
}
```

Правила, чтобы операторы не удивляли:
- оператор делает то, что от него ждут: `+` складывает, а не печатает;
- то, что не меняет объект (`+`, `==`, `[]` для чтения), помечай `const`;
- сравнение — через `= default` у `<=>`, пока хватает сравнения по всем полям подряд;
- `operator<<` для печати — уже [выше](#operator--печатать-объект-через-cout).

### `struct` или `class` — что когда

Выбор простой и не про синтаксис, а про смысл:

| Бери `struct` | Бери `class` |
|---|---|
| простой «мешок данных»: `Point`, `Student`, строка таблицы | у данных есть **правило** (инвариант), которое надо защищать |
| поля независимы, любое сочетание значений допустимо | неверное сочетание полей должно быть **невозможно** снаружи |
| нет логики или она в свободных функциях рядом | поведение и данные естественно живут вместе |

Пока задача — просто сложить несколько полей вместе (точка, запись о студенте), `struct` с открытыми полями честнее и короче. Класс достаёшь, когда появляется правило: «баланс не отрицателен», «проценты от 0 до 100», «список всегда отсортирован».

### Типовые ошибки

```cpp
// 1. Поле не инициализировано в конструкторе — внутри мусор
class Timer {
 public:
  Timer() {}          // ❌ seconds не задан → случайное значение
 private:
  int seconds;        // ✅ лечится так: int seconds = 0; (или в списке инициализации)
};

// 2. Сделал поле public «чтобы удобнее» — и потерял всю защиту
class Account {
 public:
  long long balance;  // ❌ снова кто угодно поставит -1000; инкапсуляция сломана

// 3. Забыл const на читающем методе
long long getBalance() { return balance; }   // ⚠️ без const — не вызвать у const-объекта
long long getBalance() const { return balance; }   // ✅
```

## Рецепты: хочу X → вот код

Ищешь не функцию, а решение задачи — начни отсюда.

- **Защитить поле от порчи** — сделай его `private`, а менять — через метод с проверкой. → [инкапсуляция](#инкапсуляция-спрятать-данные-открыть-действия)
- **Не дать создать объект «пустым»** — конструктор с нужными параметрами. → [конструктор](#конструктор--как-объект-рождается)
- **Метод, который вызывается у `const`-объекта** — `int hp() const { … }`. → [const-методы](#const-методы--что-только-читает)
- **Освободить ресурс автоматически** — закрытие в деструкторе (RAII). → [деструктор](#деструктор-и-raii)
- **Счётчик на весь класс** (сколько создано объектов) — `static int created;`. → [static](#static-поля--одно-на-всех)
- **Печатать объект через `cout`** — `friend std::ostream &operator<<(std::ostream &, const Hero &)`. → [operator<<](#operator--печатать-объект-через-cout)
- **Решить, `struct` или `class`** — есть правило, которое надо охранять, — `class`; просто данные — `struct`. → [что когда](#struct-или-class--что-когда)

Карточки на повторение:

```cards
Q: Чем `class` отличается от `struct` в C++?
A: Технически — только доступом по умолчанию: у `class` члены `private`, у `struct` — `public`. По смыслу `class` берут, когда у типа есть инварианты и инкапсуляция.

Q: Что делает конструктор?
A: Инициализирует объект в момент рождения — задаёт полям корректные значения (лучше через список инициализации). Гарантирует, что объект сразу в валидном состоянии.

Q: Зачем метод помечают `const` (например `int size() const`)?
A: Это обещание, что метод не меняет объект. Такой метод можно звать у `const`-объектов, а компилятор ловит случайные изменения полей.

Q: Что такое RAII и при чём тут деструктор?
A: Ресурс захватывается в конструкторе и освобождается в деструкторе. Объект уходит из области видимости → деструктор сам закрывает память/файл/блокировку — без ручного `delete`/`close`.

Q: Чем `private` отличается от `public`?
A: К `public` членам обращаются снаружи, к `private` — только методы самого класса. Поля обычно прячут в `private`.

Q: Что такое список инициализации конструктора?
A: `Point(int x, int y) : x_(x), y_(y) {}` — поля инициализируются сразу, до тела конструктора. Для `const`-полей и полей-ссылок это единственный способ.

Q: Что такое инвариант класса?
A: Правило, которое всегда верно для объекта, например «баланс не меньше 0». Конструктор его устанавливает, методы сохраняют.
H: Ради него поля и прячут в `private`.

Q: Зачем `explicit` у конструктора с одним параметром?
A: Запрещает неявное преобразование: без него `Meters m = 5;` или передача `5` в функцию, ждущую `Meters`, тихо создадут объект.

Q: Зачем геттер, если можно сделать поле `public`?
A: Метод чтения (`int hp() const`) не даёт менять поле напрямую и позволяет позже добавить проверку или вычисление, не трогая код снаружи.

Q: Что такое `this` внутри метода?
A: Указатель на текущий объект. `this->hp` — поле этого объекта; обычно пишут просто `hp`.

Q: Что даёт `auto operator<=>(const T &) const = default;`?
A: Все шесть сравнений (`==`, `!=`, `<`, `>`, `<=`, `>=`) по полям по порядку объявления (C++20).

Q: Почему `Money operator+(const Money &) const` помечен `const`?
A: Сложение не меняет левое слагаемое — возвращает новое значение. `const` позволяет складывать и константные объекты.
```
