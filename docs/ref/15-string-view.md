## 30. `std::string_view`

### За 30 секунд

- `std::string_view` — **окно** в чужую строку: указатель на начало и длина. Сам ничего не хранит и не копирует.
- Удобен как параметр функции, которая только **читает** текст: принимает и `std::string`, и `"литерал"` без создания копии.
- Умеет почти всё «читающее»: `size()`, `substr`, `find`, `starts_with`, `remove_prefix`.
- Главная ловушка: окно в **временную** строку висит, когда строка умерла. Не храни `string_view` дольше самой строки.
- Нужно сохранить или изменить текст — бери `std::string`.

```cpp
bool isCommand(std::string_view line, std::string_view cmd) {
  return line.starts_with(cmd);          // ни одной копии строки
}

isCommand("идти 3", "идти");             // литерал — без создания std::string
```

### Зачем он: `const std::string&` не всегда бесплатен

Из [раздела 9](04-funkcii.md#три-способа-передать-аргумент) правило: строку в функцию передают как `const std::string&`, чтобы не копировать. Это верно — но есть тонкость. Если позвать такую функцию с **литералом**, копия всё-таки создаётся:

```cpp
void print(const std::string &s) { std::cout << s; }

print("привет");        // ⚠️ из "привет" тихо создаётся временный std::string (выделение памяти)
```

`std::string_view` (`<string_view>`) убирает и это: он принимает и `std::string`, и литерал, и кусок другой строки — **без единой копии**.

### Что это: окно в чужую строку

`string_view` не хранит символы. Внутри — всего лишь **указатель на начало и длина**: «смотри вот сюда, вот столько букв». Данные принадлежат кому-то другому; view только читает их.

```cpp
#include <iostream>
#include <string>
#include <string_view>

void greet(std::string_view name) {        // принимает что угодно строковое, без копии
  std::cout << "Привет, " << name << "!\n";
}

int main() {
  std::string user = "Аня";
  greet(user);            // из std::string — без копии
  greet("Борис");         // из литерала — без создания временной строки
  return 0;
}
```

Поэтому `string_view` — почти идеальный **тип параметра** для функций, которые строку только читают: одна подпись работает со всеми источниками текста и ничего не копирует.

### Что с ним можно делать

Всё, что не меняет строку и не требует владения ею:

```cpp
std::string_view s = "hello.txt";

std::cout << s.size() << "\n";           // → 9
std::cout << s[0] << "\n";               // → h    доступ по индексу
std::cout << s.substr(0, 5) << "\n";     // → hello   substr возвращает тоже string_view — дёшево
std::cout << (s.find("txt") != std::string_view::npos) << "\n";   // → 1
std::cout << s.starts_with("hello") << "\n";   // → 1   (как у string)
std::cout << (s == "hello.txt") << "\n";       // → 1   сравнение работает
```

```cpp alt: Разбор команды «идти 3» без копий
std::string_view cmd = "идти 3";
std::size_t space = cmd.find(' ');
std::string_view verb = cmd.substr(0, space);                 // «идти» — окно, не копия
std::string_view arg = space == std::string_view::npos ? "" : cmd.substr(space + 1);
std::cout << verb << " / " << arg << "\n";
```

```cpp alt: Какой это файл: по расширению
bool isImage(std::string_view name) {
  return name.ends_with(".png") || name.ends_with(".jpg") || name.ends_with(".webp");
}

std::cout << isImage("hero.png") << isImage("save.txt") << "\n";   // 10
```

Уникальное для view — **дёшево двигать края окна**, не трогая данные: `remove_prefix(n)` сдвигает начало вправо, `remove_suffix(n)` — конец влево. Так, например, обрезают пробелы или отрезают уже разобранный кусок, без единой копии:

```cpp
std::string_view s = "  привет  ";
s.remove_prefix(2);   // окно поехало вправо на 2 — «съели» 2 ведущих пробела
s.remove_suffix(2);   // и с конца на 2 — теперь s смотрит ровно на "привет"
```

Чего нельзя — **менять** символы (`s[0] = 'H'` не скомпилируется) и **дописывать** (`+=` нет): view — только для чтения. Нужно изменить или накопить текст — это `std::string`.

### Главная ловушка: окно может повиснуть

`string_view` **не владеет** данными. Если строка, в которую он смотрит, перестала существовать, view указывает в никуда — это [висячая ссылка](10-slovar.md), как и у обычной ссылки, только её легче создать по неосторожности.

```cpp
std::string_view bad() {
  std::string local = "временная";
  return local;              // ❌ вернули окно в локальную строку —
}                            //    она умрёт на выходе, а view останется висеть
```

Та же беда — сохранить view от временного значения:

```cpp
std::string_view v = std::string("привет") + "!";   // ❌ временная строка тут же уничтожена,
std::cout << v;                                      //    v смотрит в мусор
```

Правило, снимающее почти все проблемы: **`string_view` — для параметров, а не для хранения.** Пришёл в функцию, попользовался, вышел — данные всё это время живы у вызывающего. Хранить текст «надолго» (в поле структуры, в векторе) — это `std::string`, который владеет своей копией.

Ещё тонкость: `string_view` **не обязан оканчиваться нулём**, поэтому отдавать его в старые C-функции (`printf("%s", …)`, что-то, что ждёт `const char*`) нельзя — для этого нужен `std::string` и его `.c_str()`.

Посмотрите по шагам, как окно «повисает»:

```steps
@id ctgy87l
# Окно в строку, которой больше нет
std::string_view bad() {
    std::string local = "временная";
    return local;
}
int main() {
    std::string_view v = bad();
    std::cout << v;
}
---
6 | | Вызываем `bad()`.
2 | local=буфер «временная» | Внутри функции живёт строка `local` со своим буфером в памяти.
3 | окно=→ буфер local, 18 байт | `string_view` — это всего лишь «адрес + длина». Он смотрит в буфер `local`, ничего не копируя. Длина — в байтах: 9 русских букв в UTF-8 занимают по 2 байта, `size()` = 18.
4 | local=уничтожена, окно=→ освобождённая память | Функция закончилась — `local` умерла, буфер отдан обратно. А окно всё ещё смотрит туда.
6 | окно=—, v=→ освобождённая память | `v` получил висящее окно.
7 | | Печать — **неопределённое поведение**: мусор, пустота или падение. Компилятор может даже не предупредить.
```

Лечится одним правилом: функция, которая **создаёт** строку, возвращает `std::string`, а не `string_view`.

### `std::span` — такое же окно для массивов

То, чем `string_view` служит для строк, `std::span<T>` (C++20) делает для любых подряд лежащих элементов: `std::vector`, `std::array`, обычного массива. Функция принимает «окно» и не копирует данные.

```cpp
#include <array>
#include <iostream>
#include <span>
#include <vector>

// Одна функция для вектора, массива и куска любого из них
int sum(std::span<const int> values) {
  int s = 0;
  for (int x : values) s += x;
  return s;
}

int main() {
  std::vector<int> v = {1, 2, 3, 4, 5};
  std::array<int, 3> a = {10, 20, 30};
  std::cout << sum(v) << " " << sum(a) << " " << sum(std::span(v).subspan(1, 3)) << "\n";   // 15 60 9
}
```

- `std::span<const int>` — только читать; `std::span<int>` — можно менять элементы оригинала.
- `subspan(начало, сколько)`, `first(n)`, `last(n)` — кусок без копии.
- Та же ловушка, что у `string_view`: окно не владеет данными. Вектор изменил размер или умер — окно смотрит в пустоту.

### Когда брать `string_view`, а когда нет

| Бери `string_view` | Бери `std::string` |
|---|---|
| параметр функции, которая строку только **читает** | нужно **хранить** текст (поле, элемент вектора) |
| хочешь принимать и `string`, и литерал без копий | нужно **менять**/дописывать текст |
| режешь на подстроки (`substr` дёшев) | нужен `const char*` для C-функции (`.c_str()`) |

Практический вывод для твоего кода: там, где сейчас `const std::string&` у функции, которая ничего со строкой не делает, кроме чтения, — можно писать `std::string_view`. Для полей и любого хранения — по-прежнему `std::string`.

> `string_view` — про производительность и удобство приёма, а не про новые возможности. Пока строки короткие, выигрыш незаметен; ценность в единой подписи «принимаю любой текст». Что дальше по темам — [раздел 26](09-spravka.md#26-что-учить-дальше).

```cards
Q: Что такое `std::string_view`?
A: «Окно» на чужие символы: указатель и длина, без копирования. Сам он ничего не хранит.

Q: Зачем параметр `std::string_view` вместо `const std::string &`?
A: Он принимает и `std::string`, и литерал `"..."`, не создавая временную строку.

Q: Чем опасно `std::string_view sv = std::string("temp");`?
A: Временная строка уничтожится в конце этой же строки кода, и `sv` будет смотреть в освобождённую память — висячий вид.
H: Сколько живёт временный объект?

Q: Как отрезать первые 3 символа у `string_view` без копирования?
A: `sv.remove_prefix(3);` или `sv = sv.substr(3);` — меняется только окно, сами данные не трогаются.

Q: Можно ли вернуть `string_view` на локальную `std::string` из функции?
A: Нет: строка умрёт при выходе из функции, и вид повиснет. Возвращай `std::string`.

Q: Как превратить `string_view` обратно в `std::string`?
A: Явно: `std::string s{sv};` — это копия, её можно хранить сколько угодно.

Q: Гарантирует ли `string_view` завершающий `'\0'`?
A: Нет. Поэтому `sv.data()` нельзя отдавать функциям, которые ждут C-строку (`printf("%s")`, `fopen`).

Q: Где `string_view` особенно полезен?
A: В разборе текста: поиск, нарезка на слова, сравнение — без выделения памяти под каждую подстроку.

Q: Что такое `std::span<const int>`?
A: Окно в подряд лежащие `int` (вектор, массив, их кусок) без копии и без права менять.

Q: Чем опасен `span` на вектор, в который потом делают `push_back`?
A: Вектор может переехать в другую память, и окно будет смотреть в освобождённую.
```

```quiz
= По значению строка копируется целиком при каждом вызове. `string_view` из этой темы — ещё один способ обойтись без копии.

В: Тема 14. Что сделает `std::stoi("abc")`?
+ Бросит `std::invalid_argument`
- Вернёт `0`
- Вернёт `-1`
= Числа в начале строки нет — разбирать нечего, поэтому исключение. Ловят его через `try`/`catch`.
```
