## 36. Ссылки и указатели

> **Определение.** **Ссылка** (`int&`) — второе имя уже существующей переменной. **Указатель** (`int*`) — отдельная переменная, в которой хранится **адрес** другой переменной. Через оба можно менять оригинал, но ссылка всегда привязана к одному объекту, а указатель можно перенаправить или обнулить (`nullptr`).

### За 30 секунд

- `&x` — **адрес** переменной `x` («где она лежит»).
- `int &r = x;` — **ссылка**: `r` — это другое имя для `x`. Меняешь `r` — меняется `x`.
- `int *p = &x;` — **указатель**: в `p` лежит адрес `x`. `*p` — «то, что по этому адресу», то есть сам `x`.
- `p->name` — то же, что `(*p).name`: поле структуры через указатель.
- `nullptr` — указатель «никуда». Разыменовать его (`*p`) нельзя — программа упадёт.

| Запись | Где стоит | Что значит |
|---|---|---|
| `int &r = x;` | в объявлении | `r` — ссылка на `x` |
| `&x` | в выражении | адрес `x` |
| `int *p = &x;` | в объявлении | `p` — указатель на `int` |
| `*p` | в выражении | значение по адресу из `p` |
| `p->f` | в выражении | поле `f` объекта, на который указывает `p` |

Главная путаница новичка: **`&` и `*` значат разное в объявлении и в выражении.** В объявлении они говорят о типе («это ссылка», «это указатель»), в выражении — действуют («взять адрес», «пойти по адресу»).

### Адрес: у каждой переменной есть место в памяти

Память компьютера — длинная лента пронумерованных ячеек. Каждая переменная занимает несколько ячеек подряд, а номер первой называется её **адресом**. Узнать адрес можно оператором `&`:

```cpp
#include <iostream>

int main() {
  int age = 25;
  double price = 9.99;

  std::cout << "age   = " << age << ", лежит по адресу " << &age << "\n";
  std::cout << "price = " << price << ", лежит по адресу " << &price << "\n";
  return 0;
}
```

```console
$ ./adresa
age   = 25, лежит по адресу 0x5ffe9c
price = 9.99, лежит по адресу 0x5ffe90
```

Адреса печатаются в шестнадцатеричном виде (`0x…`) и **меняются от запуска к запуску** — запоминать их не нужно. Важна сама идея:

```
   память (фрагмент)

   адрес:     0x5ffe90                 0x5ffe9c
             ┌─────────────────────┐  ┌──────────┐
             │        9.99         │  │    25    │
             └─────────────────────┘  └──────────┘
                 price (8 байт)         age (4 байта)
```

Имя переменной — это удобная для человека подпись к адресу. Компилятор сам помнит, что `age` — это «4 байта по адресу 0x5ffe9c».

### Ссылка `T&` — второе имя

Ссылка не создаёт новую ячейку — она **привязывается** к существующей и навсегда становится её вторым именем:

```cpp
#include <iostream>

int main() {
  int score = 10;
  int &s = score;      // s — второе имя для score

  s = 99;              // пишем через ссылку…
  std::cout << score << "\n";   // …меняется оригинал: 99

  std::cout << (&s == &score) << "\n";   // 1: у них один и тот же адрес
  return 0;
}
```

```
             ┌──────────┐
   score ──► │    99    │ ◄── s
             └──────────┘
          одна ячейка, два имени
```

Три правила ссылки:

- **Задаётся сразу при объявлении.** `int &s;` без `= что-то` — ошибка компиляции.
- **Не перепривязывается.** `s = other;` не делает `s` ссылкой на `other` — это обычное присваивание: значение `other` копируется в `score`.
- **Не бывает «пустой».** Ссылка всегда на что-то указывает — поэтому с ней безопаснее, чем с указателем.

Главное применение ссылок ты уже видел в [функциях](04-funkcii.md#три-способа-передать-аргумент): параметр `int &x` позволяет функции изменить переменную вызывающего, а `const std::string &s` — не копировать большую строку.

### Указатель `T*` — переменная, в которой лежит адрес

Указатель — это **отдельная переменная**, её значение — адрес другой переменной. Тип пишут со звёздочкой: `int*` — «указатель на `int`».

```cpp
#include <iostream>

int main() {
  int score = 10;
  int *p = &score;     // в p кладём адрес score

  std::cout << p << "\n";    // сам адрес, например 0x5ffe9c
  std::cout << *p << "\n";   // значение по адресу: 10

  *p = 42;                   // пишем по адресу…
  std::cout << score << "\n";   // …меняется score: 42
  return 0;
}
```

```
      p                      score
   ┌──────────┐           ┌──────────┐
   │ 0x5ffe9c │ ────────► │    42    │   адрес 0x5ffe9c
   └──────────┘           └──────────┘
   свой адрес,             *p — это «ячейка,
   своя ячейка             на которую смотрит p»
```

Прокрутите по шагам — обратите внимание, что при `*p = 42` меняется **`score`**, хотя строка про `p`:

```steps
@id c15o2a77
# Указатель: адрес и то, что по нему лежит
int score = 10;
int *p = &score;
std::cout << *p << "\n";
*p = 42;
std::cout << score << "\n";
int bonus = 5;
p = &bonus;
*p += 1;
---
1 | score=10 | Переменная `score` в памяти. Пусть её адрес — 0x9c.
2 | p=0x9c (→ score) | В `p` лежит не число 10, а **адрес** `score`.
3 | | `*p` — «пойти по адресу из `p`» и взять, что там лежит. | 10\n
4 | score=42 | Пишем по адресу — меняется сама `score`. Сам `p` не изменился.
5 | | Печатаем `score` напрямую — она правда 42. | 42\n
6 | bonus=5 | Новая переменная, адрес пусть 0xa0.
7 | p=0xa0 (→ bonus) | Указатель **перенаправили**. `score` осталась 42 — её это не касается.
?8 | bonus=6 | `*p += 1` теперь трогает `bonus`.
```

Звёздочка работает в две стороны:

- в **объявлении** `int *p` — «`p` — указатель»;
- в **выражении** `*p` — «пойти по адресу из `p`» (это называется **разыменовать**).

В отличие от ссылки, указатель можно **перенаправить** на другую переменную:

```cpp
int a = 1, b = 2;
int *p = &a;    // смотрит на a
p = &b;         // теперь смотрит на b; a не изменилась
*p = 20;        // b == 20
```

```cpp alt: Текущая цель героя
struct Monster { std::string name; int hp; };
std::vector<Monster> wave = {{"гоблин", 12}, {"скелет", 20}};
Monster *target = nullptr;                 // пока никого не выбрали
target = &wave[1];                         // навели прицел на скелета
target->hp -= 7;                           // бьём того, на кого смотрим
std::cout << wave[1].hp << "\n";          // 13
target = nullptr;                          // сбросили цель
```

```cpp alt: Выбранный пункт меню
std::vector<std::string> items = {"Новая игра", "Загрузить", "Выход"};
const std::string *selected = &items[0];
selected = &items[2];                      // стрелка вниз-вниз
std::cout << "> " << *selected << "\n";   // > Выход
```

> **Где ставить звёздочку.** `int *p`, `int* p` и `int * p` — одно и то же. Но в строке `int* a, b;` указатель только `a`, а `b` — обычный `int`. Поэтому указатели объявляют по одному в строке.

Посмотри на то же самое глазами памяти: слева программа, справа — что лежит в стеке. Наведи на стрелку `→` — подсветится переменная, на которую смотрит указатель.

```memory
# Указатель хранит адрес, а не значение
int a = 10;
int b = 5;
int* p = &a;
*p = 11;
p = &b;
*p = 20;
---
строка 1
стек main: a = 10
пояснение: Обычная переменная — ячейка в стеке со значением.
---
строка 2
стек main: a = 10; b = 5
---
строка 3
стек main: a = 10; b = 5; p = →a
пояснение: В `p` лежит **адрес** `a`. Сам `p` — тоже переменная в стеке.
---
строка 4
стек main: a = 11; b = 5; p = →a
пояснение: `*p` — «то, на что смотрит p». Меняем через указатель — меняется `a`.
---
строка 5
стек main: a = 11; b = 5; p = →b
пояснение: Переставили указатель: теперь он смотрит на `b`. Сама `a` не изменилась.
---
строка 6
стек main: a = 11; b = 20; p = →b
```

### `nullptr` — «ни на что не указывает»

Указатель может честно сказать «я пока никуда не смотрю» — для этого есть `nullptr`. Перед тем как разыменовывать такой указатель, его **проверяют**:

```cpp {11-14}
#include <iostream>
#include <string>
#include <vector>

struct Student {
  std::string name;
  int score = 0;
};

// Возвращает указатель на найденного студента или nullptr, если такого нет.
Student *findByName(std::vector<Student> &group, const std::string &name) {
  for (auto &s : group)
    if (s.name == name) return &s;
  return nullptr;
}

int main() {
  std::vector<Student> group = {{"Аня", 90}, {"Борис", 75}};

  Student *s = findByName(group, "Борис");
  if (s != nullptr) std::cout << s->name << ": " << s->score << "\n";

  Student *nobody = findByName(group, "Вера");
  if (nobody == nullptr) std::cout << "Вера не найдена\n";
  return 0;
}
```

```console
$ ./poisk
Борис: 75
Вера не найдена
```

Это главный случай, когда указатель удобнее ссылки: «**нашёл — вот он, не нашёл — `nullptr`**». Ссылку «на ничего» вернуть нельзя.

> **Разыменовать `nullptr` нельзя.** `*nobody` или `nobody->name` при `nobody == nullptr` — неопределённое поведение: на Windows программа обычно падает без сообщения. Проверка `if (p)` или `if (p != nullptr)` — обязательна.

В старом коде вместо `nullptr` пишут `NULL` или `0`. Это пережиток C — в своём коде используй `nullptr`.

### Стрелка `->` — поле через указатель

Если `p` — указатель на структуру, до поля можно добраться двумя способами:

```cpp
Student *p = &group[0];
(*p).score = 100;   // пойти по адресу, взять поле — скобки обязательны
p->score = 100;     // то же самое, короче — так и пишут
```

Правило простое: **у объекта — точка, у указателя — стрелка.**

```cpp
Student st;          st.name = "Аня";     // объект → точка
Student *p = &st;    p->name = "Аня";     // указатель → стрелка
Student &r = st;     r.name = "Аня";      // ссылка ведёт себя как объект → точка
```

Перепутал — компилятор подскажет: для `p.name` у указателя будет ошибка [`request for member … which is of pointer type`](11-oshibki.md#request-for-member-size-in-n-which-is-of-non-class-type-int).

### Указатель или ссылка — что брать

| Задача | Бери | Почему |
|---|---|---|
| Функция должна изменить аргумент | `T&` | короче, не бывает пустой |
| Передать большую строку/вектор только читать | `const T&` | без копии и без риска изменить |
| «Может не быть» (поиск, необязательный параметр) | `T*` + `nullptr` | ссылка не умеет быть пустой |
| Перенаправлять на разные объекты по ходу | `T*` | ссылку перепривязать нельзя |
| Владеть объектом в куче | `std::unique_ptr<T>` | сам освободит память — [раздел 33](18-umnye-ukazateli.md#33-умные-указатели) |
| Хранить много объектов | `std::vector<T>` | вообще без указателей |

**Почему в учебном коде хватает ссылок.** Почти все задачи — «изменить аргумент» или «не копировать большое». Обе решаются ссылкой, и ошибиться с ней труднее. Голые указатели нужны реже, чем кажется по старым учебникам: для массивов есть `vector`, для строк — `string`, для объектов в куче — умные указатели. А `new`/`delete` руками в современном коде не пишут — см. [раздел 24](09-spravka.md#new--delete--самая-опасная-привычка-из-старых-книг).

### Где ты уже встречал указатели

- **Итераторы** (`v.begin()`, результат `std::find`) ведут себя как указатели: `*it` — элемент, `++it` — следующий, `it->name` — поле. Поэтому `std::cout << *std::max_element(...)` — со звёздочкой. См. [раздел 17](07-algoritmy.md#17-итераторы--на-пальцах).
- **Строковый литерал** `"текст"` — это массив символов, и в сообщениях компилятора он выглядит как `const char*`. Отсюда ошибка [`invalid conversion from 'const char*' to 'int'`](11-oshibki.md#invalid-conversion-from-const-char-to-int).
- **Умные указатели** `std::unique_ptr<T>` — указатель, который сам освобождает память; у него те же `*p` и `p->`.
- **Наследование**: `Base *b = &derived;` или `std::unique_ptr<Base>` — через указатель на базовый класс вызывают `virtual`-методы наследника. См. [раздел 35](20-nasledovanie.md#35-наследование).
- **`this`** внутри метода класса — указатель на объект, у которого метод вызван: `this->name`. См. [классы](13-klassy.md#this--указатель-на-себя).

### Типовые ошибки

**Висячая ссылка или указатель** — ссылаются на переменную, которой уже нет:

```cpp
int &bad() {
  int local = 5;
  return local;     // ❌ local умрёт при выходе из функции
}                   //    g++: reference to local variable 'local' returned
```

Локальная переменная живёт до `}` своей функции. Возвращай **значение** (`int`), а не ссылку на локальное. Подробнее — [в словаре ошибок](11-oshibki.md#reference-to-local-variable-returned).

**Указатель в вектор после `push_back`**:

```cpp
std::vector<int> v = {1, 2, 3};
int *first = &v[0];
v.push_back(4);     // вектор мог переехать в новую память…
*first = 10;        // ❌ …и first смотрит в освобождённую
```

При росте вектор может выделить новый блок и перенести элементы (см. [`size` и `capacity`](06-konteynery.md#как-вектор-растёт-size-и-capacity)). Все старые указатели, ссылки и итераторы на его элементы после этого недействительны. Храни **индекс**, а не указатель.

**Неинициализированный указатель**:

```cpp
int *p;         // ❌ в p мусорный адрес
*p = 5;         //    пишем «куда-то» — порча памяти

int *q = nullptr;   // ✅ явно «никуда»; ошибку легко заметить проверкой
```

<details>
<summary>Трассировка: обмен двух чисел через указатели</summary>

Функция получает **адреса** переменных и меняет значения по ним:

```cpp
void swapPtr(int *a, int *b) {
  int tmp = *a;
  *a = *b;
  *b = tmp;
}
// вызов: int x = 3, y = 7;  swapPtr(&x, &y);
```

Пусть `x` лежит по адресу `0x10`, а `y` — по `0x14`:

| шаг | строка | `a` | `b` | `tmp` | `x` (по `0x10`) | `y` (по `0x14`) |
|---|---|---|---|---|---|---|
| старт | вызов `swapPtr(&x, &y)` | `0x10` | `0x14` | — | 3 | 7 |
| 1 | `int tmp = *a;` | `0x10` | `0x14` | 3 | 3 | 7 |
| 2 | `*a = *b;` | `0x10` | `0x14` | 3 | 7 | 7 |
| 3 | `*b = tmp;` | `0x10` | `0x14` | 3 | 7 | 3 |

Сами `a` и `b` не менялись ни разу — менялось то, **на что** они указывают. Ссылочная версия `void swapRef(int &a, int &b)` делает то же самое, но без звёздочек и без `&` при вызове: `swapRef(x, y)`. Поэтому в C++ для таких задач берут ссылки.

</details>


## Рецепты: хочу X → вот код

Ищешь не функцию, а решение задачи — начни отсюда.

- **Узнать адрес переменной** — `&x`. → [адрес](#адрес-у-каждой-переменной-есть-место-в-памяти)
- **Второе имя для переменной (менять оригинал)** — ссылка `int &r = x;`. → [ссылка](#ссылка-t--второе-имя)
- **Хранить «может быть, объект»** — указатель, `nullptr` — «ничего». → [nullptr](#nullptr--ни-на-что-не-указывает)
- **Поле объекта через указатель** — `p->hp` вместо `(*p).hp`. → [стрелка](#стрелка----поле-через-указатель)
- **Выбрать: ссылка или указатель** — «обязательно есть» — ссылка, «может не быть» — указатель. → [что брать](#указатель-или-ссылка--что-брать)

## Проверь себя

Предскажи вывод, не запуская:

```challenge
@id c1vy0fig
@type predict
Что напечатает программа? (через пробел)
---
int a = 1;
int &r = a;
int *p = &a;
r = 5;
std::cout << a << " ";
*p = 9;
std::cout << a << " " << r;
---
5 9 9
```

```quiz
В: Что делает `&` в строке `int &r = x;`?
+ Объявляет `r` ссылкой — вторым именем `x`
- Берёт адрес `x` и кладёт его в `r`
- Создаёт копию `x`
= В объявлении `&` относится к типу: `r` — ссылка. Адрес `&x` берут в выражении, и тогда слева нужен указатель: `int *p = &x;`.

В: `int *p = &x;` Что такое `*p`?
+ Значение переменной `x`
- Адрес переменной `x`
- Адрес самого указателя `p`
= `p` хранит адрес `x`, а `*p` — «пойти по этому адресу», то есть сама `x`. Адрес `x` — это просто `p`.

В: Как обратиться к полю `name` через указатель `p` на структуру?
+ `p->name`
- `p.name`
- `*p.name`
= У указателя — стрелка. `*p.name` не сработает из-за приоритета (точка выполняется раньше звёздочки); правильная длинная форма — `(*p).name`.

В: Что вернуть из функции поиска, если элемент не найден?
+ `nullptr` (функция возвращает указатель)
- ссылку на пустой объект
- `0` через ссылку `int&`
= Ссылка не бывает пустой, а указатель может честно сказать «ничего» — `nullptr`. Вызывающий проверяет результат перед использованием.

В: `int &r = a; r = b;` Что произошло?
+ Значение `b` скопировано в `a`
- `r` теперь ссылается на `b`
- Ошибка компиляции
= Ссылку нельзя перепривязать: после объявления `r` навсегда второе имя `a`. `r = b` — обычное присваивание.
```

Найди ошибку:

```findbug
struct Point { int x = 0; int y = 0; };

Point *p = nullptr;
if (p == nullptr)
    std::cout << "точки нет\n";
p->x = 5;                     // «запишем координату»
---
Проверка есть, но она ничего не защищает: `p->x = 5` выполняется **в любом случае**, в том числе когда `p == nullptr`. Разыменование `nullptr` — неопределённое поведение, обычно падение.

**Исправление:** работать с указателем только внутри ветки, где он точно не `nullptr`: `if (p != nullptr) p->x = 5;` — или вовсе не нужен указатель: `Point pt; pt.x = 5;`.
```

Карточки на повторение:

```cards
Q: Чем ссылка отличается от указателя (три пункта)?
A: Ссылку задают сразу и не перепривязывают, она не бывает пустой; указатель — отдельная переменная с адресом, его можно перенаправить и обнулить (`nullptr`).

Q: Что значат `&x` и `*p` в выражении?
A: `&x` — адрес переменной `x`; `*p` — значение по адресу, который хранится в `p` (разыменование).

Q: Когда брать указатель, а не ссылку?
A: Когда объекта может не быть (`nullptr` как «не нашёл») или когда нужно перенаправлять на разные объекты. В остальных случаях — ссылка.

Q: Почему нельзя хранить `&v[0]` и потом делать `v.push_back`?
A: При росте вектор может переехать в новую память — старый адрес станет недействительным. Храни индекс.

Q: Зачем проверять указатель на `nullptr` перед `*p`?
A: `nullptr` значит «никуда не указывает». Разыменовать его — неопределённое поведение, обычно падение программы.

Q: Что такое висячий указатель?
A: Указатель на объект, который уже уничтожен (вышел из области видимости или удалён). Адрес выглядит нормально, но обращаться по нему нельзя.

Q: Что даёт `p + 1`, если `p` указывает на элемент массива `int`?
A: Адрес следующего элемента — сдвиг на `sizeof(int)` байт, а не на один байт.

Q: Чем `const int *p` отличается от `int *const p`?
A: `const int *p` — нельзя менять значение через `p`, но сам `p` можно перенаправить. `int *const p` — указатель не перенаправить, а значение менять можно.
H: Читай объявление справа налево.

Q: Что будет, если забыть `delete` после `new`?
A: Утечка памяти: блок занят до конца программы. Поэтому вместо `new`/`delete` берут `std::make_unique` и контейнеры.

Q: Что напечатает `std::cout << p;` для `int *p`?
A: Адрес в шестнадцатеричном виде, например `0x61fe14`. Значение по адресу — `*p`.
```

## Закрепление прошлых тем

Три вопроса из тем 4, 6 и 7, где ссылки и указатели уже встречались:

```quiz
В: Тема 4. Функция `void inc(int x) { ++x; }` вызвана как `inc(a)`. Что с `a`?
+ Не изменилась — в функцию пришла копия
- Увеличилась на 1
- Ошибка компиляции
= Параметр без `&` — копия. Чтобы менять `a`, нужен параметр-ссылка: `void inc(int &x)`.

В: Тема 7. Почему пишут `std::cout << *std::max_element(v.begin(), v.end());` со звёздочкой?
+ `max_element` возвращает итератор — «указатель» на элемент, а не сам элемент
- Звёздочка здесь умножение
- Без неё выведется максимум, просто в другом формате
= Алгоритмы возвращают позицию (итератор). Значение по ней получают разыменованием `*it`, как у указателя. Без `*` код не соберётся.

В: Тема 6. В `for (auto &s : students)` зачем `&`?
+ Чтобы `s` был ссылкой на элемент: без копии, и изменения попадают в вектор
- Без `&` цикл не скомпилируется
- `&` делает цикл обратным
= Без `&` каждая итерация получает копию элемента — менять её бесполезно, а для больших структур это ещё и медленно.
```
