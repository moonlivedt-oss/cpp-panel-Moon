## 37. Семантика перемещения

> **Определение.** **Копирование** создаёт независимый дубликат: у источника всё остаётся. **Перемещение** (перенос) забирает у источника его внутренности — буфер строки, память вектора — и оставляет источник пустым, но исправным. Перенос почти бесплатен, копия большого объекта — дорогая.

### За 30 секунд

- `std::string b = a;` — **копия**: текст теперь в двух местах.
- `std::string c = std::move(a);` — **перенос**: `c` забрала буфер у `a`, сама `a` осталась пустой.
- `std::move` ничего не двигает — он только **разрешает** забрать. Забирает конструктор или присваивание.
- После `std::move(x)` значение `x` не читай — только присвой новое или дай ему умереть.
- Временные значения (`f()`, `std::string("…")`) и `return local;` переносятся **сами**, без `std::move`.

```cpp
std::vector<std::string> names;
std::string name = "Аня";
names.push_back(name);              // копия — name ещё понадобится
names.push_back(std::move(name));   // перенос — name больше не нужна
```

### Копия и перенос: в чём разница

`std::string` и `std::vector` — это «ручка» и данные в куче (картинка «коробки с ручкой» есть в [теме про строки](05-stroki.md#10-stdstring)). Копия выделяет новую коробку и переписывает туда всё содержимое. Перенос просто **передаёт ручку**: новая переменная начинает указывать на тот же буфер, а старая — на пустоту.

```
   Копия:  std::string b = a;

      a ──► [ д л и н н ы й   т е к с т ]
      b ──► [ д л и н н ы й   т е к с т ]     ← новый буфер, всё переписано

   Перенос:  std::string c = std::move(a);

      a ──► [ ]                                ← пусто, но a исправна
      c ──► [ д л и н н ы й   т е к с т ]     ← тот же буфер, ничего не переписано
```

Для строки из 10 символов разницы не заметить. Для вектора из миллиона элементов копия — миллион операций, перенос — три присваивания внутри.

### `std::move` — «разрешаю забрать»

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
  std::string a = "длинный текст, который жалко копировать";
  std::string b = a;              // копия: теперь текст есть и в a, и в b
  std::string c = std::move(a);   // перенос: c забрала буфер у a

  std::cout << "b: " << b << "\n";
  std::cout << "c: " << c << "\n";
  std::cout << "a после move: [" << a << "], size = " << a.size() << "\n";

  std::vector<std::string> names;
  std::string name = "Аня";
  names.push_back(name);              // копия — name ещё нужна
  names.push_back(std::move(name));   // перенос — name больше не нужна
  std::cout << names.size() << " " << names[1] << " [" << name << "]\n";
  return 0;
}
```

```console
$ ./move
b: длинный текст, который жалко копировать
c: длинный текст, который жалко копировать
a после move: [], size = 0
2 Аня []
```

Главное про `std::move` (он в `<utility>`):

- Сам по себе он **ничего не делает** с данными. Это пометка «с этим объектом можно поступить как с временным». Если принимающая сторона умеет переносить — перенесёт, если нет — скопирует.
- Состояние источника после переноса стандарт называет «**допустимым, но неопределённым**». У `std::string` и `std::vector` на твоей сборке это пустота, но полагаться на это нельзя. С источником можно делать только две вещи: присвоить новое значение (`a = "новое";`) или больше не трогать.

### Временные значения переносятся сами

У выражения есть «место» или его нет. У переменной `name` место есть — к ней можно вернуться (это **lvalue**, «то, что может стоять слева от `=`», как в [ошибке `lvalue required`](11-oshibki.md#lvalue-required-as-left-operand-of-assignment)). А результат `a + b`, `std::string("tmp")` или вызова функции — **временное значение** (rvalue): после строки его уже не будет.

Временное никому больше не нужно, поэтому компилятор **переносит его автоматически**, без всяких `std::move`:

```cpp
std::vector<std::string> words;
words.push_back(std::string("кот"));   // временное → перенос
words.push_back(first + " " + last);   // результат + временный → перенос
std::string line = readLine();         // результат функции → перенос (или вообще ничего)
```

Вывод: `std::move` нужен только для **именованной** переменной, которую ты сам решил больше не использовать.

### Где перенос случается без твоего участия

Учебный класс, который сообщает, как его создают, показывает все случаи разом:

```cpp {11-12}
#include <iostream>
#include <string>
#include <utility>
#include <vector>

// Учебный класс, который сообщает, как его создают: копией или переносом.
struct Loud {
  std::string data;

  explicit Loud(std::string d) : data(std::move(d)) {}
  Loud(const Loud &other) : data(other.data) { std::cout << "  копия\n"; }
  Loud(Loud &&other) noexcept : data(std::move(other.data)) { std::cout << "  перенос\n"; }
  Loud &operator=(const Loud &) = default;
  Loud &operator=(Loud &&) noexcept = default;
};

Loud make() {
  Loud local("из функции");
  return local;                   // без std::move: компилятор сам не копирует
}

int main() {
  Loud a("данные");

  std::cout << "Loud b = a;\n";
  Loud b = a;

  std::cout << "Loud c = std::move(a);\n";
  Loud c = std::move(a);

  std::cout << "Loud d = make();\n";
  Loud d = make();

  std::cout << "v.push_back(Loud(\"временный\"));\n";
  std::vector<Loud> v;
  v.reserve(4);
  v.push_back(Loud("временный"));

  std::cout << "v.emplace_back(\"на месте\");\n";
  v.emplace_back("на месте");
  return 0;
}
```

```console
$ ./loud
Loud b = a;
  копия
Loud c = std::move(a);
  перенос
Loud d = make();
v.push_back(Loud("временный"));
  перенос
v.emplace_back("на месте");
```

Что видно из вывода:

| Строка | Что произошло | Почему |
|---|---|---|
| `Loud b = a;` | копия | `a` — именованная переменная, её могут использовать дальше |
| `Loud c = std::move(a);` | перенос | мы явно разрешили забрать |
| `Loud d = make();` | **ничего** | компилятор строит объект сразу на месте `d` («пропуск копии», copy elision) |
| `push_back(Loud("временный"))` | перенос | временное значение переносится само |
| `emplace_back("на месте")` | **ничего** | объект создаётся прямо внутри вектора из аргументов конструктора |

`Loud(Loud &&other)` — это **конструктор перемещения**: `&&` в параметре означает «сюда приходит то, что можно забрать». Писать такие конструкторы самому почти никогда не нужно — см. следующий раздел.

<details>
<summary>Копнуть глубже: зачем там noexcept</summary>

Когда вектору не хватает места, он выделяет новый буфер и переселяет туда элементы (см. [как вектор растёт](06-konteynery.md#как-вектор-растёт-size-и-capacity)). Переносить их вектор будет, только если перенос помечен `noexcept` — обещанием «не бросаю исключений». Иначе, если перенос упадёт на середине, старые элементы уже будут испорчены, и вектор предпочтёт медленное, но безопасное копирование. Сгенерированные компилятором переносы помечаются `noexcept` автоматически, если это возможно, — ещё один довод не писать их руками.

</details>

### Свой класс: правило нуля

Если поля твоего класса — стандартные типы (`std::string`, `std::vector`, `int`, `std::unique_ptr`), компилятор **сам** напишет и копирование, и перенос: поле за полем. Это называется **правило нуля**: не пиши ни конструктор копирования, ни перемещения, ни деструктор — и всё будет работать правильно и быстро.

```cpp
struct Student {
  std::string name;
  std::vector<int> scores;
};                            // копирование и перенос — готовы, писать ничего не надо

Student a{"Аня", {5, 4, 5}};
Student b = std::move(a);     // перенесутся и name, и scores
```

Свои версии нужны только классу, который сам управляет ресурсом через голый указатель или дескриптор, — а такой класс лучше переделать на [умный указатель](18-umnye-ukazateli.md). Как только пишешь свой деструктор, вспоминай «правило пяти»: тогда придётся продумать и все четыре операции копирования и переноса — это уже тема для продвинутого уровня.

### Только перенос: `unique_ptr` и потоки

Некоторые объекты **нельзя** копировать по смыслу: `std::unique_ptr` владеет объектом единолично, `std::ifstream` держит открытый файл. У них копирование запрещено, а перенос разрешён — владение можно только **передать**:

```cpp
auto p = std::make_unique<int>(5);
// auto q = p;                 // ❌ ошибка: копировать unique_ptr нельзя
auto q = std::move(p);         // ✅ владение перешло к q, p теперь пустой (nullptr)

std::vector<std::unique_ptr<int>> all;
all.push_back(std::move(q));   // в вектор — тоже только переносом
```

Если видишь ошибку `use of deleted function` с копирующим конструктором `unique_ptr` — это ровно этот случай: где-то нужна копия, а объект её не допускает. Лечится `std::move` или передачей по ссылке.

### Типовые ошибки

**Чтение после переноса:**

```cpp
std::string s = "текст";
names.push_back(std::move(s));
std::cout << s.size();        // ❌ s «пустая, но неизвестно какая» — значение не используй
s = "новый текст";            // ✅ присвоить заново — можно
```

**`std::move` у `const` — молча копирует:**

```cpp
const std::string big = loadBigText();
std::string mine = std::move(big);   // ❌ из const забрать нельзя — это обычная копия
```

Ошибки компиляции нет: `std::move` превращает `big` в «временное константное», и конструктор перемещения не подходит — выбирается копирование. Если объект собираешься отдавать, не помечай его `const`.

**`std::move` в `return` — мешает оптимизации:**

```cpp
std::string build() {
  std::string s = "abc";
  return std::move(s);        // ❌ warning: moving a local object in a return statement
}                             //    prevents copy elision [-Wpessimizing-move]
```

`return s;` компилятор и так оптимизирует лучше всего — строит результат сразу на месте. `std::move` в `return` этому только мешает. Правило: **в `return` локальной переменной `std::move` не пиши**.

**Перенос в параметр «по значению» — когда это уместно.** Функция, которая всё равно сохранит строку у себя, может принять её по значению и перенести внутрь:

```cpp
struct Player {
  std::string name;
  explicit Player(std::string n) : name(std::move(n)) {}   // одна копия или ноль
};
Player p1("Аня");                 // временное → перенос, копий нет
std::string nick = "Борис";
Player p2(nick);                  // одна копия (nick нужен дальше)
```

Для функций, которые только **читают**, по-прежнему бери `const std::string &` — там перенос ни к чему.

## Проверь себя

Небольшой разбор по теме. Нажми вариант — сразу увидишь, верно или нет; можно и просто «Показать ответ».

```quiz
В: Что делает `std::move(x)` сам по себе?
+ Ничего не переносит — только помечает `x` как «можно забрать»
- Копирует `x` в новое место
- Очищает `x`
= Переносит конструктор или присваивание, которые получают помеченный объект. Без них `std::move` — просто приведение типа.

В: `std::string c = std::move(a);` Что можно делать с `a` дальше?
+ Присвоить новое значение или больше не трогать
- Читать как раньше — там тот же текст
- Ничего — `a` уничтожена
= После переноса объект «допустимый, но неопределённый». Он жив (его деструктор вызовется), но его значение не используют до нового присваивания.

В: Нужен ли `std::move` в `return local;`?
+ Нет — компилятор сам перенесёт или вовсе построит объект на месте; `std::move` этому мешает
- Да, иначе будет копия
- Да, иначе не скомпилируется
= g++ даже предупреждает: `-Wpessimizing-move`.

В: Почему `auto q = p;` не компилируется для `std::unique_ptr p`?
+ Копирование запрещено: владелец может быть только один
- `auto` не работает с указателями
- Нужно `new`
= Передать владение можно только переносом: `auto q = std::move(p);` — после этого `p` пустой.

В: Что будет при `std::move` у `const`-объекта?
+ Тихая копия — из константы забрать нельзя
- Ошибка компиляции
- Перенос, как обычно
= Конструктор перемещения требует неконстантный источник, поэтому выбирается копирование. Ни ошибки, ни предупреждения.
```

Предскажи вывод:

```challenge
@type predict
Что напечатает программа? (через пробел)
---
std::string a = "кот";
std::string b = a;
std::string c = std::move(a);
std::cout << b << " " << c << " " << a.size();
```

Найди ошибку:

```findbug
std::vector<std::string> archive;
std::string line;
while (std::getline(std::cin, line)) {
    archive.push_back(std::move(line));
    if (line.empty()) std::cout << "пустая строка во вводе\n";
}
---
После `std::move(line)` значение `line` не определено — на твоей сборке она **всегда** пустая, и сообщение печатается для каждой строки. Проверка идёт после переноса.

**Исправление:** сначала проверить, потом переносить: `if (line.empty()) …; archive.push_back(std::move(line));`. На следующем витке `getline` присвоит `line` новое значение — это разрешено.
```

Карточки на повторение:

```cards
Q: Чем перенос отличается от копии?
A: Копия создаёт независимый дубликат данных. Перенос передаёт внутренности (буфер) новому объекту, а источник оставляет пустым, но исправным. Перенос почти бесплатен.

Q: Когда `std::move` писать не нужно?
A: Для временных значений (`f()`, `std::string("…")`, `a + b`) и в `return local;` — там перенос или пропуск копии происходят сами.

Q: Что такое «правило нуля»?
A: Если поля класса — стандартные типы, не пиши свои конструкторы копирования/переноса и деструктор: компилятор сделает их правильно.

Q: Какие объекты можно только переносить?
A: Те, что единолично владеют ресурсом: `std::unique_ptr`, потоки файлов (`std::ifstream`, `std::ofstream`).
```

## Закрепление прошлых тем

Три вопроса из тем 4, 6 и 36:

```quiz
В: Тема 4. Функция только печатает строку. Как её принять?
+ `const std::string &s`
- `std::string s` и `std::move` внутри
- `std::string &&s`
= Для чтения — константная ссылка: ни копии, ни переноса, ни риска изменить.

В: Тема 6. Почему `v.push_back(x)` иногда «тормозит» на больших векторах, а `v.reserve(n)` помогает?
+ При нехватке места вектор переселяет все элементы в новый буфер; `reserve` выделяет место заранее
- `reserve` сортирует вектор
- `push_back` всегда копирует весь вектор
= Переселение — копией или переносом элементов. `reserve` убирает эти переезды, если размер известен заранее.

В: Тема 36. Что общего у ссылки `T&` и параметра `T&&` в конструкторе перемещения?
+ Оба — ссылки: объект не копируется, функция работает с оригиналом
- Оба создают копию
- `&&` — это «ссылка на ссылку»
= `&&` — ссылка на то, что можно забрать (временное или помеченное `std::move`). Через неё конструктор перемещения и забирает буфер.
```

> **Дальше.** Перенос — основа [умных указателей](18-umnye-ukazateli.md): `unique_ptr` передают только через `std::move`. В Unreal Engine та же идея живёт в `MoveTemp(x)` — это их `std::move`.
