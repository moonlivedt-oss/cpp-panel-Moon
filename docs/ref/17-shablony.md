## 32. Шаблоны

### Проблема: одна логика, несколько копий

В [разделе 9](04-funkcii.md#перегрузка-одно-имя-разные-аргументы) `maxOf` пришлось написать несколько раз — отдельно для `int` и для `double`:

```cpp
int maxOf(int a, int b)             { return (a > b) ? a : b; }
double maxOf(double a, double b)    { return (a > b) ? a : b; }
```

Тело у них **одинаковое** — меняется только тип. Копировать один и тот же код ради типа — ровно то, чего мы избегаем. Шаблон пишет эти версии за тебя.

> А строковая версия в разделе 9 сравнивала строки **по длине** — это уже другая логика, не «то же самое для другого типа». Такой случай шаблоном не заменить: там честная перегрузка. Шаблон — когда отличается только тип, а правило то же.

### `template` — функция с «дыркой под тип»

Шаблон — это функция, где тип оставлен «дыркой» с именем (обычно `T`), а компилятор подставляет настоящий тип при вызове:

```cpp
#include <iostream>
#include <string>

template <typename T>            // T — любой тип, подставится при вызове
T maxOf(T a, T b) {
  return (a > b) ? a : b;
}

int main() {
  std::cout << maxOf(3, 7) << "\n";        // T = int    → 7
  std::cout << maxOf(3.5, 2.1) << "\n";    // T = double → 3.5
  std::cout << maxOf(std::string("аб"), std::string("вг")) << "\n";  // T = string → вг
  return 0;
}
```

Одно тело — три применения. Тип `T` компилятор **выводит сам** из аргументов: передал два `int` — `T` стал `int`.

По шагам — что делает компилятор, встречая вызовы шаблона:

```steps
@id c1u12gl1
# Компилятор штампует версии maxOf
template <typename T>
T maxOf(T a, T b) {
    return (a > b) ? a : b;
}
int main() {
    std::cout << maxOf(3, 7) << "\n";
    std::cout << maxOf(3.5, 2.1) << "\n";
}
---
1 | готовые версии=нет | Пока это только **рецепт**: машинного кода для `maxOf` не существует вообще.
7 | T=int | Компилятор видит `maxOf(3, 7)`: оба аргумента `int`, значит `T = int`.
2 | готовые версии=maxOf<int> | …и штампует настоящую функцию `int maxOf(int, int)`.
7 | | Вызов готовой версии. | 7\n
?8 | T=double | Новый вызов. Какой тип компилятор подставит вместо `T`?
2 | готовые версии=maxOf<int> и maxOf<double> | Вторая, **отдельная** функция — уже для `double`. Шаблон один, а версий столько, сколько разных типов.
8 | | Вызов. | 3.5\n
```

Поэтому `maxOf(3, 2.5)` не соберётся: из `3` выходит `T = int`, из `2.5` — `T = double`, и компилятор не знает, какой выбрать.

### Как это работает: инстанцирование

Шаблон — это не готовая функция, а **рецепт**. Когда ты зовёшь `maxOf(3, 7)`, компилятор по рецепту «штампует» настоящую функцию для `int`; на `maxOf(3.5, 2.1)` — отдельную для `double`. Это называется **инстанцирование**.

Отсюда — две вещи, которые ты уже видел:

- **Ошибки в шаблонах выходят на пол-экрана.** Компилятор ругается уже в момент «штамповки», в глубине рецепта. Как их читать — [раздел 27](11-oshibki.md#страшные-ошибки-на-пол-экрана): ищи первую строку со своим типом.
- **Код шаблона живёт в заголовках.** Чтобы «штамповать» под нужный тип, компилятору нужно **тело** шаблона в каждом месте вызова — поэтому шаблоны не разносят на `.h`/`.cpp`, как обычные функции, а пишут целиком в заголовке.

### Требование к типу: он должен «уметь» нужное

Шаблон подставит **любой** тип — но только если тот умеет всё, что тело от него хочет. `maxOf` использует `>`, значит тип обязан уметь сравниваться:

```cpp
struct Point { int x = 0, y = 0; };

maxOf(Point{1, 2}, Point{3, 4});   // ❌ ошибка: у Point нет operator> — сравнивать нечем
```

Это тот же случай, что «[свой `struct` как ключ `map`](06-konteynery.md#свой-struct-как-ключ)»: контейнеры и алгоритмы — шаблоны, и если твой тип не умеет `<` или `>`, ошибка приходит из их глубины. Добавь нужный оператор — и тип «подойдёт».

### `concepts`: понятные требования к типу

Проблема шаблонных ошибок в том, что требование «тип должен уметь `>`» нигде не написано — оно спрятано в теле, и нарушение вылезает простынёй из глубины. **Концепты** (C++20) позволяют указать требование **прямо в объявлении** — тогда ошибка становится короткой и по делу:

```cpp
#include <concepts>
#include <iostream>

template <std::totally_ordered T>     // T обязан уметь сравниваться (< > ==)
T maxOf(T a, T b) {
  return (a > b) ? a : b;
}

int main() {
  std::cout << maxOf(3, 7) << "\n";   // → 7
  return 0;
}
```

Теперь вызов `maxOf` с типом без сравнения даёт понятное «constraint not satisfied: тип не удовлетворяет `totally_ordered`», а не десять экранов внутренностей. Готовых концептов в `<concepts>` много: `std::integral` (целые), `std::floating_point` (дробные), `std::totally_ordered` (сравнимые). Свои требования тоже можно описывать через `requires`, но на первое время хватает готовых.

### Шаблонные структуры

Шаблоном может быть не только функция, но и тип. Именно так устроены `std::vector<T>` и `std::pair<A, B>` — один рецепт, разные подстановки:

```cpp
template <typename T>
struct Box {                 // коробка, в которой лежит что угодно одного типа
  T value;
  bool empty = true;
};

Box<int> a{42, false};           // коробка с int
Box<std::string> b{"текст", false};   // коробка со строкой
std::cout << a.value << " " << b.value;   // → 42 текст
```

Параметров-типов может быть несколько — как у `std::map<K, V>`:

```cpp
template <typename K, typename V>
struct Pair {
  K key;
  V value;
};
```

### Когда писать свой шаблон, а когда нет

| Пиши шаблон | Не пиши |
|---|---|
| **одна и та же** логика нужна для многих типов (утилита, контейнер, алгоритм) | функция и так работает с одним типом — шаблон только усложнит |
| тип не важен, важно поведение (`>`, перебор, вывод) | «на будущее, вдруг пригодится» — обобщать заранее не надо |
| так убираешь дублирование, как с копиями `maxOf` | ради одного вызова с одним типом |

Пока задачи учебные, свои шаблоны нужны редко — гораздо чаще ты **пользуешься** чужими (`vector`, `sort`, `optional`). Свой пиши, когда ловишь себя на копировании функции ради смены типа — как раз случай `maxOf`.

> Шаблоны — большая тема (шаблонные методы, специализация, свои `concepts`). Здесь показан фундамент: **одно тело, тип-параметр `T`, компилятор штампует версии**. Этого достаточно, чтобы убирать дублирование по типу и понимать, откуда берутся длинные ошибки контейнеров. Что дальше — [раздел 26](09-spravka.md#26-что-учить-дальше).

```cards
Q: Зачем нужен шаблон функции?
A: Написать одну функцию для многих типов: `template <typename T> T maxOf(T a, T b)` работает и с `int`, и с `double`, и со `std::string`.

Q: Где обычно пишут тело шаблонной функции?
A: В заголовочном файле: компилятор должен видеть определение, чтобы создать версию под конкретный тип.

Q: Почему `maxOf(3, 2.5)` не компилируется?
A: `T` выводится как `int` из первого аргумента и как `double` из второго — конфликт. Укажи тип явно: `maxOf<double>(3, 2.5)`.
H: Какой тип компилятор выведет для каждого аргумента?

Q: Что такое инстанцирование шаблона?
A: Компилятор создаёт настоящую функцию или класс под конкретный тип, когда шаблон используется: `maxOf<int>` и `maxOf<double>` — две разные функции.

Q: Как в C++20 ограничить шаблон только целыми числами?
A: Концептом: `template <std::integral T>` (из `<concepts>`). Неподходящий тип даст понятную ошибку прямо в месте вызова.

Q: Приведи пример шаблона класса из стандартной библиотеки.
A: `std::vector<T>`, `std::optional<T>`, `std::pair<A, B>`. Пишешь `std::vector<int>` — получаешь вектор целых.

Q: Что значит `auto` в параметре: `void print(const auto &x)`?
A: Это сокращённый шаблон (C++20) — то же самое, что `template <typename T> void print(const T &x)`.

Q: Почему ошибки в шаблонах бывают на пол-экрана?
A: Компилятор показывает всю цепочку инстанцирования. Ищи первую строку с твоим файлом — там причина.
```
