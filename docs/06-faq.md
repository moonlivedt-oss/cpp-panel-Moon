### Почему везде `std::`? В учебнике пишут просто `cout`

Потому что в учебнике стоит `using namespace std;` — строка, которая втаскивает в программу **все** имена стандартной библиотеки разом. Среди них есть обычные слова: `count`, `size`, `distance`, `data`. Заведёшь свою переменную `count` — получишь конфликт, причём ошибка вылезет на пол-экрана и совсем не там, где ты её сделал.

Пять лишних символов, зато видно, что откуда. Подробный разбор — [раздел 24](ref/09-spravka.md#using-namespace-std--почему-в-этом-справочнике-его-нет).

### Что брать: `int` или `long long`?

`int` по умолчанию. `long long` — когда числа могут перевалить за два миллиарда: суммы, произведения, факториалы.

Практичнее не менять тип везде, а защитить конкретное выражение: `1LL * n * (n + 1) / 2`. → [раздел 2](ref/01-osnovy.md#ловушка-3-int-переполняется-молча)

### Когда писать `const auto &`, а когда просто `auto`?

Правило простое:

| Что перебираешь | Как писать |
|---|---|
| числа (`int`, `double`, `char`, `bool`) | `for (int x : v)` — копия ничего не стоит |
| строки, векторы, словари, структуры | `for (const auto &x : v)` — иначе копируется каждый элемент |
| нужно изменить элементы на месте | `for (auto &x : v)` |

→ [раздел 8](ref/03-logika-cikly.md#какой-цикл-когда)

### Почему `switch` не работает со строкой?

```
error: switch quantity not an integer
```

`switch` умеет только целые и `char`. Для строк — цепочка `if / else if`. Если вариантов много, заведи `map<std::string, int>` и переключайся по числу. → [раздел 7](ref/03-logika-cikly.md#switch--выбор-из-фиксированного-списка)

### В чём разница между `i++` и `++i`?

```cpp
int i = 5;
std::cout << i++;   // напечатает 5, потом i станет 6
int j = 5;
std::cout << ++j;   // сначала j станет 6, напечатает 6
```

Как отдельная строка в цикле (`for (...; ++i)`) разницы нет никакой — пиши `++i` по привычке. Разница появляется, только когда результат тут же используется.

Никогда не пиши выражения вроде `i++ + ++i`: порядок вычисления не определён, и результат может быть любым.

### Зачем `return 0` в конце `main`?

Это **код возврата**: `0` значит «программа завершилась без ошибок». Его видит система и скрипты, а пользователь — нет.

Формально в `main` его можно опустить (компилятор подставит сам), но привычка полезная: в остальных функциях `return` обязателен, а `return 1` в `main` — стандартный способ сказать «дальше считать нечего». → [раздел 7](ref/03-logika-cikly.md#после-сообщения-об-ошибке-ставь-return)

### Почему вместо русских букв кракозябры?

Три условия должны совпасть: в коде вызваны `SetConsoleCP(CP_UTF8)` и `SetConsoleOutputCP(CP_UTF8)`, сам файл сохранён в UTF-8, а шрифт консоли — Consolas или Cascadia Mono. → [раздел 1](ref/01-osnovy.md#кракозябры-вместо-русского)

### `std::endl` или `"\n"`?

`"\n"` почти всегда. `std::endl` дополнительно сбрасывает буфер на диск, и в цикле это заметно тормозит. Брать `endl` стоит, только когда нужно увидеть вывод немедленно — например, перед долгим расчётом.

### Почему `cin >> name` читает только первое слово?

Оператор `>>` останавливается на первом пробеле. Для строки целиком — `std::getline(std::cin, name)`.

Главная ловушка: если перед этим было `std::cin >> age`, в буфере остался Enter, и `getline` прочитает пустую строку. Лечится `std::cin.ignore(10000, '\n');` между ними. → [раздел 4](ref/02-vvod-vyvod.md#разные-ситуации-ввода)

### Программа открывается и сразу закрывается

Она отработала и закончилась — окно закрылось вместе с ней. В VS Code через `Ctrl+Alt+R` вывод остаётся в панели, так что проблемы нет. Если запускаешь двойным щелчком по `.exe`, добавь в конец:

```cpp
std::cin.get();   // ждём Enter перед выходом
```

`system("pause")` для этого не нужен — он запускает внешнюю программу и работает не везде.

### Как вернуть из функции несколько значений?

Два значения — `std::pair` и структурные привязки:

```cpp
std::pair<int, int> divide(int a, int b) { return {a / b, a % b}; }
auto [q, r] = divide(17, 5);
```

Больше двух или нужны понятные имена — заводи `struct`. Через параметры-ссылки тоже можно, но читается хуже. → [раздел 9](ref/04-funkcii.md#возврат-нескольких-значений)

### `class` или `struct`?

Технически разница одна: в `struct` поля по умолчанию открыты, в `class` — закрыты. Пока пишешь учебные задачи, бери `struct`: он ровно для того, чтобы сложить несколько полей вместе. `class` понадобится, когда захочешь прятать данные за методами. → [раздел 19](ref/08-struct-fayly.md#19-struct)

### Нужно ли учить указатели?

Уметь **читать** — да, их полно в чужом коде и в старых учебниках. Писать самому в учебных задачах — почти никогда: то, ради чего раньше брали указатели, сегодня делают `vector`, `string` и ссылки.

Указатели стоит разобрать чуть позже — они объясняют, как устроены ссылки и контейнеры изнутри. → [раздел 26](ref/09-spravka.md#26-что-учить-дальше)

### Хочу делать игры — с чего начать?

Сначала — уверенный C++: типы, функции, контейнеры, `struct`. Игра — это прежде всего логика, а логика на любом движке пишется тем же языком. Когда ядро освоено, посмотри [кирпичики консольной игры](ref/21-igra-v-konsoli.md): игровой цикл, сущности через `struct` + `vector`, случайность из `<random>`, поле — маленькая игра целиком, без движка. Движок и графика — сильно позже: сначала пусть язык перестанет быть препятствием. → [Маршрут изучения](00-marshrut.md)

### Скопировал код из интернета — не собирается. Почему?

Три причины по частоте:

1. **Код старше 2011 года** — там `new`/`delete`, `char*`, `NULL`. Соберётся, но писать так не надо. → [сравнение старого и нового](04-sravneniya.md#1-старый-способ--современный)
2. **Не хватает `#include`** — на форуме его не показали. Компилятор скажет, какого: `'sort' is not a member of 'std'`. → [словарь ошибок](ref/11-oshibki.md#vector-is-not-a-member-of-std)
3. **Код требует стандарта новее** — например, `std::format` работает с C++20 и GCC 13+. У тебя всё это есть. → [таблица версий](04-sravneniya.md#2-что-появилось-в-какой-версии-c)

### Программа собралась, но считает неправильно. С чего начать?

По порядку: проверь на **самом простом** входе (не `12345`, а `5`), затем напечатай промежуточные значения, затем открой отладчик и посмотри переменные на точке останова.

И прогони восемь граничных входов — половина «загадочных» ошибок ловится именно там. → [Как ловить баги](ref/12-lovim-bagi.md)

### Где смотреть правду, если справочник чего-то не покрывает?

[cppreference.com](https://en.cppreference.com/) — не учебник, а справочник по языку. Сначала непривычно, потом окажется, что там есть ответ на любой вопрос, и он точный.

Отличать свежий материал от устаревшего помогает [таблица версий](04-sravneniya.md#2-что-появилось-в-какой-версии-c): если в статье нет ничего новее C++11, скорее всего, там и остальные советы двадцатилетней давности.
