# Примеры: девять работающих программ

> Здесь не куски кода, а **законченные программы**: скопировал целиком — запустилось.
> Каждая проверена на твоём компиляторе и собирается **без единого предупреждения** со всеми строгими флагами.
> Рядом с разбором лежит готовый `.cpp` в папке [code/](code) — открой файл и нажми `Ctrl+Alt+R`.

## Как запускать

1. Открой нужный файл из [code/](code) в VS Code.
2. Нажми `Ctrl+Alt+R` — расширение C/C++ Runner соберёт и запустит **именно этот файл**.

> ⚠️ **Не собирай папку целиком** (`Ctrl+K B`). В каждом файле своя функция `main`, а в программе она должна быть одна. При сборке всей папки компоновщик откажется работать и скажет прямо:
>
> ```
> multiple definition of `main'; ... first defined here
> collect2.exe: error: ld returned 1 exit status
> ```
>
> Это не поломка кода: просто такие файлы запускают по одному через `Ctrl+Alt+R`.

Программы 5 и 6 создают рядом с собой файлы (`expenses.csv`, `report.txt`, `phones.txt`). Так и задумано: они показывают, как программа сохраняет данные между запусками.

## Как из них учиться

Читать чужой код полезно, но запоминается только то, что менял сам. В конце каждого разбора есть раздел **«Что попробовать изменить»** — пять задач по возрастанию сложности. Делай их по порядку: первая обычно на десять минут, последняя заставит перестроить программу.

Если что-то в коде непонятно — ищи по названию в [справочнике](../00-НАЧНИ-ОТСЮДА.md): нумерация разделов сквозная, и разборы ссылаются прямо на нужный раздел.
