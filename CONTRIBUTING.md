# Участие в разработке

Спасибо за интерес к «Документации C++»! Проект небольшой и без зависимостей — влиться легко.

## Быстрый цикл

```bash
git clone https://github.com/moonlivedt-oss/cpp-panel-Moon.git
cd cpp-panel-Moon
# зависимостей нет — npm install не требуется
node test/smoke.js       # прогнать смоук-тест (154 проверки)
npm run check            # node --check модулей + смоук одной командой
npm run install:vsix     # собрать .vsix и поставить в VS Code
```

## Как устроен код

- Исходники расширения — в `extension/`. Отдельного шага сборки JS нет: файлы `extension/*.js`
  и есть источник правды, `npm run package` просто кладёт их в `.vsix` (свой ZIP-writer поверх
  `zlib`, без `@vscode/vsce`).

  | Файл | За что отвечает |
  |---|---|
  | `extension/extension.js` | хост-логика: поиск папки `docs`, сбор списка материалов, webview боковой/отдельной панели, подключение плавающего окна, команды и задачи |
  | `extension/cpp-docs-runtime.js` | рантайм плавающего окна: рендер Markdown, подсветка C++/bash, drag/resize, оглавление, переходы по ссылкам, акцент из темы / custom-bg |
  | `scripts/package-extension.js` | сборка `.vsix` |
  | `scripts/preview*.js` | превью панели и окна в браузер (`build/`) |
  | `test/smoke.js` | смоук-тест без запуска VS Code |

- Стиль: осторожный, совместимый JS (расширение исполняется в разных версиях воркбенча),
  оборонительные `try/catch` вокруг работы с DOM и файловой системой, комментарии — на русском.
- Комментарий объясняет **почему**, а не пересказывает код: причину неочевидного решения,
  подводный камень VS Code, формулу. Не нужно: пересказ следующей строки, история правок и
  номера версий (для этого есть CHANGELOG).
- **Фирменный визуал — рисованные наклейки, а не эмодзи.** В коде, интерфейсе окна/панели и в
  сообщениях коммитов эмодзи не используем — вместо них наклейки из `extension/stickers/`.
  Исключения ровно два: значки сложности задач 🟢🟡🔴 (устоявшаяся система) и страница-витрина
  `extension/README.md`, где эмодзи-маркеры помогают быстро просмотреть список на Marketplace.

## Тесты

- **Смоук** (`node test/smoke.js`) — обязателен. Расширение вне редактора не запустить: модуля
  `vscode` не существует. Тест подставляет заглушку, активирует расширение и проверяет собранный
  HTML — есть ли поиск, группы и кнопки, берутся ли подписи из настоящих файлов, экранируются ли
  кавычки и угловые скобки в заголовках, что показывается при отсутствии документации, а также
  поведение плавающего окна. Прогоняй после любой правки в `extension/**`.
- Добавляешь фичу — добавь и проверку в `test/smoke.js`.
- `npm run check` = `node --check` обоих модулей + смоук; именно это гоняет CI.

## Документация

Панель показывает файлы из `docs/`. Названия и описания берутся из самих файлов (первый заголовок
`#` и первая строка цитаты `>`), поэтому новый материал появляется в списке сам — код править не
нужно. Раскладка групп рассчитана на папки `ref`, `examples`, `situacii`.

## Сборка пакета

```bash
npm run package          # dist/cpp-docs-panel-<версия>.vsix
npm run install:vsix     # то же + установка в VS Code
```

Версия берётся из `extension/package.json`. Перед релизом подними её и там, и в бейджах README.

## Pull request

1. Ветка от `main`, понятное имя.
2. `npm run check` — зелёный.
3. Опиши, что и зачем; если менял UI — приложи скриншот.
4. Видимый текст — по-русски, без эмодзи.

CI прогонит `npm run check` на Node 18/20 и соберёт `.vsix`, чтобы упаковщик не сломался.
